## 작업 ID 체계 (2026-10-09 도입)

작업 ID는 카테고리 번호로 매긴다. **첫 자리가 카테고리, 뒤 두 자리가 카테고리 안의 등록 순번**이다(101, 102, … / 201, 202, …). 새 작업부터 이 체계를 쓴다.

기존 `RG-001`~`RG-017`은 **문서 안의 표기를 새 번호로 바꿨다**(2026-10-09). 이 백로그의 제목·ToC·대시보드와 작업기록·검토자료 노트, 저장소 `docs/`·README 본문에 있던 `RG-0NN`을 아래 대응표대로 `RG-NNN`으로 치환했고, 위키링크의 대상 경로와 제목 앵커는 함께 맞췄다(치환 전후 Work/RobinGraph 위키링크 326개가 모두 해석됨). 반면 **파일명·코드 주석·테스트 이름·MLflow 기록·과거 커밋 메시지는 바꾸지 않았다**(예: `2026-10-09-RG015-…` 파일, `chat_ui.test.js`의 `RG-005`). 이런 곳에서 옛 번호를 만나면 아래 표로 새 번호를 찾는다. 같은 설명이 저장소에도 `docs/task-ids.md`로 있다.

| 1xx DB·저장소 | 데이터베이스 구조·이관·저장소 분담 | Neo4j/PostgreSQL 역할, Chunk 저장소, TEST/PROD 데이터 |

## 작업 현황 대시보드

2026-10-10 기준: **진행 중 0건 · 신규 착수 대기 3건(RG-101·RG-202·RG-406) · 최후순위 보류 4건 · 완료 RG 작업 11건과 카드 효과 1건**. RG-405는 완료 상태를 유지하며 오늘 요청한 PC·모바일 토글 확대와 소재 반사 흔들림을 보완했다. 남은 신규 권장 순서는 RG-202 → RG-406이며 RG-101의 순서는 실측 후 정한다. 기존 최후순위 보류 설정은 유지한다.

현재 앱은 TEST·PROD 모두 `3ac07e2`이며, 같은 Docker 이미지로 운영 승격했다. 토글을 열어도 카드 배율과 소재 무늬를 유지하고, 접힌 기본 화면은 스크롤 없이 맞춘다. 펼친 긴 상세는 고정 크기 안에서 스크롤해 읽는다. ## 작업 관리 및 검증 원칙

- 작업별 기록 9개에 상세 보완을 추가했다. 당시 커밋·검증 수치·배포 결과는 보존하고 후속 완료 및 구조 정정을 별도로 표시한다.
- [[Work/RobinGraph/RobinGraph 구현·데이터·검증 가이드|구현·데이터·검증 가이드]]에서 자료 수집 방식, API, 그래프 경로, TEST·PROD 범위와 기록 해석 기준을 확인한다.
- RG-201은 서식 환경과 먹이 생태를 각각 조회하는 범위다. 두 조건 교집합·실제 공존·포식 관계·유사도 순위는 이번 완료 범위에 포함하지 않는다.
- 아종 노드 수와 고유 형질·사진 확보 수를 구분한다. 부모 종 참고 자료는 아종 직접 자료로 사용하지 않는다.
- 단위 테스트, 실제 DB, 배포 API, 브라우저 확인을 구분한다. 제외한 테스트와 문서 보완에서 재실행하지 않은 검증을 명시한다.
- 새 관계나 보류 이름 확대는 자료·출처·활성 분류판·화면 동작·완료 기준을 정한 뒤 별도 작업으로 등록한다. 이번 상세화만으로 새 작업을 자동 착수하거나 미확인 항목을 완료 처리하지 않는다.

## 지속적 백로그 운영 규칙

1. 작업 상세는 해당 카테고리 폴더의 `작업 백로그.md`에 ID별로 한 곳에만 둔다. 전체 백로그의 이전 제목은 상세로 안내하는 링크로 유지한다. 현황표는 상태·우선순위·요약·상세 링크만 관리한다.
2. 새 작업 추가와 상태 변경 시 목차, 현황표, 상세 위치를 함께 갱신한다. 제목은 고유하게 유지하고 기존 ID를 재사용하지 않는다.
3. 보류 작업은 사용자 재개 지시에 따라 진행 중으로 전환한다. 실제 진행 작업이 생기면 별도 ‘진행 중 작업’ 구역을 만들고 목차·현황표에도 반영한다.
4. 완료 기준을 모두 충족한 뒤 완료 상세로 이동한다. 일부 구현·배포만 끝난 작업은 완료 처리하지 않고 완료 범위와 남은 범위를 나누어 기록한다.
5. 실제 담당·확인된 모델과 검증 환경, 통과·실패·건너뜀, 해당하는 커밋·배포 정보를 기록한다. 문서 작업처럼 해당하지 않는 항목은 그 이유를 적는다. 인증 정보는 기록하지 않는다.
6. 과거 우선순위와 기준 수치는 변경 이력에 날짜와 함께 보존한다. 현재 현황표와 혼동되는 추천·순위는 남기지 않는다.
