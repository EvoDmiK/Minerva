### RG-014 — HippoRAG 스타일의 근거 검색 및 그래프 연관 검색 도입

- [ ] 착수 대기 — 신규 작업 등록 (2026-10-07)
- **우선순위**: 4 — 검색 기반과 평가 자료를 확인한 뒤 단계적으로 개편.
- **목적·배경**: 단순 이름 조회를 넘어 여러 문서에 흩어진 관련 사실과 근거를 함께 찾는다. 기존 Neo4j 검색·전문/벡터 검색·RRF와 비교해 다단계 근거 검색의 실제 개선을 검증한다.
- **기술 방향**: HippoRAG의 개체·사실 그래프와 Personalized PageRank(PPR) 기반 검색을 참조한다. HippoRAG 2의 passage 연결·fact 선택도 비교하되 1/2의 구성을 혼용해 동일 구현이라 주장하지 않는다. 공식 구현을 그대로 도입할지 기존 Neo4j에 필요한 원리를 구현할지 설계 단계에서 근거와 함께 결정한다. [원 논문](https://arxiv.org/abs/2405.14831), [HippoRAG 2 논문](https://arxiv.org/abs/2502.14802), [공식 저장소](https://github.com/OSU-NLP-Group/HippoRAG)
- **변경 전후 목표**: 기존 순위 병합 중심 경로에 질문 관련 개체·사실을 시작점으로 그래프 연관성을 확산해 근거 passage를 순위화하는 시험 경로를 추가한다. 검색 점수나 그래프 연결만으로 생태 사실을 확정하지 않고 인용 원문으로 답변을 검증한다.
- **범위·구현 단계**:
  1. 실제 TEST의 문헌·청크·관계·출처 수와 활성 전문/벡터 인덱스·임베딩 프로필을 감사한다. 아종 19,879개를 문헌 근거 19,879개로 세지 않는다. 설계 문서에 있는 기능과 실제 실행 가능한 기능을 구분한다.
  2. 제한된 허용 문헌 집합을 고정하고 청크 ID·문서 ID·릴리스·원문 해시를 유지한다. 추출 개체·사실·원문 passage 연결, 중복 병합과 이름 후보 대조를 설계한다. 모델 추출 관계는 검토된 분류·생태 관계와 분리하고 원문으로 추적 가능하게 한다.
  3. 질문의 seed 개체/사실 검색 → 제한된 PPR → passage 순위화 → 출처 필터 및 근거 구성 경로를 구현한다. 동의어 연결 기준, 관계 가중치, 감쇠율, 후보 수·시간·메모리 제한을 명시한다.
  4. 기존 임베딩 설정(Jina 512차원·질문/문서 작업 구분)과 실제 호환성을 확인한다. 다른 임베딩을 시험하면 별도 프로필·인덱스로 관리한다. Neo4j GDS 설치를 전제로 하지 않고 제공 기능과 외부 그래프 계산의 비용을 비교한다.
  5. 고정 자료 재실행의 중복 방지, 문헌 삭제·원문 변경·분류판 변경 시 인덱스 갱신을 지원한다. 활성 릴리스·자료 허용 범위를 통과한 그래프에서만 확산하고 최종 근거에서도 재검사한다.
  6. 기존 검색과 새 검색을 설정으로 선택해 같은 질문·자료로 비교한다. 기능 플래그, 이전 인덱스 보존 및 롤백 절차를 두고 TEST부터 적용한다.
- **예상 변경 위치**: `src/robingraph/retrieval/hybrid.py`, `src/robingraph/retrieval/neo4j_hybrid.py`, 근거 답변·수집 경로, 새 그래프 색인·PPR 모듈, 평가 자료·검색 설계 문서.
- **협업 추천**:
  - **Codex 주 담당**: 기존 저장 구조·검색 계약 분석, 인덱스·PPR·검색 연동·성능 계측·회귀·배포.
  - **Antigravity 조사·독립 평가**: 원 논문/공식 구현 대조, HippoRAG 1/2 선택 근거, 다단계 질문과 정답 근거 작성·검색 품질 평가.
  - **Claude 협업**: 근거 passage와 생성 답변의 일치·인용·불확실성 표현 검토, 단일 질문의 회귀 확인.

- **완료 기준·검증 계획**:
  - 최소 50문항(단일 근거·다단계 근거·근거 부족 포함, 다단계 최소 20문항)의 질문·정답 근거를 고정한다. 조정용과 최종 평가용을 분리하고 같은 corpus·top-k·답변 생성 조건에서 기존 검색과 비교한다.
  - Recall@k·MRR 및 필요한 모든 근거를 찾은 질문 비율, 인용 정확성·근거 없는 답변 비율, p50/p95 지연·색인 시간·메모리·모델 사용량을 기록한다. 다단계 근거 검색이 기준선보다 개선되고 단일 근거·자료 없음 회귀 기준을 통과해야 활성화한다. 목표 개선폭과 지연/메모리 상한은 기준선 측정 후 구현 전에 고정한다.

### RG-017 — 한국 서식 여부 토글과 범위별 이름 우선 정책

- [ ] 후속 계획 — 등록만 완료 (2026-10-08), 구현 미착수.
- **우선순위**: 5 — 기존 신규 대기 RG-016 → RG-015 → RG-014 뒤의 후속 작업. 실제 착수 시점은 사용자 지시를 따른다. 최후순위 보류 RG-002·RG-010·RG-011·RG-012는 유지한다.
- **요청 배경·목표**: 사용자가 “나중에 한국 서식종하고 안 사는 종을 토글로 나눠, 한국에 서식하는 종 검색은 한국어 우선, 안 사는 종은 영어 우선”을 제안했다. 현재 TOP3는 지역 구분 없이 검증 국명 후보를 먼저 선정하므로, 향후 검색 범위에 따라 후보 집합과 이름 우선 정책을 함께 바꾼다.
- **현재 근거·주의점**: 검증 국명이 있다는 사실은 한국 서식 근거가 아니다. 국명 없음·국내 관찰 기록 없음도 한국 비서식의 증거로 취급하지 않는다. 현재 국명 사전이나 사진·영어 이름만으로 국내 서식 여부를 판정하지 않는다. 이 작업 등록 중 서식 자료 조사나 실제 데이터 검증은 수행하지 않았다.
- **변경 전후 동작**:
  - 현재: 지역 토글 없이 전체 활성 종 중 검증 국명이 있는 후보를 우선하고 같은 이름 조건 안에서 점수순 추천한다.
  - 예정 한국 서식종 모드: 근거로 확인된 한국 서식종 집합에서 검색·비교 후보를 고른다. 검증된 국명을 우선 선정·표시하고 같은 조건 안에서 기존 가중 점수순으로 정렬한다.
  - 예정 한국 비서식종 모드: 비서식으로 확인된 집합에서 검색·비교 후보를 고른다. 원자료의 영어 이름을 우선 선정·표시하고 같은 조건 안에서 기존 가중 점수순으로 정렬한다. 국명이 있는 해외 종도 이 모드에서는 영어 이름을 우선한다.
  - 이름이 없으면 확인 가능한 다른 언어 이름, 최종적으로 학명을 사용한다. 학명·이름 출처·서식 범위 근거는 함께 보존한다.
  - 한국 서식 여부 미확인은 별도 상태로 관리한다. 단순한 국내 목록 미등재를 비서식으로 단정하거나 미확인 종을 비서식 목록에 자동 포함하지 않는다. 미확인 표시 위치·전체 검색 기본값은 착수 시 확정한다.
- **범위·구현 단계**:
  1. 한국 서식 여부를 판별할 사용 가능한 원자료·이용 조건·갱신 주기·분류판을 확인한다. 텃새·여름/겨울철새·나그네새·미조의 포함 기준을 자료에 맞춰 명시하고, “서식종”과 “국내 기록종”을 구분한다.
  2. 원자료의 종을 활성 분류판 종 ID·학명으로 연결하고 서식/비서식/미확인 상태, 출처·판정 기준·자료 버전을 보존한다. 분류 변경·누락·충돌은 임의 확정하지 않는다.
  3. 검색 화면에 한국 서식종/그 외 종을 고르는 토글을 제공하고 실제 후보 검색 범위에 연결한다. 화면 이름만 바꾸고 후보 집합은 전체로 남기는 구현을 피한다. 최종 사용자용 모드명은 미확인 처리 기준과 함께 정한다.
  4. 선택한 범위의 이름 우선 정책을 일반 검색·TOP3·같은 속/과·생태 관계·비교 카드에 일관되게 전달한다. 현재 점수 계산과 출처 검증은 유지하고, 이름 우선순위와 추천 순서를 화면에 설명한다.
  5. 국명/영어 이름 검증과 부족한 이름 후보의 대체 표시, 3종 미만인 후보 집합을 처리한다. 선택 범위 밖의 종으로 추천 수를 억지로 채우지 않는다.
  6. 토글 변경 시 이전 요청의 늦은 응답과 이전 범위의 비교 결과가 새 범위에 섞이지 않도록 상태·취소·재조회 동작을 정의한다.
- **예상 변경 위치**: 한국 서식 상태·근거/분류판 연결 데이터, 검색/API 범위 계약, 이름 우선 정책·후보 조회기, 채팅 토글·비교 화면, 관련 회귀 테스트·작업 문서. 구체 파일은 착수 시 코드·자료 검토로 확정한다.
- **협업 추천**:
  - **Codex 주 담당**: 자료·활성 분류 연결, 범위 API·후보 선정·이름 정책, 회귀·통합 검증.
  - **Claude 협업**: 토글·모드 설명·이름/출처 표시와 모바일 화면·상태 전환 UX.
  - **Antigravity 독립 검증**: 국내 서식 근거·계절/미조 기준·미확인 처리 대조, 실제 API·브라우저 범위 검증.
  - 추천이며 아직 위임하거나 실행하지 않았다. 실행 시 사용 가능한 설정 모델을 확인한다.
- **완료 기준·검증 계획**:
  - 한국 서식종 모드는 확인된 국내 집합만 반환하고 국명이 우선된다. 비서식종 모드에서는 확인된 해외 집합만 반환하고 영어 이름이 우선된다.
  - 한국어 이름이 있는 해외 종, 국명이 없는 국내 종, 서식 여부 미확인 종을 각각 검증해 이름 유무와 서식 판정을 혼동하지 않는다.
  - 철새·나그네새·미조·자료 충돌·분류판 불일치의 포함/미확인 동작이 정의된 기준과 일치한다.

### RG-101 — 문헌 Chunk 검색 저장소 분리 (PostgreSQL pgvector + Neo4j 정책 재확인)

- [ ] 착수 대기 — 신규 작업 등록 (2026-10-09). DB 관련 작업은 100번대로 관리한다.
- **우선순위**: 미정 — 첫 단계(실측)로 이전 시점과 규모 기준을 정한 뒤 결정한다.
- **목적·배경**: 문헌 Chunk가 계속 늘어난다. Neo4j에 본문·벡터를 두면 페이지 캐시와 메모리(16GB NAS 공유)를 차지하고 라이선스·출처 같은 정형 조건으로 먼저 거르는 검색이 불편하다. Chunk 본문·임베딩·전문 색인을 PostgreSQL(pgvector)로, 그래프 관계(Document·Chunk 식별 노드, EvidenceUnit, Claim)를 Neo4j에 두는 구조를 검토한다. ADR-0001이 "관찰·문헌 청크의 규모와 실제 성능을 측정한 후 유지 여부를 다시 판단한다"고 정한 후속이다.
- **기술 방향**: 설계안은 저장소 `docs/decisions/0007-chunk-search-store-split.md`(Proposed). 정책의 기준값(`SourceDataset.policy_status`, `Document.embedding_allowed`)은 Neo4j에 유지한다. PostgreSQL이 정책 사본 플래그로 사전 필터해 후보를 뽑고 Neo4j가 `_RECHECK_AND_CITE_QUERY`로 권위 있는 재확인을 한다. 사본은 성능 최적화이고 보안 경계는 Neo4j 재확인이다. Neo4j 재확인이 안 되면 PostgreSQL 결과만 내보내지 않는다(현행 fail-closed 보존). `search()` 시그니처와 `hybrid.py`의 RRF는 유지한다. 논의 기록: [[Work/RobinGraph/검토자료/2026-10-09-DB-저장소-분담-논의|DB 저장소 분담 논의]].
- **범위·구현 단계**:
  1. **실측**: 실제 Chunk 수·본문 크기, Neo4j 전문/벡터 검색 p50/p95 지연, 벡터 인덱스의 메모리·페이지 캐시 영향, 정책 필터 탈락률을 측정한다. 이전 시점과 규모 기준을 이 결과로 정한다.
  2. **인프라 확인**: pgvector를 쓸 PostgreSQL을 정한다. 현재 5433 포트는 n8n과 공유하는 `postgres:16-alpine`이며 pgvector 포함 여부를 확인하지 않았다. 기존 인스턴스 사용과 검색 전용 별도 인스턴스를 비교한다.
  3. **한국어 전문 검색 비교**: `pg_trgm`, `pg_bigm`, `pgroonga`, 전문 검색만 Neo4j 유지를 평가 세트로 비교한다.
  4. **설계 확정**: 실측과 인프라 결과를 반영해 ADR-0007을 수정하고 승인한다. 임베딩 프로필별 테이블/부분 인덱스, 정책 사본 동기화(ADR-0006 outbox), 후보 over-fetch 상한을 확정한다.
  5. **구현**: 순위 생성·재확인 인터페이스 분리, PostgreSQL `search` 스키마, 적재 경로(현행 `index_chunks`의 전체 교체 의미 보존), 설정값(`ROBINGRAPH_CHUNK_SEARCH_BACKEND=neo4j|postgres`).
  6. **전환**: 이중 적재 → 같은 질의 세트로 그림자 비교 → 설정 전환 → 일정 기간 뒤 Neo4j의 Chunk 본문·벡터 속성과 인덱스 제거(식별 노드와 관계는 유지).
- **예상 변경 위치**: `src/robingraph/retrieval/neo4j_hybrid.py`, `retrieval/hybrid.py`(변경 최소), 새 PostgreSQL 검색 모듈, `ingest/`의 outbox 투영, `cli.py`, `scripts/load_pmc_pilot.py`, `docs/decisions/0007-*`.
- **완료 기준·검증 계획**: `tests/test_neo4j_hybrid.py` 시나리오를 두 백엔드에 같이 적용한다. 정책 취소 시 모든 채널에서 제거(PostgreSQL 사본이 오래된 경우 포함), 임베딩 허용만 취소 시 전문에는 남고 벡터에서 제외, 프로필·`content_hash` 불일치 시 벡터 채널 비활성과 경고, Neo4j 재확인 불가 시 PostgreSQL 결과 비노출, 경고에 제외된 id 미포함, 특수문자·불리언 키워드 안전 처리를 확인한다. 이중 적재 후 결과 겹침·순위·누락·정책 제외 수를 기존 평가 코드와 평가 세트로 비교하고, 실제 TEST DB·API에서 검색·인용을 확인한 뒤 전환·롤백을 검증한다. 품질이나 지연이 기준에 못 미치면 Neo4j 백엔드를 유지한다.
- **선행 조건·경계**: RG-014(HippoRAG 스타일 검색)가 같은 `hybrid.py`·`neo4j_hybrid.py`를 수정 대상으로 잡고 있어 순서와 인터페이스를 함께 정해야 한다. 정책 기준 데이터는 PostgreSQL로 옮기지 않는다. 관찰(Observation)·분류·Claim의 RDB 이전은 이 작업에 포함하지 않는다. 현재 검색 쿼리는 `:Fixture` 레이블 코퍼스 대상이므로 PROD 코퍼스 확대 경로와 레이블 정책을 함께 정리한다.
- **결과 기록**: 계획 등록만 완료. 실측·인프라 확인·구현·DB 변경·배포는 미실행. 설계 문서는 코드 읽기만으로 작성했고 관련 테스트는 실행하지 않았다.

  1. 응답 결과를 정상 답변(`answer`), 추가 확인(`clarify`), 답변 보류(`abstain`), 실행 오류(`error`)로 구분하고 실패/보류 사유를 별도 구조화한다. 정상적인 자료 없음 응답을 무조건 기술적 ERROR로 바꾸지 않는다.

## 지속적 백로그 운영 규칙

1. 작업 상세는 ID별로 한 곳에만 둔다. 현황표는 상태·우선순위·요약·상세 링크만 관리한다.
2. 새 작업 추가와 상태 변경 시 목차, 현황표, 상세 위치를 함께 갱신한다. 제목은 고유하게 유지하고 기존 ID를 재사용하지 않는다.
3. 보류 작업은 사용자 재개 지시에 따라 진행 중으로 전환한다. 실제 진행 작업이 생기면 별도 ‘진행 중 작업’ 구역을 만들고 목차·현황표에도 반영한다.
4. 완료 기준을 모두 충족한 뒤 완료 상세로 이동한다. 일부 구현·배포만 끝난 작업은 완료 처리하지 않고 완료 범위와 남은 범위를 나누어 기록한다.
5. 실제 담당·확인된 모델과 검증 환경, 통과·실패·건너뜀, 해당하는 커밋·배포 정보를 기록한다. 문서 작업처럼 해당하지 않는 항목은 그 이유를 적는다. 인증 정보는 기록하지 않는다.
6. 과거 우선순위와 기준 수치는 변경 이력에 날짜와 함께 보존한다. 현재 현황표와 혼동되는 추천·순위는 남기지 않는다.
