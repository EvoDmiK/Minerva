## 요청 배경과 범위

까치의 등급과 생태 자료 누락을 계기로, 사용자가 까치뿐 아니라 전체 종에 적용할 자료 연결 개선을 요청했다. IUCN 신뢰 출처 조사는 Antigravity에 배정했고, 필요할 경우 n8n을 수집에 사용하도록 허용했다. 이 문서는 보전 자료 조사 결과이며 형질 조회 복구와는 별도다. 조사 자체는 운영 코드·DB·등급·n8n 워크플로를 변경하지 않았다.

## 확인한 출처와 채택 범위

1. [GBIF가 호스팅하는 IUCN 공개 체크리스트](https://www.gbif.org/dataset/19491596-35ae-4a91-9a98-85cf505f1bd3): 발행기관 IUCN, DOI `10.15468/0qnb58`. 고정한 공개 ZIP의 `eml.xml`을 Codex가 직접 읽어 제목과 배포일 2026-07-28, CC BY 4.0 표기를 재확인했다. 현재 공개 목록 연결에 사용하는 2026-1 배포본이다. 이용 조건 확인은 **이 배포본**에 한정하며 IUCN 모든 자료나 API에 확대하지 않는다.
2. [공식 IUCN API](https://api.iucnredlist.org/): 이전 작업의 HTTP 401 결과는 `docs/work-log/2026-10-09-iucn-api-access-check.md`에 기록되어 있다. 이번 조사에서는 토큰으로 재요청하지 않았다. 승인된 API 이용이 확인되기 전까지 현재 공개 체크리스트 경로를 유지한다.
3. [BirdLife 분류 자료](https://datazone.birdlife.org/about-our-science/taxonomy) 및 [이용 조건](https://datazone.birdlife.org/terms-and-conditions): 조류 평가·분류의 중요한 참고 자료다. Antigravity가 확인한 DataZone 이용 조건에는 TDM·스크래핑 제한이 있어 이번 수집 경로로 채택하지 않았다. 체크리스트 파일을 내려받을 수 있다는 사실만으로 별도 이용 조건까지 승인된 것으로 보지 않는다.
4. 국내 국가 적색목록·법정 보호등급은 세계 IUCN 평가와 구분해야 한다. 국립생물자원관·국립생태원은 후속 후보이나, **정확한 배포 파일과 해당 이용 조건을 이번 통합 검토에서 재현 가능하게 확정하지 못했으므로 라이선스 미검증으로 남긴다.** 포털 루트나 다른 게시물의 공공누리 표시를 전체 자료에 적용하지 않는다.
5. [홍콩조류협회 까치 종 계정](https://avifauna.hkbws.org.hk/species/0260/033600)은 Pica serica 설명과 LC 기술의 참고 문헌이다. 현재 까치 화면 LC는 기존 사용자 요청 표시와 해당 문헌을 근거로 유지한다. 공식 세계 평가 원문을 독립 검증한 것으로 승격하지 않으며 원자료 NE와 `independently_verified: false`를 보존한다.

## 제안: n8n을 활용한 갱신

사용자가 필요시 n8n 활용을 허용했다. 현 시점에는 이미 저장된 형질 후보값이 온전하여 재수집이 필요하지 않았고, n8n 워크플로를 만들거나 실행하지 않았다. 향후 공개 보전 목록 갱신은 다음 흐름으로 구성할 수 있다.

1. 공식 공개 배포본의 릴리스 메타데이터·ETag/Last-Modified를 정기 확인한다. 헤더 미지원 시 다운로드 해시로 비교한다.
2. 새 파일을 별도 보관하고 전체 SHA-256, 라이선스, 릴리스, 원본 URL, 취득 시각을 기록한다. 해시 계산만으로 원본 신뢰가 입증되는 것은 아니므로 공식 배포 경로도 검증한다.
3. 고정된 새 스냅샷으로 오프라인 인덱스를 만들고 기존 연결과 등급의 차이를 보고한다.
4. 다대일·일대다 분류, 명명자 연도 차이, 인용/평가 ID 불일치는 자동 확정하지 않는다. 종수 급변·연결 탈락·등급 변화도 검토 대상으로 둔다.
5. 검증한 산출물로 TEST에서 실제 응답을 확인한 후 배포한다. 원본과 직전 인덱스를 남겨 되돌릴 수 있게 한다.

이 흐름은 제안이며 현재 예약 수집 또는 DB 변경은 없다. 새 원본이 확보되기 전 형질 비율을 추정하여 채우거나 지역 적색등급을 세계 등급 필드에 넣지 않는다.

## 해설 — 이번 조사가 답하려던 질문

사용자의 핵심 질문은 “까치는 실제로 LC라고 하는데 앱은 왜 미확인 또는 NE로 보이는가”, “다른 종에도 비슷한 문제가 얼마나 있는가”, “AviList 이외의 신뢰할 수 있는 출처로 확인할 수 있는가”였다.

이를 판단하려면 네 층을 따로 확인해야 한다. 첫째는 현재 앱이 어느 종을 가리키는지, 둘째는 원목록이 어떤 값을 갖는지, 셋째는 그 종과 평가 자료의 연결을 검증했는지, 넷째는 연결된 평가 원문까지 직접 확인했는지다. 화면에 표시된 등급 하나만으로 이 네 가지가 모두 해결됐다고 볼 수 없다.

| 구분 | 확인하는 질문 | 이번 결과 |
|---|---|---|
| 종 식별 | ‘까치’가 Pica serica로 해석되는가 | 기존 이름 정책 유지, TEST 실제 응답에서 확인 |
| 원자료 보존 | AviList의 원값을 남겼는가 | 원자료 NE를 보존 |
| 화면 표시 | 사용자에게 무엇을 보여주는가 | 기존 문헌 보완과 요청에 따른 LC 유지 |
| 공개 목록 연결 | 고정 체크리스트와 현행 규칙으로 연결되는가 | 전체 11,131종 중 7,507종 연결 재현 |
| 평가 원문 독립 확인 | 정확한 종 범위·평가 ID·시점의 원문을 읽었는가 | 전수 수행하지 않음, independently_verified=false 유지 |

따라서 까치 화면의 LC를 확인한 것과 세계 평가 원문을 독립 검증한 것은 서로 다른 결과다. 이번 작업은 그 차이를 숨기지 않고 출처와 상태를 보존하는 방향으로 기록했다.

## 해설 — AviList NE와 공식 미평가를 구분해야 하는 이유

AviList는 앱의 현재 종 분류 기준이다. 보전 평가 자료가 사용하는 분류 범위와 맞지 않으면, 그 평가를 해당 AviList 종으로 그대로 연결할 수 없는 경우가 있다. 이런 맥락의 NE를 보고 “IUCN이 이 새를 한 번도 평가하지 않았다”고 단정할 수 없다.

반대로 다른 이름의 종에 LC가 보인다는 이유만으로 현재 종도 LC라고 자동 복사해서는 안 된다. 이름 변경인지, 분할·통합인지, 일부 집단만 겹치는지 확인해야 한다. 형질 복구에서 사용한 Avibase 개념 검증도 그 원칙을 따른 것이지만, 형질 교차표 승인이 IUCN 평가 연결 승인까지 대신하지는 않는다.

808종은 현행 감사에서 ‘AviList NE로 개념 검토 필요’에 해당한 집계다. 이 숫자는 808종 모두가 새로 분리된 종이라는 증거나 실제 미평가 종 수가 아니다. 사용자 화면의 ‘미확인’은 연결 상태를 나타내는 경우가 있으므로 보전 상태 자체와 혼동하지 않게 다뤄야 한다.

### 수치 계산을 다시 확인하는 방법

전체 11,131 = 연결 7,507 + 제외 3,624다. 제외 3,624 = 명명자 2,286 + 학명 474 + 평가 ID/인용 56 + NE 개념 검토 808이다. 이 표는 현행 판정에서 분류한 상위 사유의 집계다.

명명자 2,286건 내부의 패턴 묶음은 933 + 1,353이다. 세부 플래그는 같은 행에 여러 개가 생길 수 있어 플래그 수를 그대로 더해 종 수로 취급하지 않는다. 특히 933건 분석은 성씨 자체의 동일성을 검사한 것이 아니다.

추가 검토 후보 2,816을 7,507에 더해 ‘10,323종 검증 완료’로 쓰면 안 된다. 후보 분석은 아직 연결 규칙 변경이나 개별 평가 확인이 아니며, 이번에 완료한 연결 수는 현행 7,507의 재현이다.

## 후속 설계 — 새 출처를 넣기 전에 남길 정보

다음은 향후 구현을 위한 검토 기준이며 이번에 새 DB 필드를 만들거나 전체 종 레코드에 적용한 내용은 아니다.

| 남겨야 할 정보 | 필요한 이유 |
|---|---|
| 발행 기관·배포 URL·자료 DOI | 누가 제공한 어떤 자료인지 구별 |
| 릴리스·게시일·취득 시각·파일 SHA-256 | latest 주소의 변경과 과거 결과를 추적 |
| 해당 배포 파일의 라이선스·귀속 문구 | 사이트 전체 정책을 잘못 전용하지 않도록 함 |
| 원본 학명·명명자·분류 개념 식별자 | 현재 AviList 종과 같은 범위인지 확인 |
| 평가 식별자·평가 URL·서지 인용 | 이름만 비슷한 다른 평가의 등급 혼입 방지 |
| 세계/지역 평가 범위 | 국내 적색목록을 세계 IUCN 등급으로 오인하지 않도록 함 |
| 원자료 등급·화면 표시 등급·연결 상태 | 원값 보존과 표시 정책 변경을 추적 |
| 독립 검증 여부와 검증 근거 | 목록 연결과 원문 검토를 구분 |
| 승인/보류 사유·직전 버전과의 차이 | 자동 갱신 때 판정 변화를 검토 |

이 정보를 확보하더라도 출처의 평가는 시점과 범위를 갖는다. 이름이 일치한다는 이유만으로 최신 평가 또는 같은 분류 범위라고 간주하지 않는다.

## 후속 설계 — n8n 수집 흐름과 검토 지점

n8n은 자료를 정기 확인하고 보관·비교하는 데 사용할 수 있다. 종 개념 불일치나 불확실한 평가 연결을 자동으로 승인하는 역할까지 맡기는 것은 이번 제안의 범위가 아니다.

| 단계 | 제안하는 처리 | 실패 또는 변화 발생 시 |
|---|---|---|
| 갱신 감지 | 배포 메타데이터·ETag·Last-Modified 확인, 필요시 파일 해시 비교 | 다운로드 실패를 기존 값 없음으로 덮어쓰지 않음 |
| 원본 보관 | 공식 경로, 전체 파일, 시각, 버전, 라이선스 기록 | 출처·이용 조건 미확정이면 새 버전 적용 보류 |
| 오프라인 분석 | 고정 스냅샷에서 인덱스 생성 | 손상·구조 변경·필수 필드 누락이면 중단 |
| 차이 보고 | 연결 증가/탈락, 등급 변경, 분류 불일치 목록 생성 | 다중 대응·불일치는 검토 대상으로 남김 |
| TEST 확인 | 대표종과 예외종의 실제 API·카드·출처 확인 | 기존 정상 응답 회귀 시 배포 보류 |
| 적용 및 이력 | 검토된 산출물의 버전과 적용 기록 보관 | 직전 검증 산출물을 되돌릴 수 있게 보존 |

현재 상태는 **설계 제안**이다. 정기 실행 주기, n8n 워크플로 ID, 실행 성공 기록은 없다. 사용자의 n8n 활용 허용과 실제 구축 완료를 혼동하지 않는다. 이번 형질 데이터는 후보에 온전히 저장돼 있어 이 흐름을 실행할 필요가 없었다.

## 검증 책임과 유지보수 인계

Antigravity는 출처·연결 불일치 조사와 재현 분석을 맡았다. Codex는 고정 ZIP의 EML을 직접 확인하고 같은 고정 입력으로 분석을 독립 재실행하여 집계를 확인했다. 이는 원본 두 파일을 사용한 실제 재현이며 모의 API 결과는 아니다.

재현 스크립트는 입력 해시를 기록하지만 이 문서의 고정 해시를 자동 강제하는 도구로 해석하면 안 된다. 새 파일로 실행했다면 먼저 입력 해시·버전·구조를 비교하고 새로운 분석 결과로 기록해야 한다. 다운로드 URL이 같아도 바이트가 달라지면 이번 집계와 동일한 스냅샷이 아니다.
