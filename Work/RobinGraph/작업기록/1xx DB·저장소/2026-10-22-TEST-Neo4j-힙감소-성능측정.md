# TEST Neo4j Heap 감소 성능측정 (2GiB/4GiB) — 2026-10-22

> TEST 환경(16GB Mac .97 앱 / 32GB Mac .98 Neo4j)에서 Neo4j 힙 설정(초기 2GiB / 최대 4GiB, pagecache 1GiB) 하의 순수 읽기 성능을 실측했다. Chunk 검색(과거 관측 비교), 3.3만 종 도메인 그래프 복합 질의, 855종 이름 벡터 조회를 순차 warm 조건에서 측정했다. 설정 변경, 컨테이너 재시작, DB 쓰기, 애플리케이션 코드 변경, 운영 반영 및 Git commit/push는 일체 수행하지 않았다.

## 2. 세부 검증 내용 및 관측 사실

### 1) Chunk 검색 관측 비교 (`chunk-current.json`, `summary.json`)
- 5문항 x 10회 = 50회 순차 warm 실행 결과, 전문 5.453ms, 벡터 10.901ms, 하이브리드 11.386ms의 p50이 기록되었다.
- 10/18 기준선 대비 약 +1.5 ~ 2.0ms의 지연 증가가 관측되었으나, **과거와 현재의 코드베이스, 데이터 구성 및 테스트 환경이 달라 이를 힙 감소에 따른 인과적 A/B 결과로 단정할 수 없다.**
- Chunk 코퍼스는 4개 synthetic fixture(171문자)로 과거와 동일하며, 대규모 문헌 코퍼스 하의 힙 영향도를 검증한 것은 아니다.

### 2) 도메인 그래프 관계 질의 실측 (`graph-current.json`, `graph-probe.py`)
- 분류 관계(LCA), 동일 속, 국내 서식 동일 속, 참새목 열매, 서식지 일치/먹이 상이, 숲 직박구리 먹이 공유 등 6개 문항을 순회하며 각 20회(총 120회) 실측했다.
- 총 380회의 실제 Cypher 쿼리가 실행되었으며, 문항별 결과 해시는 20회 모두 100% 일치하여 응답 안정성을 확인했다.
- 순수 Neo4j 왕복 지연시간(Bolt 네트워크 및 드라이버 디코딩 포함) 중앙값은 **60.3ms ~ 273.7ms**였으며, PostgreSQL 메타데이터 조회 및 Python 계층 처리를 포함한 서비스 전체 응답 중앙값은 **132.8ms ~ 490.0ms**였다(HTTP 통신, 분류 모델, 임베딩 호출 제외).

### 3) 종 이름 벡터 검색 실측 및 프로브 가드 보정 (`names-current.json`, `names-probe.py`)
- 저장된 855건 카탈로그 중 3종(`Nestor notabilis`, `Anas zonorhyncha`, `Anas platyrhynchos`)의 벡터를 재사용하여 각 20회(총 60회) 검색을 수행했다.
- top-1 자가 매칭 정확도는 **60회 전수 100%** 일치했으며, Neo4j 왕복 지연 p50은 **2.456ms ~ 2.924ms**로 매우 안정적이었다.
- **프로브 진단 가드 보정 이력**: 최초 프로브 스크립트 작성 시 cosine 유사도 조건을 `> 0.9999`로 과도하게 엄격히 설정하여 올바른 1위 결과(`score: 0.9998698...`)를 비정상 탈락시키는 현상이 발생했다. 이는 애플리케이션이나 인덱스 버그가 아니며, 진단 가드를 올바른 `taxon_id` 일치 및 유효 유사도 범위(`0 <= score <= 1`)로 정정하여 60회 전수 통과했다.

### 4) JVM 힙 및 GC 동작 관측 (`runtime-mid.json`, `runtime-after.json`)
- JMX 관측 힙 사용량(used)은 시작 시점 303.9 MiB, 그래프 질의 도중 265.9 MiB, 측정 종료 후 123.0 MiB로 나타났다. 이는 특정 시점의 JVM Used Heap 스냅샷일 뿐이며 프로세스 RSS(물리 메모리)나 최고 메모리 점유를 측정한 것은 아니다.
- 그래프 질의 중간(`runtime-mid`)부터 종료(`runtime-after`) 사이의 델타 측정 결과, G1 Young Generation GC는 4회(총 47ms) 발생했고 Old Generation GC는 0회(0ms)였다.

## 3. 한계 및 해석 유의사항

1. **인과적 A/B 비교 불가**: 10/18과 10/22 간 힙 외의 다양한 요인이 존재하므로 관측된 지연 차이를 힙 축소의 직접적 영향으로 단정하지 않는다.
2. **힙 추가 축소 안전 확언 금지**: 본 벤치마크는 단일 스레드(동시성 1) 순차 warm 읽기 부하에 국한된다. "현재의 순차 읽기 부하 하에서 큰 성능 장애나 비정상 메모리 누수가 관측되지 않았다"는 선까지만 유효하며, 힙을 더 줄여도 안전하다거나 대규모 운영 부하를 견딜 수 있다는 결론으로 확대 해석하지 않는다.
3. **미검증 영역**: Cold cache(인스턴스 재시작 직후), 다중 동시 요청(고동시성), 장기 GC soak, OS 레벨 물리 메모리(RSS, Swap, 페이지 캐시 히트율)는 검증 대상에 포함되지 않았다.
