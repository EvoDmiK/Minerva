## 작업 상세

### RG-101 — 문헌 Chunk 검색 저장소 분리 (PostgreSQL pgvector + Neo4j 정책 재확인)

- [ ] 착수 대기 — 신규 작업 등록 (2026-10-09). DB 관련 작업은 100번대로 관리한다.
- **우선순위**: 미정 — 첫 단계(실측)로 이전 시점과 규모 기준을 정한 뒤 결정한다.
- **목적·배경**: 문헌 Chunk가 계속 늘어난다. Neo4j에 본문·벡터를 두면 페이지 캐시와 메모리(16GB NAS 공유)를 차지하고 라이선스·출처 같은 정형 조건으로 먼저 거르는 검색이 불편하다. Chunk 본문·임베딩·전문 색인을 PostgreSQL(pgvector)로, 그래프 관계(Document·Chunk 식별 노드, EvidenceUnit, Claim)를 Neo4j에 두는 구조를 검토한다. ADR-0001이 "관찰·문헌 청크의 규모와 실제 성능을 측정한 후 유지 여부를 다시 판단한다"고 정한 후속이다.
- **기술 방향**: 설계안은 저장소 `docs/decisions/0007-chunk-search-store-split.md`(Proposed). 정책의 기준값(`SourceDataset.policy_status`, `Document.embedding_allowed`)은 Neo4j에 유지한다. PostgreSQL이 정책 사본 플래그로 사전 필터해 후보를 뽑고 Neo4j가 `_RECHECK_AND_CITE_QUERY`로 권위 있는 재확인을 한다. 사본은 성능 최적화이고 보안 경계는 Neo4j 재확인이다. Neo4j 재확인이 안 되면 PostgreSQL 결과만 내보내지 않는다(현행 fail-closed 보존). `search()` 시그니처와 `hybrid.py`의 RRF는 유지한다. 논의 기록: [[Work/RobinGraph/검토자료/2026-10-09-DB-저장소-분담-논의|DB 저장소 분담 논의]].
- **범위·구현 단계**:
  1. **실측**: 실제 Chunk 수·본문 크기, Neo4j 전문/벡터 검색 p50/p95 지연, 벡터 인덱스의 메모리·페이지 캐시 영향, 정책 필터 탈락률을 측정한다. 이전 시점과 규모 기준을 이 결과로 정한다.
  2. **인프라 확인**: pgvector를 쓸 PostgreSQL을 정한다. 현재 5433 포트는 n8n과 공유하는 `postgres:16-alpine`이며 pgvector 포함 여부를 확인하지 않았다. 기존 인스턴스 사용과 검색 전용 별도 인스턴스를 비교한다.
  3. **한국어 전문 검색 비교**: `pg_trgm`, `pg_bigm`, `pgroonga`, 전문 검색만 Neo4j 유지를 평가 세트로 비교한다.
  4. **설계 확정**: 실측과 인프라 결과를 반영해 ADR-0007을 수정하고 승인한다. 임베딩 프로필별 테이블/부분 인덱스, 정책 사본 동기화(ADR-0006 outbox), 후보 over-fetch 상한을 확정한다.
  5. **구현**: 순위 생성·재확인 인터페이스 분리, PostgreSQL `search` 스키마, 적재 경로(현행 `index_chunks`의 전체 교체 의미 보존), 설정값(`ROBINGRAPH_CHUNK_SEARCH_BACKEND=neo4j|postgres`).
  6. **전환**: 이중 적재 → 같은 질의 세트로 그림자 비교 → 설정 전환 → 일정 기간 뒤 Neo4j의 Chunk 본문·벡터 속성과 인덱스 제거(식별 노드와 관계는 유지).
- **예상 변경 위치**: `src/robingraph/retrieval/neo4j_hybrid.py`, `retrieval/hybrid.py`(변경 최소), 새 PostgreSQL 검색 모듈, `ingest/`의 outbox 투영, `cli.py`, `scripts/load_pmc_pilot.py`, `docs/decisions/0007-*`.
- **완료 기준·검증 계획**: `tests/test_neo4j_hybrid.py` 시나리오를 두 백엔드에 같이 적용한다. 정책 취소 시 모든 채널에서 제거(PostgreSQL 사본이 오래된 경우 포함), 임베딩 허용만 취소 시 전문에는 남고 벡터에서 제외, 프로필·`content_hash` 불일치 시 벡터 채널 비활성과 경고, Neo4j 재확인 불가 시 PostgreSQL 결과 비노출, 경고에 제외된 id 미포함, 특수문자·불리언 키워드 안전 처리를 확인한다. 이중 적재 후 결과 겹침·순위·누락·정책 제외 수를 기존 평가 코드와 평가 세트로 비교하고, 실제 TEST DB·API에서 검색·인용을 확인한 뒤 전환·롤백을 검증한다. 품질이나 지연이 기준에 못 미치면 Neo4j 백엔드를 유지한다.
- **선행 조건·경계**: RG-202(HippoRAG 스타일 검색)가 같은 `hybrid.py`·`neo4j_hybrid.py`를 수정 대상으로 잡고 있어 순서와 인터페이스를 함께 정해야 한다. 정책 기준 데이터는 PostgreSQL로 옮기지 않는다. 관찰(Observation)·분류·Claim의 RDB 이전은 이 작업에 포함하지 않는다. 현재 검색 쿼리는 `:Fixture` 레이블 코퍼스 대상이므로 PROD 코퍼스 확대 경로와 레이블 정책을 함께 정리한다.
- **결과 기록**: 계획 등록만 완료. 실측·인프라 확인·구현·DB 변경·배포는 미실행. 설계 문서는 코드 읽기만으로 작성했고 관련 테스트는 실행하지 않았다.

### RG-102 — PROD 활성 종 데이터 준비

- [ ] 보류 — 최후순위
- **우선순위**: 최후순위 (2026-10-07 사용자 지시).
- **목적**: PROD에서도 실제 종 조회가 가능하도록 한다.
- **범위**: TEST·PROD 데이터 분리, 수집 상태와 활성 스냅샷, 출처·릴리스 확인.
- **완료 기준**: PROD에서 실제 종 질문의 설명·카드·관련 새 조회를 검증한다.
- **현재 상태 (2026-10-10 갱신)**: 운영 데이터가 없다는 과거 안내를 정정한다. 승인된 이관 후 Neo4j 노드 475,063개·관계 543,728개의 속성 정규화 해시를 TEST와 PROD에서 대조했고, PostgreSQL 수집 8개 테이블은 운영 고유 이력을 보존해 동기화했다. 실제 운영 프로필·계통·채팅과 카드 브라우저 검증은 완료했다. 현재 앱은 TEST와 동일 이미지의 `3ac07e2`이다. 다만 **운영 관련 새 조회**의 완료 증거는 이번 문서 대조에서 확인하지 못해 전체 항목은 보류를 유지한다. 데이터 미준비 때문에 보류된 것은 아니다.
- **근거·검증 경계**: 저장소 `docs/work-log/2026-10-09-approved-production-pg-sync-and-deploy.md` 및 `docs/verification/assets/2026-10-09-approved-production-{public-contract,public-samples,browser}.json`의 실제 DB·HTTP·브라우저 결과를 확인했다. 오늘 카드 릴리스에는 추가 DB 이관이 없었다. 남은 관련 조회는 실제 PROD에서 확인한 뒤 완료 처리한다.
- **기존 이관 이력**: [[Work/RobinGraph/작업기록/1xx DB·저장소/2026-10-09-TEST-PROD-데이터-이관|초기 데이터 이관]] · [[Work/RobinGraph/작업기록/7xx 배포·인프라/2026-10-09-PROD-API-3e639ce-배포|초기 PROD 배포]]

## 관리 기준

- 새 작업은 이 카테고리의 다음 ID로 등록하고 전체 백로그 현황표와 링크를 함께 갱신한다.
- 상세는 이 파일에서 관리하고, 구현·검증·배포 원문은 같은 폴더의 개별 작업기록에 보존한다.
- 여러 카테고리에 걸친 작업은 주된 변경 분야에 원문 하나만 두고 관련 카테고리에서 링크로 연결한다.
- 기존 파일명·옛 작업 ID·커밋·테스트·검증 결과는 보존한다.
