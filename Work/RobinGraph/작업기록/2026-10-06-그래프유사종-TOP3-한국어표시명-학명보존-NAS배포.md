## 1. 실제 그래프 탐색으로 유사종 TOP3 제공

### 사용자가 할 수 있는 것

- `멧비둘기와 비슷한 종은 어떤게 있니?`처럼 질문하면 상위 3종과 점수·가점 근거·출처를 바로 확인한다.
- 후보의 비교 버튼을 누르면 원래 답변과 별도의 말풍선에 두 종의 비교와 카드 버튼이 표시된다.
- `청둥오리와 같은 속의 새는?`는 기존의 같은 속 탐색으로 구분한다.
- `왜가리는 무엇을 먹고 사니?`는 출처 있는 먹이 구성비를 답한다.

### 알고리즘과 점수

알고리즘 식별자는 `taxonomy-ecology-v1`이다. 활성 분류 그래프의 속·과 관계와 출처가 확인된 생태 형질을 비교하여 규칙 점수를 합산한다.

| 공통 조건 | 가점 |
|---|---:|
| 같은 속 | 50 |
| 같은 과 | 30 |
| 같은 서식 환경 범주 | 10 |
| 같은 먹이 생태 범주 | 10 |

자기 자신을 제외한 허용된 활성 종 전체를 먼저 검사한다. 앞부분 일부만 뽑아서 순위를 계산하지 않는다. 생태 가점은 대상과 후보 양쪽에 같은 데이터셋·릴리스·분류값의 비추론 형질과 허용된 증거가 있어야 적용한다. 같은 관계의 증거가 여러 개여도 중복 가점하지 않는다.

양의 점수 후보를 점수 내림차순으로 정렬하고, 동점은 학명·종 ID 순서로 정렬해 최대 3종을 반환한다. 같은 속 가점에는 같은 과의 활성 경로 확인도 필요하다.

**점수는 외형·유전 유사도 백분율이나 확률이 아니다.** 현재 가중치는 같은 속·과를 강하게 우선한다. 사용자가 지적한 분류 가중치 편향은 인정했으며, 오늘은 가중치를 변경하지 않았다. 여러 기준 종으로 비교·평가하며 조정하는 작업이 남아 있다.

### 오늘 실제 NAS에서 확인한 샘플

각 조회에서 자기 자신을 제외한 11,130종을 검사했다. 아래 표시명은 오늘 최종 한국어 표시 자료를 반영했다. ‘번역명’은 공식 국명을 의미하지 않는다.

| 기준 종 | 상위 3종과 점수 |
|---|---|
| 멧비둘기 | 순다목도리비둘기 (번역명) 90 / 염주비둘기 90 / 필리핀목도리비둘기 (번역명) 90 |
| 청둥오리 | 고방오리 100 / 안데스청둥오리 (번역명) 100 / 흰뺨고방오리 (번역명) 100 |
| 왜가리 | 대백로 100 / 노란부리백로 (번역명) 100 / 코코이해오라기 (번역명) 100 |

처음 검증 당시의 GET 응답 시간은 멧비둘기 4.310초, 청둥오리 1.598초, 왜가리 1.726초였다. 오늘의 특정 실행 측정값이며 지속적인 성능 보장은 아니다.

## 2. 일반 소개 질문에도 유사종 결과 연결

`멧비둘기에 대해 알고싶어.`, `청둥오리에 대해 알고 싶어.` 같은 일반 소개에서도 종 설명·카드 표시 버튼을 유지하면서 설명창에 유사종 TOP3를 함께 제공한다.

- 응답 계약에 선택 필드 `ChatSpeciesResult.similar_species`를 추가했다.
- 종 ID·분류판·concept set이 맞는 결과만 연결한다.
- 미리 받은 결과를 기존 관련 종 탐색 화면에 전달해 중복 조회를 피한다.
- 유사종 조회 실패나 버전 불일치는 해당 부분만 생략하고 종 소개를 유지한다.
- 아종에는 종 단위 유사도 조회를 적용하지 않는다.
- 탐색·비교는 설명창에 두며 도감 카드 안으로 옮기지 않는다.

이 작업은 Claude와 GPT(Codex)가 Ponytail 방식으로 기존 API·화면 흐름을 재사용했다. Claude는 프로필 응답 연결을, GPT는 미리 받은 결과의 화면 연결과 자동 펼침을 맡았다. 새 유사도 엔진이나 의존성을 추가하지 않았다.

## 3. 서식 환경·먹이 생태 목록은 범주별 3종만 표시

‘같은 서식 환경·먹이 생태의 새 살펴보기’는 각 범주에서 최대 3종만 보여준다.

Neo4j에서 중복 제거한 후보 4개를 받아 추가 결과 여부를 판단하고 3개를 반환한다. 화면에서도 범주별 3개를 제한하며, 더 있으면 일부만 표시했음을 안내한다.

일반 유사종 TOP3와는 다르다. 이 목록은 같은 생태 분류값을 공유하는 종의 일부이며 기존 이름 정렬을 유지한다. 유사도 순위나 실제 공존·먹이 관계를 뜻하지 않는다.

청둥오리·멧비둘기에서 서식 환경 3종과 먹이 생태 3종을 확인했다. `왜가리와 먹이가 비슷한 새는?`도 해당 범주 후보 3종만 응답했다.

## 4. 전체 활성 종의 한국어 표시명과 원본 학명 보존

### 최종 이름 수

| 이름 구분 | 종 수 |
|---|---:|
| 기존 그래프의 한국어 이름 | 840 |
| IOC v15.2 한국어 참고 이름 | 170 |
| Gemini 번역명 | 10,121 |
| 합계 | 11,131 |

처음에는 한국어 이름 레코드가 847개였지만, 7개는 실제로 영어·포르투갈어·학명 값이었다. 이 7개는 원본 그래프를 수정하지 않고 화면 표시를 보완했다. 기존 한글 이름이 있는 종은 자동 번역으로 교체하지 않았다.

### 적용 방식

1. 기존 그래프의 한국어 이름을 우선한다.
2. 학명이 정확히 일치하는 IOC 한국어 참고 이름을 적용한다.
3. 나머지는 Gemini 번역명으로 표시하고 **(번역명)**을 붙인다.

카드 제목·카드 버튼·설명 제목·같은 속/과 목록·유사종 TOP3·생태 범주 목록·비교 표에 같은 표시 규칙을 적용했다. IOC 참고 이름에는 출처를 보존했다.

고정 자료 파일은 `src/robingraph/retrieval/species_ko_translations.json`이다. 종 ID·학명·원문 영명이 모두 일치할 때만 표시 보완을 적용한다. 요청마다 번역 API를 호출하지 않는다. 다른 분류 릴리스·학명·영명·아종으로 잘못 적용하지 않는다.

**학명, 종 ID, 원문 영어 이름은 원본 그대로 보존했다.** 학명과 분류군의 라틴어는 식별과 출처 표시를 위해 계속 보여준다.

### Gemini 협업의 실제 경로

Gemini CLI 작업자를 시작했으나 초기 로그인 단계에서 실행되지 않았다. 실제 이름 생성과 검토는 기존 NAS 서비스에 설정된 Gemini API의 `gemini-3.5-flash-lite`를 이용했다.

이름 생성 후 영문 원뜻과 대조하는 별도 검토를 수행하여 580개 표현을 보정했다. 이 검토는 공식 한국어 국명의 출처 검증을 대신하지 않는다. 따라서 확인되지 않은 이름은 번역명으로 구분한다. API 키는 NAS 컨테이너 환경 안에서만 사용했고 산출물에 저장하지 않았다.

### 표시명과 검색 이름의 차이

이번 변경은 화면 표시 자료 보완이다. Neo4j의 한국어 `VernacularName`이나 검색 별칭을 새로 적재하지 않았다. 새 번역명을 입력해 검색할 수 있다고 보장하지 않는다. 비교 버튼은 학명으로 원래 그래프 종을 조회한다.

아종의 별도 한국어 명명 체계나 새로운 분류 릴리스의 전체 번역 자료를 만든 작업도 아니다. 분류판이 바뀌면 자료 재수집·검토가 필요하다.

### 참고 자료

- [AviList v2025b](https://www.avilist.org/checklist/v2025b/): 종 ID·학명·원문 영명, CC BY 4.0.
- [IOC World Bird List 다국어 목록](https://www.worldbirdnames.org/new/ioc-lists/master-list-2/): v15.2 한국어 열과 정확한 학명 일치로 참고 이름 170개 보완.
- Gemini 번역·재검토: 출처로 확인한 표준명이 아닌 별도 표시 자료.
