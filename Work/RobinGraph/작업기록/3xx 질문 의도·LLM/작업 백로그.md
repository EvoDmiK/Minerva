### RG-301 — Jev System One API를 이용한 질문 의도 분석

- [x] 구현·NAS TEST 적용 완료 (2026-10-08) — 검증 한계는 아래 결과와 상세 기록을 따른다.
- **우선순위**: 완료 — 착수 당시 신규 작업 1순위.
- **목적·배경**: “청둥오리 아종 알려줘”, “흰뺨검둥오리 아종 알려줘”처럼 지원 가능한 질문이 자동 분류 단계에서 막히는 문제를 줄인다. 현재 자동 경로는 규칙 인식과 임베딩 기반 분류를 사용하며, 의도 판단과 종 이름 해소를 함께 검증해야 한다.
- **변경 전후 목표**: 분류 실패로 곧바로 추가 확인을 요구하던 질문을 Jev의 구조화된 의도 판단으로 적절한 조회기에 연결한다. 모호한 질문은 확신도를 기준으로 확인 질문을 유지한다.
- **범위·구현 단계**:
  1. 사용자 키 발급처 `https://thejevai.com/settings`에 맞춰 제공자 `POST https://thejevai.com/v1/systemone`, 모델 `typesafe/jev-1.13`, `state/model/questions`를 사용한다. 초기 TypeSafe 직접 주소의 401은 제공자 불일치였고 실제 제공자 API 호출로 재확인했다. 실제 응답은 `code=0 → data.result.answers.intent`다. [제공자 API](https://thejevai.com/docs)
  2. 상위 의도(종 정보·분류·관찰·근거·기타/불확실)와 필요한 세부 의도(아종 목록·먹이·서식 환경·활동·관련 종 등)를 기존 핸들러에 연결한다. Jev의 Choice 결과·확률 분포·confidence를 검증하며, 현재 임베딩 유사도 임계값을 그대로 이식하지 않는다. [의도 라우팅](https://docs.typesafe.ai/patterns/intent-routing), [확신도](https://docs.typesafe.ai/confidence)
  3. Jev의 의도 선택과 자유형 종 이름·날짜·장소 추출을 분리한다. 종 이름은 기존 이름 후보·별칭·분류판 대조와 원문 구간 추출을 사용하고, 선택한 의도와 필터가 서로 맞는지 확인한다. 의도만 profile로 바꾸고 전체 문장을 종 이름으로 넘기는 오류를 방지한다.
  4. 명시적 조회 모드와 확실한 기존 규칙 경로를 보존하고, 자동 모드의 나머지 판단에 Jev를 연결한다. 기타·낮은 확신도·복합 질문은 잘못된 단일 경로로 강제하지 않는다.
  5. 서버 환경 변수로 키·모델·타임아웃·라우터 선택을 설정한다. 인증 실패·요청 제한·과부하·잘못된 응답 시 제한된 재시도 후 기존 경로 또는 확인 질문으로 처리한다. 원래 라우터로 되돌릴 수 있게 한다.
  6. MLflow에 실제 모델, 의도·확신도, 라우팅 지연, 사용량과 실패 유형을 남긴다. 인증 정보는 기록하지 않는다.
- **예상 변경 위치**: `src/robingraph/api/semantic_router.py`, `src/robingraph/api/app.py`, `src/robingraph/cli.py`, 새 Jev 클라이언트·설정, 라우팅 테스트·환경 설정 문서.
- **협업 추천**:
  - **Codex 주 담당**: API 어댑터·라우팅 계약·이름/필터 연결·회귀 테스트·NAS TEST 배포.
  - **Claude 협업**: 한국어 질문 유형·혼동 사례·Choice 설명과 확인 질문 문구 설계, 평가 정답표 작성.
  - **Antigravity 독립 검증**: 공식 API 계약·확신도 해석 대조, 평가 정답표 검토, 실제 API·브라우저 재현 확인.
  - 에이전트의 현재 설정 모델을 사용하고 실제 실행 모델을 결과에 기록한다. 모델명을 미리 실행 사실로 확정하지 않는다.

  - 한국어 표현 변형·영문/학명·오타·여러 의도·범위 밖·자료 없음이 포함된 최소 100문항 정답표를 만들고, 임계값 조정용과 최종 평가용을 분리한다. 기존 라우터 대비 의도별 정확도·macro-F1·자동 처리율·오분류율·확인 질문 비율을 같은 조건으로 비교한다. 기존 정상 회귀 사례의 의도·대상은 모두 유지하고 신고 재현 사례는 모두 해결한다.
