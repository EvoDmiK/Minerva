# Obsidian 작업기록·검토자료 폴더 정리

## 요청 배경과 목표

사용자는 Obsidian MCP에서 작업내용과 검토내용을 폴더로 나눠 달라고 요청했다. 직전 RobinGraph 작업 맥락에 따라 범위를 `Work/RobinGraph/`로 잡았다. 기존51개 Markdown 문서는 구현·배포 기록, 사전 검토·출처 감사·성능 점검·설계, 프로젝트 관리 문서가 같은 깊이에 섞여 있었다. 기존 프로젝트 index에도 검토자료와 작업기록이 혼재했고 Strands 검토2개와 Jev 적합성 문서가 작업 목록에 빠져 있었다.

## 분류와 변경 전후

| 위치 | 기존 문서 수 | 기준 |
|---|---:|---|
| Work/RobinGraph/ | 3 | index.md·작업 백로그·구현/데이터/검증 가이드 |

기존48개 문서는 파일명을 유지해 이동했다. 별도 검토6개는 전체아종 Antigravity 화면검토, 전체아종 이름자료 출처감사, RG301 Jev 적합성검증, RG301 채팅플로우 지연점검, Strands Decider2B 의도분류/Mac학습 검토, Strands Decider 한국어 데이터셋 설계다.

09-30 NAS 이력/525 진단과10-02 임베딩 내부망 호출은 실제 환경 변경·복구·컨테이너 재생성을 수행해 작업기록에 둔다. 지연점검은 frontmatter가 worklog지만 실측과 개선 권고가 주목적이어서 검토자료에 둔다. 출처감사는 수집 스크립트·산출물·테스트를 포함한 부분작업 보고서지만 감사·규칙·커버리지 확인이 주목적이고 최종 통합 배포 기록이 따로 있어 검토자료에 둔다. 검토자료를 “코드 변경이 전혀 없는 문서”로 정의하지 않는다.

프로젝트 루트 index는 두 폴더로 가는 진입점으로 바꾸고, 각 하위 폴더에 전체 문서를 연결한 index.md를 생성했다. 이번 정리 기록도 작업기록에 추가하므로 정리 후 작업기록 원문은43개다. 각 폴더 index를 포함한 전체 문서 수는54개다. 본문에 포함된 작업 당시 검증·검토 결과는 해당 작업 문서 안에 보존한다.

## 링크와 본문 보존

Vault의 Markdown102개를 읽어 들어오는 링크와 이동 문서의 나가는 링크를 함께 확인했다. 전체 경로, RobinGraph로 시작하는 짧은 경로, 고유 파일명 위키 링크를 해석해 이동 대상의 새 Vault 전체 경로로 바꾼다. 제목 앵커·블록 참조·별칭을 보존하며 Markdown 상대 링크는 이동 후 문서 위치를 기준으로 계산한다. 다른 프로젝트 문서의 분류는 바꾸지 않고 이동 대상에 연결하는 링크만 정리한다.

프로젝트 루트 index 외18개 문서에서35개 텍스트 블록을 정확히 교체했다. 백로그가 커서 파일 전체 덮어쓰기 대신 작은 원문 블록의 정확 일치를 사용했다. 변경 전 본문에서 링크 대상만 바꾼 예상값과 저장 후 본문을 대조한다. 이 기록과3개 index를 제외한 기존 원문에는 새 내용·검증 결과를 추가하지 않는다.

## 협업과 검증

root가 MCP 조회·이동·링크 수정·인덱스 작성·저장 후 검증을 담당했다. card_selection_review는 애매한 문서8개의 본문을 읽고 독립 분류 기준과 링크 보존 점검 항목을 검토했다. 리뷰어는 Vault를 수정하지 않았다.

- Vault Markdown105개를 저장 후 다시 읽어 계획한 내용과 모두 일치했다. 기존102개는 루트 프로젝트 index의 재구성 및 이동 관련 링크 수정만 반영했고 그 외 본문을 보존했다.
- RobinGraph 기존51개는 누락·중복 없이 남아 있고 이동48개 모두 새 경로 존재·기존 경로 부재를 확인했다. 두 하위 index와 이번 정리 기록을 더해 RobinGraph54개다.
- RobinGraph 전체 경로 위키 링크200개를 검사해 누락 대상0·이전 이동 경로 참조0을 확인했다. 별칭·제목 앵커·블록 참조는 링크 경로만 치환한 예상 본문과의 일치로 보존을 확인했다.
- 작업기록 index는 기존42개+이번 기록1개의43개, 검토자료 index는6개를 중복 없이 연결한다. 세 index의 파일명이 같아도 전체 경로 링크로 분리된다.
- 기존 백로그의 작업 상태·우선순위와 본문은 이동 링크 치환 외에는 바꾸지 않았다. 다른 프로젝트와 Learning의 폴더 이동은0개다.
- MCP 읽기/이동/편집을 실제 수행한 결과이며 모의 Vault 검증으로 대체하지 않았다. 앱·DB/API·배포 검증은 문서 정리 범위가 아니므로 실행하지 않았다.

## 적용 범위·Git·배포·한계

Obsidian 문서 구조와 연결 링크만 변경했다. RobinGraph 소스·DB·API·NAS 런타임 변경이 없어 앱 테스트·실제 DB/API 재검증·배포를 수행하지 않는다. 저장소 코드 변경이 없으므로 이번 요청에서 새 Git 커밋·push도 수행하지 않는다. Vault의 별도 자동 Git 동기화 완료 여부는 확인하지 않는다. 다른 Work 프로젝트와 Learning의 폴더 구조는 유지한다. Obsidian의 실제 화면·검색 인덱스 반영 속도는 별도로 검증하지 않는다. 인증 정보는 기록하지 않는다.
