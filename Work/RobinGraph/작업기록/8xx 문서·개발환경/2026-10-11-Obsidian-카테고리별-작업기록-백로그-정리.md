# Obsidian 카테고리별 작업기록·백로그 정리 — 2026-10-11

## 요청 배경과 목표

사용자는 Obsidian MCP를 통해 작업기록 폴더를 기존 작업 백로그의 카테고리로 나누고, 각 폴더 안에 백로그 파일을 만들어 정리하도록 요청했다. “일단 여기까지 하고 보자”라는 범위에 따라 폴더·백로그·연결 링크 정리까지만 수행했다. 등록된 기능 작업을 착수하거나 상태를 바꾸는 요청으로 해석하지 않았다.

대상은 현재 작업공간의 프로젝트와 일치하는 `Work/RobinGraph`다. Birds-Nest·Gullinkambi도 별도 작업기록과 백로그를 가지고 있으나 그 구조는 이번 정리 대상이 아니다. 다른 문서의 RobinGraph 이동 대상 링크는 연결 유지에 필요한 범위만 수정했다.

## 확인한 기존 구조와 근거

- `RobinGraph 작업 백로그.md`에 1xx~9xx, 9개 카테고리와 기존 ID 대응표가 있었다.
- 작업 상세는 카테고리와 별개로 착수 대기·보류·완료 상태별로 한 파일에 모여 있었다. 번호 작업 18개와 번호 없는 카드 3D 효과 1개, 총 19개 상세다.
- `작업기록/`에는 날짜별 작업기록 91개와 인덱스가 바로 놓여 있었다. 별도 검토자료는 이미 분리되어 있었다.
- 작업기록 파일명에는 옛 ID가 남아 있으므로 이름만으로 새 카테고리를 결정하지 않고 제목·요약·실제 범위를 확인했다.

## 변경 전후 동작

변경 전에는 큰 전체 백로그에서 작업 상세를 찾고 날짜순 인덱스에서 기록을 찾아야 했다. 변경 후 전체 백로그에서 카테고리를 선택하면 해당 폴더의 백로그에서 작업 현황·목적·범위·완료 기준·검증 이력·작업기록 목록을 함께 볼 수 있다.

전체 백로그에는 전체 현황·우선순위·ID 대응표·공통 운영 기준·과거 변경 이력을 남겼다. 기존 상세 제목은 카테고리별 백로그로 안내하는 바로가기로 유지하여 과거 제목 앵커 링크를 보존했다. 실제 상세 본문은 카테고리별 백로그 한 곳에서 관리한다.

## 폴더·파일 변경

모든 폴더 아래에 `작업 백로그.md`를 만들었다. 다음 기록 수는 이번 정리 기록을 제외한 기존 원문 수다.

| 카테고리 | 기존 작업기록 | 백로그 상세 |
|---|---:|---:|
| 1xx DB·저장소 | 3 | 2 |
| 2xx 검색·RAG·그래프 질의 | 10 | 2 |
| 3xx 질문 의도·LLM | 6 | 1 |
| 4xx 채팅 UI·카드 | 41 | 7 |
| 5xx 데이터·분류·이름 | 17 | 5 |
| 6xx 관측·평가 | 1 | 2 |
| 7xx 배포·인프라 | 8 | 0 |
| 8xx 문서·개발환경 | 5 | 0 |
| 9xx 기타·실험 | 0 | 0 |
| 합계 | 91 | 19 |

- 기존 원문 91개는 파일명·과거 작업 ID를 보존한 채 각 카테고리 폴더로 이동했다.
- 작업기록 인덱스는 9개 카테고리의 백로그·기록 목록으로 연결하는 표로 바꿨다.
- 프로젝트 인덱스와 관련 문서의 이동 대상 경로를 갱신했다. 기존 문헌 증류 스크립트 `scripts/distill_knowledge.py`의 해당 경로 문자열도 이동된 원문 경로로 맞췄다. 스크립트는 실행하지 않았다.
- 7xx·8xx·9xx에는 등록된 백로그 ID 작업이 없다는 사실을 표시했다. 기존 기록을 새 ID 작업으로 임의 등록하지 않았다.
- 각 카테고리 백로그에 새 기록 저장 위치와 전체 현황표 동시 갱신 기준을 적었다.

여러 분야에 걸친 기록은 주된 변경 분야에 원문 하나만 배치했다. 예를 들어 MLflow 태그·드래그 카드 통합 기록은 6xx 관측·평가에, TEST/PROD 이관·배포 종합 기록은 7xx 배포·인프라에 둔다. 관련 작업 상세의 링크로 다른 분야에서도 접근할 수 있다.

## 검증 방법과 실제 결과

### Obsidian MCP 실제 읽기·쓰기 검증

- MCP로 목록 조회·원문 읽기·파일 생성·이동·갱신을 수행했다. 로컬 파일의 모의 변경이 아니다.
- 이동·본문 갱신 직후 대상 111개 파일을 MCP로 다시 읽어 작성 예정 내용과 비교했다. 불일치 0개.
- 기존 작업기록 91개 모두 새 경로에서 확인했다. 이전 경로에 남은 원문 0개. 작업기록 루트의 Markdown 파일은 `index.md` 하나다.
- 원문 91개를 기존 본문과 비교하여 이동된 경로 문자열의 치환 외에는 동일함을 확인했다.
- 백로그 상세 19개 모두 카테고리별 백로그에 목적·범위·완료 기준·검증·결과를 포함한 기존 본문 그대로 존재함을 확인했다. 경로와 내부 제목 링크만 새 위치에 맞췄다.
- 갱신한 문서에서 제목 앵커 링크를 대상 문서의 실제 제목과 대조했다. 확인된 잘못된 제목 앵커 0개.
- Vault 전체 Markdown 206개를 읽고 위키링크 1,069개를 검사했다(이 정리 기록 생성 전 기준). 이전 RobinGraph 작업기록 경로를 참조하는 본문 0개.
- 당시 미해결 링크 7개 중 2개는 아직 작성 전이던 이 정리 기록을 가리킨 것으로, 이 문서를 작성해 연결했다. 나머지 5개는 이번 이동과 무관한 기존 예시 링크 4개와 다른 프로젝트의 이전 Dev 경로 링크 1개다. 요청 범위를 넘어 수정하지 않았다.

### 실행하지 않은 검증

- 앱 단위 테스트·브라우저 UI·실제 DB·외부 API 검증: 실행하지 않음. 앱 구현·DB·서비스 설정을 바꾸지 않은 Vault 구조 정리이기 때문이다.
- 문헌 증류 스크립트 실행: 건너뜀. 이번에는 이동 대상 문자열의 경로만 갱신했고 증류 작업은 요청 범위가 아니다.
- Obsidian GUI 화면 렌더링 및 첨부 파일 실물 검증: 수행하지 않음. MCP 재읽기·경로·위키링크·제목 앵커 검사로 검증했다. 원문에 있던 저장소 상대 첨부 링크의 유효성을 새로 확인했다고 주장하지 않는다.

## 커밋·배포 정보

RobinGraph 저장소 코드 변경·Git 커밋·푸시·TEST 배포·Production 배포·운영 컨테이너 재시작·DB 변경은 수행하지 않았다. 이번 요청은 Obsidian 문서 정리다. Vault 동기화 도구의 후속 커밋·원격 동기화 완료 여부도 별도로 조회하지 않았다.

## 남은 한계와 후속 관리

- 새 상세는 해당 카테고리 백로그에 작성하고, 상태·우선순위 변경은 전체 현황표에도 반영한다.
- 새 작업기록은 같은 카테고리 폴더에 저장하고 백로그의 기록 목록에 링크한다.
- 9xx는 현재 빈 카테고리지만 추후 작업을 위해 백로그를 마련했다.
- 기존 작업 상태·우선순위·과거 배포 및 검증 결과는 바꾸지 않았다. 자료 갱신이나 미해결 기능 착수는 별도 지시를 따른다.
