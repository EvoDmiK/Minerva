### RG-202 — HippoRAG 스타일의 근거 검색 및 그래프 연관 검색 도입

- [ ] 착수 대기 — 신규 작업 등록 (2026-10-07)
- **우선순위**: 4 — 검색 기반과 평가 자료를 확인한 뒤 단계적으로 개편.
- **목적·배경**: 단순 이름 조회를 넘어 여러 문서에 흩어진 관련 사실과 근거를 함께 찾는다. 기존 Neo4j 검색·전문/벡터 검색·RRF와 비교해 다단계 근거 검색의 실제 개선을 검증한다.
- **기술 방향**: HippoRAG의 개체·사실 그래프와 Personalized PageRank(PPR) 기반 검색을 참조한다. HippoRAG 2의 passage 연결·fact 선택도 비교하되 1/2의 구성을 혼용해 동일 구현이라 주장하지 않는다. 공식 구현을 그대로 도입할지 기존 Neo4j에 필요한 원리를 구현할지 설계 단계에서 근거와 함께 결정한다. [원 논문](https://arxiv.org/abs/2405.14831), [HippoRAG 2 논문](https://arxiv.org/abs/2502.14802), [공식 저장소](https://github.com/OSU-NLP-Group/HippoRAG)
- **변경 전후 목표**: 기존 순위 병합 중심 경로에 질문 관련 개체·사실을 시작점으로 그래프 연관성을 확산해 근거 passage를 순위화하는 시험 경로를 추가한다. 검색 점수나 그래프 연결만으로 생태 사실을 확정하지 않고 인용 원문으로 답변을 검증한다.
- **범위·구현 단계**:
  1. 실제 TEST의 문헌·청크·관계·출처 수와 활성 전문/벡터 인덱스·임베딩 프로필을 감사한다. 아종 19,879개를 문헌 근거 19,879개로 세지 않는다. 설계 문서에 있는 기능과 실제 실행 가능한 기능을 구분한다.
  2. 제한된 허용 문헌 집합을 고정하고 청크 ID·문서 ID·릴리스·원문 해시를 유지한다. 추출 개체·사실·원문 passage 연결, 중복 병합과 이름 후보 대조를 설계한다. 모델 추출 관계는 검토된 분류·생태 관계와 분리하고 원문으로 추적 가능하게 한다.
  3. 질문의 seed 개체/사실 검색 → 제한된 PPR → passage 순위화 → 출처 필터 및 근거 구성 경로를 구현한다. 동의어 연결 기준, 관계 가중치, 감쇠율, 후보 수·시간·메모리 제한을 명시한다.
  4. 기존 임베딩 설정(Jina 512차원·질문/문서 작업 구분)과 실제 호환성을 확인한다. 다른 임베딩을 시험하면 별도 프로필·인덱스로 관리한다. Neo4j GDS 설치를 전제로 하지 않고 제공 기능과 외부 그래프 계산의 비용을 비교한다.
  5. 고정 자료 재실행의 중복 방지, 문헌 삭제·원문 변경·분류판 변경 시 인덱스 갱신을 지원한다. 활성 릴리스·자료 허용 범위를 통과한 그래프에서만 확산하고 최종 근거에서도 재검사한다.
  6. 기존 검색과 새 검색을 설정으로 선택해 같은 질문·자료로 비교한다. 기능 플래그, 이전 인덱스 보존 및 롤백 절차를 두고 TEST부터 적용한다.
- **예상 변경 위치**: `src/robingraph/retrieval/hybrid.py`, `src/robingraph/retrieval/neo4j_hybrid.py`, 근거 답변·수집 경로, 새 그래프 색인·PPR 모듈, 평가 자료·검색 설계 문서.
- **협업 추천**:
  - **Codex 주 담당**: 기존 저장 구조·검색 계약 분석, 인덱스·PPR·검색 연동·성능 계측·회귀·배포.
  - **Antigravity 조사·독립 평가**: 원 논문/공식 구현 대조, HippoRAG 1/2 선택 근거, 다단계 질문과 정답 근거 작성·검색 품질 평가.
  - **Claude 협업**: 근거 passage와 생성 답변의 일치·인용·불확실성 표현 검토, 단일 질문의 회귀 확인.
  - 에이전트의 현재 설정 모델을 사용하고 실제 실행 모델을 결과에 기록한다.
- **완료 기준·검증 계획**:
  - 최소 50문항(단일 근거·다단계 근거·근거 부족 포함, 다단계 최소 20문항)의 질문·정답 근거를 고정한다. 조정용과 최종 평가용을 분리하고 같은 corpus·top-k·답변 생성 조건에서 기존 검색과 비교한다.
  - Recall@k·MRR 및 필요한 모든 근거를 찾은 질문 비율, 인용 정확성·근거 없는 답변 비율, p50/p95 지연·색인 시간·메모리·모델 사용량을 기록한다. 다단계 근거 검색이 기준선보다 개선되고 단일 근거·자료 없음 회귀 기준을 통과해야 활성화한다. 목표 개선폭과 지연/메모리 상한은 기준선 측정 후 구현 전에 고정한다.
  - 제한 자료·다른 릴리스·삭제된 문헌이 확산 경로나 최종 인용으로 섞이지 않고, 없는 관계를 사실로 출력하지 않는다. 원문 변경 후 오래된 사실과 인용을 제거한다.
  - 실제 NAS TEST DB·API로 검색 비교와 인용 연결을 확인하고 재색인·재실행·롤백을 검증한다. 실험에서 개선이 없으면 미완료/실험 보류로 기록하고 기존 경로를 유지한다.
- **선행 조건·경계**: 충분한 허용 문헌·청크와 실제 임베딩 검색 기반을 먼저 확인한다. RG-301과 통합하는 채팅 검증은 라우팅 계약 확정 후 수행하지만 검색 실험은 독립 착수할 수 있다. 전체 분류 그래프 교체·PROD 활성화·미확인 자료 자동 수집은 포함하지 않는다.
- **결과 기록**: 계획 등록만 완료. 원 논문·공식 구현 방향 확인 외에 색인·성능 평가·DB 변경·배포는 미실행.

### RG-201 — 그래프 관계 탐색 기능 확장

- [x] 자연어 질문별 그래프 답변·NAS TEST 배포·실환경 검증 완료 (2026-10-05)
- **목적**: 자연어로 새의 형질과 관련 종을 질문하면 그래프를 조회해 해당 정보·관계·출처를 바로 답한다.
- **요청 범위 정정**: 생태 탐색 버튼 추가만으로 완료 처리한 이전 해석을 정정한다. 사용자 요구는 ‘왜가리는 무엇을 먹고 사니?’, ‘청둥오리와 비슷한 종은 어떤게 있니?’ 같은 질문에 응답하는 기능이다.
- **범위**: 먹이·서식 환경·활동 시간·외관·같은 속/과 관련 종·같은 먹이/서식 범주 관련 종 질문과 지원 표현 변형. 형질은 EltonTraits·AVONET 등 허용된 직접 자료, 분류 관계는 활성 AviList, 이름 관계는 검토 manifest를 사용한다.
- **완료 기준**: 요청한 두 질문이 자동 모드에서 정확한 대상·주제로 처리되고 정보·후보·출처가 추가 버튼 클릭 없이 표시된다. 자료 없음·여러 후보·가축형·이름/분류판 불일치·별도 비교·연속 질문도 검증한다.
- **결과 (2026-10-05)**:
  - 왜가리 먹이 질문에 물고기 60% 등 자료의 구성비와 출처를 직접 답한다. 전 지역·계절·개체의 식단으로 단정하지 않는다.
  - 청둥오리 관련 종 질문에 고방오리·흰뺨검둥오리 등 같은 속·과 후보를 바로 조회·표시한다. 외형 유사도·계통상 최단 거리 순위로 주장하지 않는다.
  - 명시한 속/과 또는 먹이/서식 환경 기준만 필터한다. 서식지·활동 시간·외관 질문은 해당 자료만 먼저 표시하며 근거가 없으면 답변을 보류한다.
  - 고유 통칭은 연결 종의 ID·개념집합·분류판을 대조하고 이름 출처를 보존한다. 까마귀처럼 여러 후보 및 집오리 같은 가축형은 임의 치환하지 않는다.
  - 질문과 종 필터가 다르면 확인 질문, 아종 직접 형질이 없으면 부모 값을 대신 쓰지 않음. 명시적 문헌·관찰 경로 유지.
  - 한국어 이름 우선·허용 영어 이름 대체, 후보 비교는 새 말풍선에 두 종 설명·카드 제공. 기존 버튼은 보조 경로로 유지.
  - Python 524건 중 492건 성공·32건 제외, 프런트엔드 121건 전부 성공. 실제 NAS 자연어 요청 10개 및 Chromium 320·390·1280px에서 두 요청·직접 후보·별도 비교·연속 질문·활동 시간·먹이 범주 필터를 검증했다.
  - GPT-6.1-sol UI·테스트, GPT-6-sol 대상/출처 정책 독립 검토, Codex 질문 처리·API·근거 구성·통합·배포·실환경 검증. graphify 갱신 완료.

## 관리 기준

- 새 작업은 이 카테고리의 다음 ID로 등록하고 전체 백로그 현황표와 링크를 함께 갱신한다.
- 상세는 이 파일에서 관리하고, 구현·검증·배포 원문은 같은 폴더의 개별 작업기록에 보존한다.
- 여러 카테고리에 걸친 작업은 주된 변경 분야에 원문 하나만 두고 관련 카테고리에서 링크로 연결한다.
- 기존 파일명·옛 작업 ID·커밋·테스트·검증 결과는 보존한다.
