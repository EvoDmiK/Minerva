## 요약

- **배경 및 목적**: 기존의 조류 검색(단일 종 사실 조회, 이름 해소, 유사종 비교 등)을 기반으로, Neo4j 그래프의 분류학적 계층 구조와 AVONET / EltonTraits 생태 형질 데이터를 활용하여 두 종 간의 관계나 다중 분류·생태 조건을 자연어로 묻고 답하는 **그래프 관계 기반 질의응답 기능**을 확장 구축하고자 한다.
- **주요 질의 범위 및 유스케이스**:
  1. **두 종 분류 관계 / 공통 상위분류 및 경로**: 두 종 간의 공통 상위 분류군(LCA) 및 분류학적 계층 경로 탐색 (예: 까치와 어치의 분류 관계). *진화적 계통 거리가 아닌 분류학적 계층 경로로 기술.*
  2. **같은 속 종**: 특정 종과 동일한 속(Genus)에 속하는 조류 목록 조회 (예: 직박구리와 같은 속 새).
  3. **국내 기록 + 같은 속**: 같은 속 조건에 국내 야생 출현(reviewed record) 필터를 결합한 조건 검색 (예: 국내 기록된 기러기속 새).
  4. **참새목 중 열매 먹는 새**: 특정 분류군(`Passeriformes`)과 식성 형질 결합 조회 (`Fruit > 0` 형질 보유 또는 주식성 `Frugivore` 분류를 분리하여 엄격 정의, 임의의 `Fruit >= 50%` 기준 배제).
  5. **숲 서식 + 직박구리와 먹이를 공유하는 새**: 특정 서식지(`Forest`)와 기준 종의 식성 범주 교집합 조회.
  6. **청둥오리와 서식지가 겹치면서 먹이가 다른 새**: 서식지 범주 일치 및 식성 상이 조건 결합 조회. *실제 생태적 공존이 아닌 데이터상 서식지 범주 일치 한계 명시.*
- **조류학적 데이터 무결성 원칙 및 한계 명시**:
  - **일반 과실식 vs 특정 식물 열매 공유 구별**: EltonTraits/AVONET 기반의 일반 과실식(Frugivory) 형질 공유는 정직하게 제공하되, "산수유 열매를 함께 먹는 새"와 같이 특정 식물 종 열매의 실제 섭식 공유는 원천 데이터에 개별 식물-조류 상호작용 데이터가 없으면 **임의 추정/환각하지 않고 반드시 "자료 부족(출처 미확보)"으로 안내**한다.

## 1. 작업 배경 및 문제 분석

### 1) 발생 배경 및 요구사항
- RobinGraph는 Neo4j에 조류 분류 체계(Order, Family, Genus, Species)와 AVONET / EltonTraits 생태 형질(Habitat, Diet, Activity cycle) 데이터를 보유하고 있다.
- 기존의 조류 검색(단일 종 사실 조회, 이름 해소, 유사종 추천 등)을 확장하여, 두 종 간의 관계나 특정 생태·분류학적 교집합 조건을 묻는 자연어 질의를 지원하고자 한다:
  - "까치와 어치는 어떤 관계야?" (공통 상위분류 및 분류학적 계층 경로)
  - "직박구리와 같은 속 새들은 뭐가 있어?" (동일 속 종 집합)
  - "국내에 기록된 기러기속 새들은?" (속 분류 + 국내 출현 기록 복합 필터)
  - "참새목 중에서 열매를 먹는 새는?" (목 분류 + 식성 형질: `Fruit > 0` 또는 `Frugivore` 주식성)
  - "숲에 살면서 직박구리와 먹이를 공유하는 새는?" (서식지 + 특정 종과의 먹이 범주 교집합)
  - "청둥오리와 서식지가 겹치면서 먹이가 다른 새는?" (서식지 범주 일치 + 식성 상이 교집합)

### 2) 기술적 검토 및 데이터 한계선 정의
- **분류학적 계층 경로(Taxonomic Hierarchy Path)**:
  - 실제 Neo4j 그래프는 `(:Taxon)-[:PARENT_OF*]->(:Taxon|Species)` 계층 관계를 사용한다. (존재하지 않는 `BELONGS_TO` 관계 사용 금지).
  - 공통 상위 분류군(LCA) 및 상위 분류 계층 경로는 **진화적 계통 거리(evolutionary phylogenetic distance)로 표현하지 않고, 분류학적 계층 경로(taxonomic hierarchy path)로 정직하게 기술**한다.
- **생태 형질 정의**:
  - 임의의 `Fruit >= 50%` 기준을 배제하고, `Fruit > 0`(과실 섭식 형질 보유)과 `Frugivore`(과실식이 주 식성인 범주)를 명확히 분리하여 쿼리한다.
- **엄격한 조류학적 데이터 원칙 (AGENTS.md 규칙)**:
  - **일반 과실식 vs 특정 식물 열매 공유 구별**: EltonTraits는 조류의 '과실류 섭식 비율' 데이터만 제공하며, "직박구리가 먹는 산수유나 감 열매를 같이 먹는 새"처럼 특정 식물 종에 대한 섭식 상호작용 네트워크는 포함하지 않는다. 따라서 특정 식물 열매 공유에 대한 질문이 들어올 경우 **임의 추정/환각하지 않고 "특정 식물 열매 공유에 대한 원천 자료 부족"으로 명확히 안내**한다.
  - **서식지 범주 일치 한계**: "청둥오리와 서식지가 겹치는 새" 질의는 원천 데이터의 서식지 범주(`Habitat: Wetland` 등)가 일치함을 의미할 뿐, 동일 시공간에서의 실제 생태적 공존을 입증하는 것은 아니라는 한계를 명시한다.
- **대화 문맥 범위 제한**:
  - 이번 요구사항의 최초 구현 범위는 **독립 자연어 질문별 처리(single-turn)**이며, 세션/대화 상태 기억(조건 이어가기 문맥 유지)은 이번 완료 목표 범위에서 제외하고 향후 후속 과제로 둔다.

1. **분류 관계 질의**: 두 종 입력 -> LCA 탐색 -> "까치와 어치는 모두 참새목(Passeriformes) 까마귀과(Corvidae)에 속하며, 속 단계(까치속 Pica, 어치속 Garrulus)에서 분기합니다." 형식의 분류학적 계층 경로 답변.
2. **동일 속 조회**: 종 입력 -> 속(Genus) 조회 -> 속 내 타 종 목록 반환.
3. **국내 기록 + 동일 속**: 국내 출현 필터(`korea_occurrence: true` 또는 reviewed species list) 적용.
4. **분류군 + 식성 질의**: 상위 분류군 필터(`Passeriformes`) + 식성 조건(`Fruit > 0` 또는 `Frugivore`) 분리 적용.
5. **서식지 + 먹이 공유 질의**: 서식지(`Forest`) + 기준 종(`Hypsipetes amaurotis`)의 주요 먹이 범주 매칭.
6. **서식지 일치 + 먹이 상이 질의**: 서식지 범주(`Wetland`) 일치 + 주 식성 상이 종 목록 조회 (서식지 범주 일치 한계 안내 포함).

1. **원천 데이터 한계 및 특정 식물 상호작용 부재**:
   - EltonTraits는 거시 식성 범주 비율 데이터만 제공하므로, 구체적인 특정 식물 종 열매(산수유, 찔레 등) 섭식 공유는 "자료 부족"으로 안내하도록 가드 확립.
2. **서식지 공존의 데이터 한계**:
   - 서식지 범주 일치는 통계적 서식 환경 분류의 일치일 뿐 실제 야생 시공간의 공존을 의미하지 않음을 명시.
3. **대화 상태 기억(조건 이어가기) 후속 분리**:
   - 단일 질문별 독립 처리를 이번 완료 범위로 하며, "그 중에서 국내에 사는 새는?"과 같은 다중 턴 대화 상태 유지는 이번 구현 범위에서 제외하고 향후 후속 과제로 분리함.
4. **후속 과제 연결**:
