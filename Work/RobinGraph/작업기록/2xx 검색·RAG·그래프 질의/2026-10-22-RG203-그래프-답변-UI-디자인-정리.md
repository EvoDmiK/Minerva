## 1. 작업 배경 및 문제 분석

### 발생 현상 / 요구사항
1. **긴 종 목록 표출 시 화면 과밀**:
   - 동일 속 20종, 참새목 열매 20종 등 다수의 조류 카드가 한 번에 말풍선에 렌더링될 경우, 전체 채팅 인터페이스의 스크롤이 지나치게 길어짐.
   - 모바일(390px) 화면에서 다른 메시지나 입력창 확인이 불편해지는 사용성 저하 발생.
2. **시각적 계층 및 디자인 정돈 필요**:
   - 분류학적 계층 경로(`Anas` 속 계층 구조)와 출처 링크, 프로필 열기 버튼 간의 시각적 구분이 보다 직관적으로 정돈될 필요가 있음.
   - "특정 식물 열매 공유 자료 부족" 및 "서식 범주 일치 한계 안내" 메시지가 본문과 자연스럽게 구분되어 신뢰감을 주도록 스타일 보완 요구.

### 원인 분석 및 설계 검토
- 기존 구현은 API가 반환한 `items` 배열을 순회하며 단순 반복 렌더링하는 초기 프로토타입 형태였음.
- JavaScript 차원에서 기본 노출 한도(예: 6개 등)를 두고 초과 항목을 접을 수 있는 접기/펼치기 상태 토글이 필요함.
- 디자인 전담(Antigravity)이 전용 CSS 클래스를 분리하여 말풍선 내부의 여백, 폰트, 버튼 호버 스타일을 일관되게 정립하도록 구조를 분리함.

## 2. 해결 방안 및 설계

1. **JavaScript 목록 접기/펼치기 구조 (`chat.js`)**:
   - `ChatGraphResult` 응답 렌더링 시 반환된 종 목록 개수를 확인.
   - 일정 개수 초과 시 기본 항목만 먼저 표시하고, 하단에 잔여 개수를 안내하는 접기/더보기 토글 버튼(`[더보기 N개 더]`, `[접기]`) 배치.
   - 각 종 버튼 클릭 시 기존의 `profile` 패널 조회 연동은 그대로 유지.
2. **CSS 전용 스타일시트 고도화 (`chat.css`)**:
   - `.graph-query-answer` 컨테이너 내부의 구조화된 클래스 부여:
     - `.graph-query-path`: 분류학적 계층 경로 칩/배지 스타일
     - `.graph-query-species-list`: 종 목록 래퍼 (그리드/플렉스 정렬)
     - `.graph-query-toggle-btn`: 접기/펼치기 토글 버튼 스타일
     - `.graph-query-limitation`: 자료 부족 및 한계 안내 박스 스타일
   - `reducedMotion: 'reduce'` 미디어 쿼리 준수 및 터치 영역(최소 44px) 고려.
