## 배경과 목표

까치 카드에 생태 설명과 LC 배지가 추가되어도 먹이 구성·먹이 활동 위치가 빈 박스로 남았다. 앞선 작업은 까치의 정성 설명과 표본 체중을 추가했지만 두 비율의 원본 유무와 전체 종의 연결 문제까지 해결하지 못했다. 사용자는 Ponytail의 Claude와 GPT-6.1-sol 협업, 까치에 한정하지 않는 공통 처리, Antigravity의 신뢰할 수 있는 IUCN 출처 조사를 요청했다. 필요하면 n8n을 수집에 사용해도 된다고 허용했다.

목표는 저장 누락·옛 학명 매핑 보류·원본 필드 부재·분류 개념 차이를 구분하고, 입증 가능한 연결만 복구하여 실제 화면에서 확인하는 것이다. 비율이 없는 종에 다른 종의 비율을 복사하지 않는다.

## 원인과 실제 감사 근거

[전체 종 감사](https://github.com/EvoDmiK/RobinGraph/blob/main/docs/verification/2026-10-09-all-species-trait-audit.md)와 [집계 JSON](https://github.com/EvoDmiK/RobinGraph/blob/main/docs/verification/2026-10-09-all-species-trait-audit-summary.json)에 상세 근거가 있다.

- AviList 11,131종이 활성 TEST PostgreSQL 및 Neo4j에 모두 저장되어 있었다. 원본과 DB의 양방향 종 ID 누락·학명 불일치·중복은 0이었다.
- EltonTraits 9,993개 유효 프로필, AVONET 11,009개 원기록도 누락 0이었다. 이미 연결된 형질 claim은 각각 46,512개·128,331개이며 원본값 불일치 0이었다.
- 현재 학명과 정확히 같지 않은 원본은 Elton 2,241개·AVONET 1,130개 후보로 남아 있었다. 후보 `profile_json`의 정규화 값은 원본과 모두 같았고 누락·중복·값 불일치 0이었다. PostgreSQL 원기록에는 주로 식별 메타데이터가 있고 전체 형질값은 graph claim/후보 JSON에 있다는 차이도 확인했다.
- 기존 비율 차트의 원자료 연결 범위는 7,752종이었다. 현재 학명의 원본행이 없다는 것이 생물학적 자료 자체가 전혀 없다는 뜻은 아니다. 직박구리·대백로 등은 옛 이름으로 원자료에 존재했다.
- Pica serica는 두 원본에 독립된 행이 없고 이번 개념 교차표에도 승인 연결이 없다. Pica pica의 비율을 까치로 복사할 수 없다.
- IUCN 등급 연결은 형질 자료와 별도다. [Antigravity 조사 통합본](https://github.com/EvoDmiK/RobinGraph/blob/main/docs/verification/2026-10-09-iucn-source-review.md)에 현재 목록 연결 7,507종과 미연결 사유, 개별 평가 검증의 한계를 기록했다. 이번에 보전 매핑 기준을 완화하지 않았다.

## 연결 규칙과 변경 내용

[교차표 생성 보고](https://github.com/EvoDmiK/RobinGraph/blob/main/docs/verification/2026-10-09-trait-crosswalk-build.md)에 원본 URL·전체 해시·구조 검사·규칙·사유별 집계를 기록했다.

- AVONET은 원본 Avibase 개념 ID와 현재 AviList 종의 ID가 고유하게 일치할 때만 승인한다.
- EltonTraits는 BL3 행에 한해, 공개 BirdLife–BirdTree 대응표의 양방향 일대일 관계와 AVONET Avibase ID를 거쳐 현재 종 개념이 일치할 때 승인한다.
- 이름 유사도·종소명만으로 고르지 않는다. 일대다/다대일·충돌·IOC27 분류 기준 미확인은 승인에서 제외한다.
- 동일 학명이라도 개념 일치가 입증되지 않은 기존 값은 `needs_review`로 출처에 설명한다. 모든 차이를 분할 전 자료라고 단정하지 않는다.
- 최종 교차표의 이름 변경 승인 행은 Elton 1,868개·AVONET 703개다. 이는 원자료 행 단위이며 서로 다른 종 2,571개라는 뜻은 아니다.

조회 복구는 기존 후보값과 활성 원기록을 읽어 적용한다. 대상 종/개념집합/분류 릴리스, 원본 고정 해시, 활성 자료 릴리스, 후보 수집 run, 허용 정책과 원기록 식별자를 함께 검증한다. 패키지에 교차표를 포함하고 정적 인덱스를 캐시한다. DB의 후보나 graph 관계를 영구 갱신하지 않는다. 원본이 바뀌면 현재 고정 스냅샷 기준의 승인을 자동 재사용하지 않는다.

카드에서는 비율이 없을 때 같은 크기의 두 영역 안에 출처가 있는 먹이 유형/생태 범주 또는 주 생활 방식을 표시하고 `비율 자료 없음`을 명시한다. 주 생활 방식에서 지면·수관 등의 먹이층이나 비율을 추정하지 않는다. 범주값도 없으면 자료 없음 상태를 유지한다. 정성 대체 영역에 별도 출처를 중복 추가하지 않고 기존 답변 출처 토글을 사용한다.

### 알려진 한계

- 까치의 수치 비율은 새로 확보하지 못했다. 기존 연구·문헌의 정성 정보와 표본 체중을 사용하며 비율 부재를 유지한다.
- 읽기 시점 복구이므로 후보 상태/graph 관계 자체는 바뀌지 않는다. graph 전용 질의·순위 산정의 자료 범위까지 모두 확장했다고 주장하지 않는다.

## 상세 해설 — 처음 읽는 사람을 위한 용어와 저장 구조

이 작업에서 말하는 ‘형질’은 체중, 부리·날개 길이, 먹이 유형, 먹이 구성, 먹이 활동 위치 같은 종의 특성이다. ‘프로필’은 한 자료원의 한 원본 행에 묶인 여러 형질이다. 따라서 프로필 1개와 형질 1개, 생물학적 종 1개는 서로 다른 집계 단위다.

| 용어 | 이 작업에서의 의미 |
|---|---|
| AviList | 앱이 현재 종과 분류 계통을 식별하는 기준 목록. 모든 생태 수치의 원천은 아님 |
| EltonTraits | 먹이·활동 위치 비율과 체중 등 생태 형질의 원자료 |
| AVONET | 체형 측정값과 생태 범주 등의 원자료 |
| 종 개념 | 이름이 가리키는 생물 집단의 범위. 이름이 같아도 분할·통합에 따라 범위가 다를 수 있음 |
| 교차표 / crosswalk | 서로 다른 분류 체계의 원본 행과 현재 종을 어떤 근거로 연결했는지 기록한 표 |
| TraitClaim | 이미 현재 종에 연결하여 저장한 개별 형질 주장 |
| TaxonMappingCandidate | 현재 종 연결을 확정하지 못해 보류한 원자료 후보 |
| source_record | 원자료의 식별자·행·출처·수집 이력을 확인하는 PostgreSQL 기록 |
| 읽기 시점 복구 | DB의 원본과 관계를 수정하지 않고 조회 응답을 만들 때 승인된 후보를 결합하는 방식 |

원본 파일 → 수집·정규화 → 현재 종에 연결되는 형질 claim 또는 연결 보류 후보 → 공통 조회 함수 → 종 프로필 → 카드라는 순서로 데이터가 이동한다. PostgreSQL 원기록에는 주로 식별 메타데이터가 있고, 실제 정규화 형질값은 연결된 graph claim 또는 후보의 `profile_json`에 있었다. 원기록 테이블 하나만 보고 “숫자가 저장되지 않았다”고 판단할 수 없는 구조다.

기존 조회는 이미 현재 종에 연결된 값을 읽었다. 옛 학명으로 온 자료는 후보에 정상 저장돼도 연결이 보류되면 카드에 도달하지 않았다. 이번 수정은 원본을 다시 수집하는 대신, 검증된 교차표와 활성 원기록을 대조하여 그 보류 후보를 읽는 경로를 추가했다.

## 상세 해설 — 연결 승인과 보류의 기준

### 왜 학명만으로 연결하지 않았는가

같은 새가 속 이동으로 이름만 바뀌는 경우와, 종이 나뉘어 예전 이름의 범위가 달라지는 경우는 다르다. 앞의 경우에는 기존 측정값을 현재 종에 연결할 수 있지만, 뒤의 경우에는 어느 집단의 값인지 추가 근거가 필요하다. 이름 유사도나 종소명만 비교하면 두 경우가 섞인다.

AVONET은 Avibase.ID1과 AviList의 AvibaseID가 고유하게 일치하는지 확인했다. EltonTraits는 BL3 분류 행에 대해 BirdTree 이름 → 공개 BirdLife–BirdTree 일대일 대응 → AVONET의 BirdLife 종과 Avibase ID → 현재 AviList 종 순서로 확인했다. 양방향 고유성이 필요하며 복수 원본이 같은 대상과 충돌하면 자동 승인하지 않는다.

Elton 원저자 메타데이터를 추가 확인하여 조류 분류가 Jetz 2012와 같고 BirdLife v3(2010년 6월)를 주로 따른다는 근거를 보강했다. 초안의 BL3 시점 미확인 한계는 이 확인으로 해소했다. IOC27 행은 여전히 별도 검토 대상이며 이번 자동 승인 수는 0이다.

### 최종 교차표의 집계

| 자료 | 원본 프로필 | 승인 전체 | 같은 이름 승인 | 바뀐 이름 승인 | 검토 필요 | 대상 미확정 |
|---|---:|---:|---:|---:|---:|---:|
| AVONET | 11,009 | 10,037 | 9,334 | 703 | 545 | 427 |
| EltonTraits | 9,993 | 8,633 | 6,765 | 1,868 | 1,001 | 359 |

‘승인 전체’는 교차표의 판정 결과이고 ‘바뀐 이름 승인’이 이번 후보 복구의 핵심 범위다. 703 + 1,868 = 2,571은 **자료원별 프로필 수**다. 한 종이 두 자료원에 모두 있을 수 있으므로 서로 다른 2,571종이라고 표현하면 안 된다.

기존의 정확 학명 연결 수와 교차표의 같은 이름 승인 수가 다른 이유는, 이번 교차표가 이름뿐 아니라 종 개념의 일치까지 요구하기 때문이다. 이미 표시되던 값을 모두 새로 검증 완료 처리한 것이 아니다. `needs_review`는 후보 또는 기존 연결의 개념 검토가 필요하다는 뜻이고, `unresolved`는 이 규칙으로 대상을 정하지 못했다는 뜻이다.

| 대표 사례 | 원자료 이름 | 현재 이름 | 판단 |
|---|---|---|---|
| 직박구리 | Ixos amaurotis | Hypsipetes amaurotis | 개념 대응 확인, 옛 이름의 Elton 형질 복구 |
| 대백로 | Casmerodius albus | Ardea alba | 개념 대응 확인, 옛 이름의 Elton 형질 복구 |

| 새매 | Accipiter nisus | Accipiter nisus | 기존 정확 연결 유지, 신규 복구 사례로 집계하지 않음 |

## 상세 구현 — 공통 조회에서 무엇을 검증하는가

복구는 `read_traits` 공통 경로에 연결됐다. 종마다 예외문을 추가하지 않고 현재 종과 승인된 원본 행의 관계로 동작한다.

1. 패키지에 포함된 교차표의 출처·고유성·고정 버전을 확인하고 정적 인덱스를 프로세스당 한 번 캐시한다.
2. 현재 종의 ID·학명·Avibase ID와 분류 개념집합·릴리스·스냅샷이 승인 대상과 일치하는지 확인한다.
3. 허용된 활성 자료원과 성공한 수집 run에 속하는 후보인지 확인한다. 후보의 원본 이름·기록·정책·미해결 상태·last_seen_run도 대조한다.
4. 후보에 EvidenceUnit 또는 원기록 graph edge가 없는 구조를 고려해, 같은 활성 릴리스의 PostgreSQL 정본 source_record와 원본 해시·행/SpecID/URI·수집 이력을 대조한다.
5. 후보 JSON 크기, 신원과 필드 구조, 허용 단위, 유한한 양수 측정값, 비율 합계 허용 범위 99–101, 원본 추정 플래그 등을 검사한다. 숫자 0과 불리언 false를 혼동하지 않도록 검증한다.
6. 같은 자료원의 같은 형질이 이미 있으면 기존 값을 우선하고 중복으로 넣지 않는다. 잘못된 후보 하나 때문에 정상적인 다른 자료원이나 기존 값까지 지우지 않는다.
7. 원자료명·대상명·방법·사유를 `taxonomy_alignment`에 남기고 읽기 시점 복구였다는 provenance를 함께 반환한다.

원자료 증거는 `evidence_kind: stored_source_record`, 복구 여부는 `mapping_provenance.read_time_recovery: true`로 구분한다. 출처 URL·인용·라이선스와 자료/교차표/분류 해시를 추적할 수 있게 한다. 깨진 교차표나 누락된 근거를 검증 완료로 취급하지 않는다.

PostgreSQL 검증은 읽기 전용 트랜잭션을 사용하고 Neo4j 조회도 고정 MATCH 읽기다. 조회 중 원본 다운로드·수집 API·n8n을 호출하지 않는다. 다만 후보가 개별 전자서명된 것은 아니다. 이번 전수 감사로 저장값과 고정 원본의 일치를 확인하고, 실행 시에는 출처 및 구조 조건을 검증하는 방식이다.

### 성능 관측의 의미

대표 실 DB 호출의 1회 관측은 직박구리 180.49ms, 대백로 84.21ms, Tachyspiza badia 180.95ms, Pica serica 35.83ms, Pica pica 67.04ms, 청둥오리 41.89ms였다. **최종 추정 플래그 보완 이전의 함수 단위 관측**이며, 채팅 전체 응답 시간·최종 배포 성능·p95를 뜻하지 않는다.

복구가 필요한 경우 추가 조회는 Neo4j 1회와 PostgreSQL 1–2회였고 기존 정확 연결만 사용하는 경우 추가 조회는 0회였다. 정적 인덱스 구축 380.54ms는 파일 읽기·JSON 파싱을 포함한 전체 첫 요청 시간이 아니다. 일괄 rows 재현 1,103.21ms 역시 DB 네트워크 시간을 제외하므로 서비스 지연으로 인용하지 않는다.

## 상세 구현 — 숫자의 출처와 추정 여부

종 개념 연결이 승인됐다는 사실은 모든 숫자가 그 종을 직접 측정한 관측값이라는 뜻이 아니다. Elton의 식이·활동 비율은 문헌 설명을 표준화한 반정량적 추정 비율이며, 개별 원본의 확실성 코드를 추가로 보존해야 한다.

## 상세 화면 동작 — 까치와 다른 종에 공통으로 적용

| 원자료 상태 | 먹이 구성 영역 | 먹이 활동 위치 영역 |
|---|---|---|
| 비율 있음 | 원비율 도넛 차트 | 원비율 도넛 차트 |
| 비율 없고 정성 자료 있음 | 먹이 유형 또는 먹이 생태 범주와 ‘비율 자료 없음’ | 주 생활 방식과 ‘비율 자료 없음’ |
| 정성 자료도 없음 | ‘기록된 자료 없음’ | ‘기록된 자료 없음’ |
| 한쪽에만 비율 있음 | 해당 영역의 상태에 따라 독립 표시 | 해당 영역의 상태에 따라 독립 표시 |

두 영역은 기존 120×100 크기와 2열 배치를 유지한다. 긴 값은 두 줄로 제한하고 전체 정보는 기존 상세 행과 출처에서 확인한다. 정성 대체 영역에는 새 클릭 요소를 넣지 않아 카드 드래그 동작을 방해하지 않도록 했다.

‘나무와 전선에 앉기’ 같은 주 생활 방식은 먹이를 찾는 층별 비율과 다른 정보다. 이를 수관 100%처럼 변환하지 않는다. 까치는 현재 문헌 보완 4형질과 정성 내용을 표시하지만 수치 비율은 여전히 미확보다. 체중 220.64g 역시 앞선 문헌 보완의 표본 평균이며 이번에 종 전체 평균으로 새 산출한 수치가 아니다.

출처는 기존 ‘답변 출처 보기’에 모은다. 연결 근거는 알려진 상태와 사유만 사람에게 읽히는 문장으로 표시하고 원자료 학명은 길이를 제한해 textContent로 넣는다. 미확인 코드를 그대로 노출하거나 HTML로 삽입하지 않는다. 기존 출처 항목을 같은 카드 안에 중복 생성하지 않는다.

### 교차표 재현 절차

저장소의 구현 버전과 고정 설정을 맞춘 뒤 아래 순서로 재현할 수 있다. RAW_DIR는 사용자가 정하는 별도 원본 보관 디렉터리다. 과거 세션의 /tmp 경로가 영구 보존된다고 가정하지 않는다.

```sh
python3 scripts/build_trait_crosswalk.py --fetch RAW_DIR
python3 scripts/build_trait_crosswalk.py --raw-dir RAW_DIR --check
```

첫 명령은 고정 출처 파일을 가져와 확인하고, 두 번째는 생성 결과와 커밋된 교차표의 바이트 일치를 검사한다. 원본 해시·필수 시트·구조가 다르면 중단하며 새 파일을 기존 승인 결과와 같은 것으로 취급하지 않는다. 실제 서버 검증은 활성 TEST 설정과 읽기 권한이 별도로 필요하다. 위 명령만으로 DB 복구나 배포가 실행되지는 않는다.
