# 그래프 관계 탐색·통칭·가축형 확대 조사와 NAS TEST 배포

## 작업 결과

독립 작업 RG-501 통칭·가축형 조사를 구현하고 NAS TEST에 배포했다. 이 결과는 RG-201의 완료 근거가 아니다. RG-401~RG-404·RG-502는 같은 날 별도로 구현·검증되었고, RG-201은 2026-10-05 생태 관계 탐색으로 별도 완료되었다. 처음에는 비둘기·까마귀·닭·집오리의 네 예시를 중심으로 8개 관계만 구현했으나, 사용자 지적에 따라 다른 조류의 통칭·별칭·가축형·닭 품종까지 조사 범위를 확대했다.

| 항목 | 최종 검토 규모 |
|---|---:|
| 이름 엔티티 | 33개 |
| 고유 검색어 | 70개 |
| 출처 검토 관계 | 47개 |
| 고유 대상 종 | 37개 |

전체 조류 또는 모든 품종을 망라한 목록은 아니다. 넓은 통칭에는 출처로 확인한 일부 후보를 표시하고, 불확실한 연결은 보류했다.

## 사용자에게 보이는 동작

- 등록된 통칭·가축형 이름을 질문하면 설명창에서 관계 설명·후보·출처를 먼저 안내한다.
- 후보의 **관련 야생종 자료 보기**를 선택하면 해당 종의 설명·카드를 확인한다.
- 종 설명에서 **통칭·가축형 관계 알아보기**를 펼쳐 역방향으로 연결된 이름을 탐색한다.
- 가축형과 야생종을 같은 종 정보로 합치지 않는다. 관련 야생종의 사진·체중·생태·보전 등급을 가축형이나 품종의 정보로 대입하지 않는다.
- 여러 종을 뜻하는 이름은 후보를 분리한다. 후보 누락이나 출처·활성 분류판 불일치는 임의 선택 대신 답변 유보로 처리한다.
- 일반 학명 조회와 직접 profile·lineage 조회, 명시적인 관찰·근거 질문의 기존 경로를 유지한다.

## 확대 조사 내용

| 구분 | 조사·반영 예 |
|---|---|
| 기존 예시 | 비둘기·집비둘기, 까마귀, 닭, 집오리 |
| 주요 가축형 | 거위, 칠면조, 메추리, 뿔닭, 카나리아, 사육염주비둘기, 십자매 |
| 닭 품종·집단 이름 | 오골계, 백봉오골계, 연산오계, 토종닭, 재래닭 |
| 통칭·별칭 | 학·단정학, 공작, 백조, 백로, 앵무새·앵무, 잉꼬, 코커틸, 금사조·금사작, 뱁새, 산비둘기, 종달새, 장끼·까투리, 부엉이, 할미새, 딱따구리 |

거위와 집오리는 확인된 서로 다른 기원 후보를 유지했다. 단순 반려 사육을 가축화 관계로 판정하지 않았다. 닭 품종은 품종→가축 닭→야생 기원이라는 근거 연결을 설명하며 별도 종·아종 지위를 임의로 부여하지 않았다.

문조·금화조·기러기 등은 출처 또는 분류 경계 추가 확인을 위해 보류했다. 색상이나 상표 이름만으로 종을 추정하지 않았다. 개별 연결·출처·보류 사유의 최종 목록은 아래 저장소 문서를 기준으로 한다.

## 구현과 자료 검증

- 별도 `BirdNameUsage` 노드를 활성 AviList `BirdTaxon`에 `NAME_RELATION`으로 연결했다.
- PostgreSQL에는 검토 manifest·출처·불변 release/record·활성 상태를 기록하고, Neo4j 관계와 대조한다.
- API: `GET /v1/taxa/name-relations?name=...`. 등록 이름의 채팅 응답은 `disposition=clarify`, `result.kind=name_relations`이다.
- 적재기 `scripts/load_name_relations.py`는 기본 dry-run이며 `--apply`로만 적용한다. API 시작 시 자동 DB 쓰기는 하지 않는다.
- 고정 AviList 2025b 원본에서 37개 대상 모두 정확히 하나의 species 행으로 확인했다. 원본 SHA-256: `3b08845b54b8ab53908aee84d05b0fd8df765e9e01dc655599ca304d9f132411`.
- 기존 관계 조회 25개·검토 목록 24개 제한을 확대 자료에 맞게 수정했다. 운영상 검토 목록 상한은 5,000개이며 조회는 검토 manifest 크기를 기준으로 누락·초과 관계를 탐지한다.
- 등록된 가축형 학명과 공백을 포함하는 이름의 자연어 질문도 관계 안내로 처리하도록 수정했다.
- graphify AST 갱신을 완료했다.

## 상세 보완 — 2026-10-05

### 이름 관계와 분류 관계의 구분

| 예 | 표시 원칙 |
|---|---|
| 한 종으로 검토된 통칭 | 연결된 종의 설명·카드 버튼을 준비 |
| 여러 종을 뜻하는 통칭 | 검토 후보를 나누고 사용자가 선택 |
| 가축형·품종 | 관련 야생종 자료임을 표시하고 선택 후 제공 |
| 아종 | 이름의 모양 대신 실제 부모·아종 관계를 조회 |

이름이 검색되었다고 이름 엔티티 자체에 야생종의 체중·사진·보전 등급을 붙이지 않는다. ‘닭 → 적색야계’처럼 검토한 관계는 관련 야생종 자료로 가는 연결이며 모든 가축 개체·품종을 그 야생종과 동일한 정보로 설명하는 계약이 아니다.

### 적재와 조회의 책임

검토 manifest는 검색어·관계 설명·대상 종·출처를 명시한다. 적재기는 대상이 활성 분류판에서 정확히 한 종인지 확인하고 PostgreSQL 검토 릴리스와 Neo4j 투영을 맞춘다. API는 조회만 수행하며 시작할 때 자동 적재하지 않는다.

수집·검토 단계에서 보류한 이름은 실패를 숨기기 위한 대체 이름으로 등록하지 않는다. 후보가 누락되거나 분류판이 달라지면 결과를 임의 축소해서 표시하지 않고 조회를 거부한다. 새 자료 적용은 별도 검토·적재·활성화 작업이다.

### 검토 규모와 현재 화면 계약

33개 엔티티·70개 검색어·47개 관계·37개 종은 이 릴리스의 검토 규모이며 전체 새 이름의 커버리지가 아니다. 단일 통칭의 answer와 여러 후보·가축형의 clarify는 이후 아종·통칭 카드 연결에서 보완된 현재 화면 계약이다. 원문의 모든 이름 clarify는 초기 구현 시점의 동작이다.
