# RG-013 Jev 의도분석 적합성 검증

## 결론

**Jev는 RG-013의 선택형 의도·세부 주제 분류에 조건부로 적합하다. 다만 한국어 성능과 기존 Jina 라우터 대비 개선은 실제 API 평가 전에는 확정할 수 없다.**

Jev에 의도 판단을 맡기되, 종 이름·날짜·장소 추출과 활성 분류판 해소, 아종 목록 조회 연결은 별도로 구현·검증해야 한다. Jina 문헌 임베딩·Neo4j 하이브리드 검색·기존 답변 생성기를 교체하는 제안이 아니다. 큰 생성 LLM보다 빠르다는 소개는 현재 임베딩+코사인 라우터보다 우수하다는 증거가 아니다.

## 요청 배경과 검증 범위

- 요청: [[RobinGraph 작업 백로그#RG-013 — Jev System One API를 이용한 질문 의도 분석|RG-013]]에 Jev를 쓰는 것이 적합한지 관련 문서와 현 코드를 대조한다.
- 공식 TypeSafe API·모델·한국어/CJK 지원·confidence·알려진 한계·후보 값 추출·함수 호출·SDK 재시도 문서를 HTTP GET으로 확인했다.
- RobinGraph 원격 dev를 `04389fc3c9780c3a03e104f90e42812c5e0633d1`에 고정하고 semantic_router.py, app.py, species_questions.py 등 관련 코드를 읽었다.
- **실제 실행:** 원격 문서/코드 HTTP 조회, 기존 순수 parser의 제한된 실행, AST 기반 코드 호출 경로 확인.
- **미실행:** 인증된 Jev 추론·계정 모델 조회, 한국어 벤치마크, NAS API/DB 검증, 전체 제품 테스트, 구현·Git 변경·배포. 브라우저 제어 없음.
- 백로그 상태·우선순위는 변경하지 않았다. 이 조사는 RG-013 구현 착수가 아니다.

## 공식 문서에서 확인한 적합성과 한계

### 선택형 판단은 용도에 부합

`POST https://api.typesafe.ai/v1/systemone`에 `state/model/questions`를 보내며 Choice는 정의한 선택지와 전체 확률 분포·confidence를 반환한다. Noul은 yes 확률, Score는 순서 있는 기준의 점수다. 공식 문서가 intent routing 및 정해진 함수·인자 선택을 실제 패턴으로 소개한다.

여러 질문은 동일 state를 독립적으로 평가한다. 한 요청에서 상위 의도 결과가 세부 의도 질문에 자동 전달되지는 않는다. 상위·세부 분류를 병렬로 쓰면 코드에서 일관성을 검사하고, 결과 의존성이 필요하면 두 단계로 나눈다.

### 한국어 품질은 미확정

모델 문서는 영어가 주 학습 언어이자 정확도가 가장 높은 언어이며, CJK 등 다른 언어는 처리하나 동일한 품질은 아니라고 밝힌다. 확보한 문서에는 RobinGraph 한국어 조류 질문 성능을 입증하는 수치가 없다. 고객별 fine-tuning/LoRA 적응도 제공하지 않는다고 안내한다. 도메인 적응은 state·instructions·criteria 구성과 판단 분해로 수행한다.

### 자유형 추출과 계산은 분리

Jev는 자유형 텍스트 생성 모델이 아니다. 후보 값 추출 cookbook은 코드가 후보 구간을 찾고 Jev가 후보 중 하나 또는 none을 선택한다. Choice 최대 선택지는 255개이므로 모든 조류 이름을 한 번에 열거할 수 없다. 이름 후보의 재현율, 동명이름·통칭·학명·분류판 연결은 별도 검증 대상이다. 날짜 성분 추출은 제한된 선택지로 가능하지만 날짜 비교·범위 계산은 코드가 처리한다.

### confidence는 정확도 보증이 아님

Choice의 공식식은 `(p_max - 1/n) / (1 - 1/n)`이다. 분포의 최고 확률을 재표현한 값으로 기존 cosine score나 실측 정답률과 동일하지 않다. 설명용 계산에서 선택지 5개·최고 확률 0.8은 confidence 0.75다. 이는 실제 API 응답이 아니다. 차순위와의 분리 정도는 별도 측정할 수 있다. Noul 응답에는 별도 confidence 필드가 없다.

한국어 평가에서 confidence 구간별 실측 정답률과 자동 처리율·자동 처리 오분류율을 함께 확인해야 한다. 기존 cosine 임계값 0.70·margin 0.08을 그대로 가져오지 않는다.

### 공식적으로 알려진 실패 형태

Jev 1.13 한계 문서(검토일 2026-10-02)는 문자 그대로의 해석, 복잡한 간접 추론, 불필요하게 긴 state, 적대적 내용, 모순된 기준, 선택지 순서 영향, 정확한 계산/날짜 비교·생성의 약점을 명시한다. 선택지 순서 교체·한국어 부정 표현·복합 질문·사용자 입력의 라우팅 조작 문구를 평가에 포함한다. 높은 confidence만으로 안전성을 인정하지 않는다.

### 운영 조건

문서상 현재 모델은 `jev-1.13.0`이며 alias는 이동하므로 평가 버전과 실제 응답 model을 기록한다. 입력 100만 tokens당 $0.042·출력 무료라는 표는 공개 문서 가격이며 자체 비용 실측이 아니다. 실제 usage와 재시도 포함 지연으로 평가한다. 401/422와 429/529를 구분하고 전체 라우팅 deadline과 제한된 backoff를 둔다. Python SDK 재시도 총 예산 기본값 30초는 대화 경로에서 별도 조정 대상이다. 고객 데이터로 학습하지 않는다는 안내와 무보존은 다른 약속이며 ZDR은 enterprise 제공으로 안내된다.

## 현재 코드에서 확인한 문제

1. **임베딩 후보 누락:** ChatIntent 타입에는 profile이 있지만 실제 semantic prototype은 taxonomy/observations/evidence 세 개뿐이다. profile·아종 목록 주제는 cosine 후보에 없다.
2. **세부 질문 처리 누락:** 기존 species parser는 먹이·서식 환경·활동·외관·관련종을 지원하지만 아종 목록 주제는 없다.
3. **채팅 조회 연결 누락:** GET `/v1/taxa/subspecies`는 subspecies_handler를 호출한다. POST `/v1/chat`에는 이 handler로 아종 목록을 직접 조회하는 분기가 없다. 이는 pinned 코드 정적 확인이며 NAS 전체 요청의 재현은 아니다.
4. **이름 추출 누락 위험:** profile 경로는 recognized 이름/명시적 필터가 없으면 질문 전체를 이름으로 사용한다(app.py 1070). Jev가 profile만 반환해도 `청둥오리 아종 알려줘` 전체가 이름으로 넘어갈 수 있다.
5. **새 라벨 차단 필요:** 현 app.py는 알려진 분기 외 나머지를 evidence로 취급한다. Jev의 other/unknown은 명시적으로 clarify 처리해야 하며 임의 문헌 검색으로 넘기지 않는다.

### 제한된 parser 실제 실행 결과

- `청둥오리 아종 알려줘`: 두 기존 parser 모두 None.
- `흰뺨검둥오리 아종 알려줘`: 두 기존 parser 모두 None.
- 대조군 `청둥오리에 대해 알려줘`: profile·청둥오리 인식.
- 대조군 `왜가리는 무엇을 먹고 사니?`: diet·왜가리 인식.

AST로 순수 parser 부분만 추출해 실행했으며 종료 코드는 0이다. 이름 별칭 함수는 empty-set stub을 사용했으므로 통칭 검증이 아니다. 실제 임베딩 응답·DB·전체 채팅 성공률을 실행한 결과로 해석하지 않는다.

## 권장 적용 구조와 실제 평가 기준

**고정 한국어 질문 API 비교 → TEST shadow 비교 → 합격 시 기능 플래그 활성화** 순서가 적절하다. 초기 실험은 실행 가능한 action 하나를 Choice로 선택하고 코드가 기존 경로·세부 주제로 매핑하는 단순 구조도 비교한다. 예: `list_subspecies`는 부모 종 ID 검증 후 기존 아종 handler로 연결한다.

- 이름은 기존 이름/별칭/학명 후보 검색과 원문 근거로 해소한다. 필요시 별도 구조화 추출을 사용하되 최종 ID·활성 분류판을 대조한다. 자연어 의미 판단을 정규식 확대만으로 대체하지 않는다.
- 불확실·여러 후보·복합 요청·필터 충돌은 확인 질문으로 보낸다. Jev는 승인된 읽기 전용 handler만 선택하며 Cypher나 임의 실행 명령·권한을 결정하지 않는다.
- 명시적 모드와 검증된 기존 동작을 유지하고 Jev 장애 시 검증된 복귀 정책만 적용한다. 기존 라우터도 불확실하면 clarify를 유지한다.
- 최소 100문항의 조정용/최종용 분리를 유지한다. 존대·띄어쓰기·오타·학명·통칭·아종/종·분류 계보 대조·대명사·복합·범위 밖·적대적 문구를 포함한다. 한국어 원문을 유지하고 한국어/영어·이중언어 기준 설명을 개발용 표본에서 비교한다.
- intent 정확도·macro-F1 외에 **의도+세부 주제+대상 ID+조회 결과가 모두 맞는 종단 성공률**을 비교한다. 아종이 없으면 정확한 empty/자료 상태가 성공이지 임의의 아종을 만들어 반환하는 것이 아니다.
- confidence 구간별 정확도, 자동 처리율·오분류율·확인 질문 비율, p50/p95·재시도 포함 지연, input usage 비용을 함께 기록한다. 선택지 순서를 바꾼 안정성도 확인한다.
- 평가 전에 허용 오분류·coverage·지연 기준을 정하고 개선이 없으면 기존 경로를 유지한다. API·모델·전체 흐름의 실제 검증 전에는 RG-013 완료로 표시하지 않는다.
