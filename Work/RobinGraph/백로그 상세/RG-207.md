# RG-207 — 원문 조건 추출·엔티티 연결·안전 검증

[[Work/RobinGraph/RobinGraph 작업 백로그|← 전체 백로그]] · [[Work/RobinGraph/작업기록/2xx 검색·RAG·그래프 질의/작업 백로그|← 2xx 작업 백로그]]

- **상태**: 완료 (2026-10-22, 검증 범위 완료: 원문 조건 추출·스팬 커버리지·안전 검증 완료; 런타임 엔드투엔드는 RG-208로 연계, 운영은 향후 별도 승인)
- **우선순위**: P1 (높음)
- **권장 담당**: Claude (추출·엔티티 연결), Codex (API 계약 및 안전 리뷰)
- **목적**:
  - 사용자 자연어 원문으로부터 질의 수행에 필수적인 파라미터(대상 종, 분류목, 먹이 범주, 서식지, 같음/다름, 부정, 지역 범위, 특정 식물)를 손실 없이 추출하여 RG-205 정형 스키마로 구조화
  - 추출된 엔티티 및 조건의 유효성을 기존 검증 자산(`taxon_name_resolution.py` 등)을 통해 철저히 검증하고, 미지원 조건이나 출처 부재 시 안전하게 보류하는 방어 체계 구축
- **범위 및 변경 목표**:
  - 원문 조건 파라미터 추출:
    - 추출 수단은 규칙 기반, 소형 모델 기반, 또는 하이브리드 병행 방식 중 정형 계약 평가 후 결정하며, 모델 출력값도 엄격한 검증 대상으로 취급
  - 엔티티 연결 및 재검증:
    - 추출된 조류 국명/학명은 기존 이름 해소기(`taxon_name_resolution.py`)를 통해 실제 Neo4j에 존재하는 유효한 Taxon ID로 엄격히 재검증
    - 이름이 불완전하거나 동음이의어 등 모호성이 존재할 경우 임의 선택을 배제하고 사용자 확인(`clarify`) 유도
  - 안전 검증 및 경계 방어 원칙:
    - 필수 조건 누락, 조건 간 논리적 충돌, 시스템 미지원 조건 발견 시 즉시 `clarify` 안내
    - 특정 식물(감나무 등) 질의를 일반 열매 범주로 몰래 완화(silent relaxation)하여 임의 답변하는 행위 절대 금지 (`specific_fruit` -> `insufficient_data` 유지)
    - 나무열매 질의를 일반 열매 범주로 조회할 경우, 원천 데이터 한계(`(나무·풀 구분 없음)`) 및 limitations 안내 필수 명시
    - 학술적 근거(EltonTraits, AVONET 등)가 없는 임의의 가상 관계 생성 일체 금지
  - Cypher 실행 안전성:
    - **자유 Cypher 생성/실행 일체 금지**: 오직 사전 정의되고 파라미터화된 고정 Cypher 템플릿만 실행하여 오실행을 줄임
  - API 계약 조율:
    - API payload 필드 변경이나 확장 필요 시 사전에 Codex 및 UI 담당(Antigravity)과 합의
- **예상 대상 파일 / 모듈**:
  - `src/robingraph/retrieval/taxon_name_resolution.py` (현재 이름 해소기)
  - `src/robingraph/retrieval/graph_questions.py` (현재 고정 Cypher 템플릿 및 파서)
  - `src/robingraph/api/schemas.py` (현재 DTO 스키마)
  - `src/robingraph/retrieval/graph_condition_extractor.py` (예정: 원문 조건 추출 및 안전 검증기)
  - `tests/test_graph_condition_extractor.py` (예정: 조건 추출 단위 테스트)

  - [ ] 특정 식물 질의의 임의 완화 차단 및 `insufficient_data` 보류 검증 통과
  - [ ] 모호한 종명/조건 충돌에 대한 `clarify` 정상 응답 검증 통과
  - [ ] 자유 Cypher 생성 없이 사전 정의된 파라미터화 템플릿만 호출됨을 보증하는 단위 테스트 통과
  - [ ] RG-205 홀드아웃셋 기준 조건 추출 정확도(Slot Accuracy) 및 오실행 방지율 목표치 달성
