# RG-101 — 문헌 Chunk 검색 저장소 분리 (PostgreSQL pgvector + Neo4j 정책 재확인)

[[Work/RobinGraph/RobinGraph 작업 백로그|← 전체 백로그]]

- **상태**: 보류 (소규모 기준선 완료 · 실제 문헌 축적 후 재개)
- **우선순위**: 보류
- **권장 담당**: dev-claude (retrieval/ingest/PostgreSQL/pgvector) / dev-codex (아키텍처·인프라·통합 검증)
- **목적**:
  - 문헌 Chunk가 증가함에 따라 Neo4j 본문·벡터 적재로 인한 메모리 및 페이지 캐시(16GB NAS 공유) 점유 완화
  - 라이선스, 출처 등 정형 메타데이터 사전 필터링의 유연성 및 성능 확보
  - ADR-0001의 "관찰·문헌 청크 규모 및 실제 성능 측정 후 유지 여부 재판단" 결정 후속 이행
- **범위 및 변경 목표**:
  - Chunk 본문, 임베딩, 전문 색인을 PostgreSQL(pgvector)로 분리하고, 그래프 관계(Document·Chunk 식별 노드, EvidenceUnit, Claim)는 Neo4j에 유지
  - 정책 기준값(`SourceDataset.policy_status`, `Document.embedding_allowed`)은 Neo4j에 유지하며 PostgreSQL은 정책 사본 플래그로 사전 필터 후 Neo4j `_RECHECK_AND_CITE_QUERY` 재확인 (fail-closed 원칙 보존)
  - `search()` 인터페이스 및 `hybrid.py`의 RRF 순위 결합 로직 유지
  - 제외 범위: 관찰(Observation)·분류·Claim RDB 이전, 정책 기준 데이터 PostgreSQL 이전
- **예상 대상 파일 / 모듈**:
  - `src/robingraph/retrieval/neo4j_hybrid.py`
  - `src/robingraph/retrieval/hybrid.py`

### 2. 단계별 진행 및 검증 이력

#### 1단계: 2026-10-18 읽기 전용 TEST 기준선 실측 (완료)
- **환경 및 대상 코퍼스**:
  - Fixture 2문서 · 4청크 (171문자, 357 UTF-8 바이트)
  - 512차원 벡터 2개 적재 상태
- **질의 실측 (warm sequential)**:
  - 5개 질의 × 10회 반복 (총 50개 표본 측정, 임베딩 시간은 DB 측정에서 제외)
  - 전문 검색 지연: p50 3.945ms / p95 6.806ms
  - 벡터 검색 지연: p50 8.920ms / p95 18.262ms
  - 하이브리드 지연: p50 9.504ms / p95 10.851ms
- **외부 임베딩 지연**:
  - Jina API 첫 호출(cold start): 8,729.422ms
  - 이후 호출(warm): 205.979 ~ 216.448ms
- **인프라 확인 결과**:
  - NAS PostgreSQL(5433 포트) 메타데이터 확인
  - `pgvector`, `pg_bigm`, `pgroonga` 부재 확인 (`pg_trgm` 미설치 상태)
- **테스트 및 영향**:
  - 단위 검사 3개 통과, 실제 조회 성공
  - 데이터셋, 인덱스, 앱, 배포 변경 없음, commit/push 없음

#### 2단계: 2026-10-18 보류 전환 (사용자 새 지시)
- **상태**: 보류 (소규모 기준선 완료 · 실제 문헌 축적 후 재개)
- **결정 사유**:
  - 사용자 새 지시에 따라 RG-101을 보류하고 RG-406(한국 서식 토글 및 범위 우선 정책)을 우선 진행
  - 현재 Fixture 단계에서는 Neo4j 백엔드를 유지하고 PG 분리 구현은 보류
- **후속 계획**:
  - 기존 실측 기록은 온전히 보존
  - ADR-0007은 Proposed 상태 유지
  - 향후 실제 문헌 코퍼스가 축적되고 품질/규모 판단 기준이 설 때 격리 환경에서 실측 재개
