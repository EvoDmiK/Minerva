# RG-204 — 의미 기반 그래프 질의 해석 및 안전한 실행 전환 (상위/에픽)

[[Work/RobinGraph/RobinGraph 작업 백로그|← 전체 백로그]] · [[Work/RobinGraph/작업기록/2xx 검색·RAG·그래프 질의/작업 백로그|← 2xx 작업 백로그]]

- **상태**: 진행 중 (2026-10-22 착수, Phase 1 착수 및 하위 과제 총괄 진행; 운영은 향후 별도 승인)
- **우선순위**: P1 (높음)
- **권장 담당**: Codex (작업 조율·통합 검증), Claude (검색 로직·의미 추출), Antigravity (필요 시 UI), Writer (문서·백로그)
- **목적**:
  - RG-203의 결정론적 정규식 파서에서 나타난 단건 어휘/어미 보완(새중에서 insufficient_data 오분류, 나무열매 및 어떤게 있어 clarify 오분류) 반복을 탈피하고, 질문의 의미 구조(semantic structure)를 체계적으로 해석하여 7개 고정 그래프 질의 유형과 조건을 안전하게 실행하는 구조적 전환을 총괄
  - 상위 과제인 RG-204는 하위 과제의 완료 선행 조건이 아니라 하위 과제들의 진행 및 완료를 묶는 상위 에픽(Parent Epic)이며, 유한 문법 한계를 극복하면서 검증을 통해 오실행을 줄이는 다단계 파이프라인 확립
- **범위 및 변경 목표**:
  - 4개 하위 과제(RG-205 ~ RG-208)의 단계별 진행 조율 및 게이트웨이 검증 (실제 진행 순서: RG-205 선행 계약 → RG-206/207 유형 탐색/조건 추출 → RG-208 통합 및 단계적 전환):
    - Phase 1: [[Work/RobinGraph/백로그 상세/RG-205|RG-205]] 구조화 질의 계약·정답 평가셋·현재 기준선
    - Phase 2: [[Work/RobinGraph/백로그 상세/RG-206|RG-206]] 질문 임베딩 기반 질의 유형 후보 검색
    - Phase 3: [[Work/RobinGraph/백로그 상세/RG-207|RG-207]] 원문 조건 추출·엔티티 연결·안전 검증
    - Phase 4: [[Work/RobinGraph/백로그 상세/RG-208|RG-208]] 통합·관측·TEST 비교·단계적 전환
  - 핵심 아키텍처 원칙 준수:
    - 질문 임베딩은 7대 질의 유형 후보 검색(`top-k`)에만 사용하며, 과거 답변 재사용은 일체 금지 (항상 실제 DB 조회 근거 답변).
    - 질문 전체를 종 엔티티, 영구 별칭, Query 노드로 자동 저장하지 않음.
    - 작업 범위 및 질의 유형 후보 자료는 별도로 관리하되, 기존 이름 해소(855개 이름 벡터) 및 검색 인프라는 재사용.
    - 임베딩 저장 위치는 설계/비용 측정 후 결정하며, Neo4j 벡터 인덱스 신설을 필수로 단정하지 않음.
    - 기존 자체 호스팅 Jina 호환 모델 및 Jev 설정을 재사용하며, 새 외부 모델/인프라 확장 확정 금지.
    - 에이전트 모델은 각 워크트리 현 설정을 사용하며 착수 시 실제 모델명을 확인해 기록 (현재 모델명 임의 추정 금지).
  - 제외 범위: 후속 대화 문맥 유지(multi-turn state), 답변 캐싱, 특정 식물 생태 데이터 수집.
