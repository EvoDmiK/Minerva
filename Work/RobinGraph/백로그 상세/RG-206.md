# RG-206 — 질문 임베딩 기반 질의 유형 후보 검색

[[Work/RobinGraph/RobinGraph 작업 백로그|← 전체 백로그]] · [[Work/RobinGraph/작업기록/2xx 검색·RAG·그래프 질의/작업 백로그|← 2xx 작업 백로그]]

- **상태**: 착수 대기
- **우선순위**: P1 (높음)
- **권장 담당**: Claude (검색 로직·임베딩 프로필), Codex (성능·설정 검증)
- **목적**:
  - 사용자 자연어 질문을 임베딩 벡터로 변환하여 7대 고정 그래프 질의 유형 중 적합한 후보를 안전하고 신속하게 탐색(top-k)
  - 임베딩 유사도 점수 및 차순위와의 점수 격차(margin)를 기반으로 신뢰도를 평가하고, 모호하거나 기준 미달인 경우 안전하게 보류(`clarify`)하는 체계 구축
- **범위 및 변경 목표**:
  - 버전 관리되는 대표 질문(canonical prototypes) 및 패러프레이즈 임베딩 인덱스 구축:
    - 7개 질의 유형별 고품질 프로토타입 질의 구성 및 임베딩 사전 계산
  - 신뢰도 산출 및 보류 판정 로직:
    - top-k 후보 검색, 코사인 유사도 점수, 1위와 2위 간 마진(margin) 기반 신뢰도 점수 산출
    - 신뢰도 임계치 미달 시 임의 추론을 배제하고 안전하게 질문 종류 재확인(`clarify`) 유도
  - 라우터 공존 및 우선순위 설계:
    - 기존 `SemanticRouter`(taxonomy/observations/evidence 3개 prototype 분류), 그래프 7개 정규식, Jev 라우터와 중복 라우터를 신설하지 않고 명확한 실행 우선순위 및 공존 계약 확립
  - 핵심 금지 원칙 준수:
    - 질의 유형 후보만으로 종 ID나 조건 파라미터를 임의 확정하지 않음 (조건 추출은 RG-207 담당)
    - 과거 유사 질문의 답변 텍스트나 페이로드를 재사용하지 않음 (반드시 실시간 DB 조회)
    - 질문 전체를 신규 엔티티나 노드로 자동 적재하지 않음
  - 임계치 튜닝과 홀드아웃 분리 검증:
    - RG-205의 튜닝셋으로만 임계치를 조정하고, 최종 평가는 독립 홀드아웃셋에서 수행
  - 인프라 및 지연시간 측정:
    - 기존 자체 호스팅 Jina 호환 임베딩 모델 재사용 (새 외부 모델 도입 금지)
    - 로컬/TEST 환경에서의 실제 임베딩 API 호출 지연시간(p50/p95) 실측 및 캐싱 프로필 수립
- **예상 대상 파일 / 모듈**:
  - `src/robingraph/api/semantic_router.py` (현재 라우터)
  - `src/robingraph/api/jev_router.py` (현재 Jev 라우터)
  - `src/robingraph/embeddings/__init__.py` (현재 임베딩 인터페이스)
  - `src/robingraph/retrieval/graph_semantic_router.py` (예정: 그래프 질의 유형 라우터)

  - [ ] top-k 유사도 및 차순위 격차(margin) 기반 신뢰도 산출 및 안전 보류 판정 구현
