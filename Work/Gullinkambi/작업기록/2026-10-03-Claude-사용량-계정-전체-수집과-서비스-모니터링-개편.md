# Claude 사용량 계정 전체 수집과 서비스 모니터링 개편

## 요약

Claude 사용량이 Mac mini의 Claude Code status line에서만 갱신돼, 다른 기기나 VS Code 확장에서 쓴 양이 늦게 반영되던 문제를 고쳤다. 수집기가 Claude Code 로그인 토큰으로 계정 전체 사용률을 5분마다 조회하고, 실패하면 기존 status line 캐시로 되돌아가게 했다.

같은 날 `통합 대시보드`를 `서비스 모니터링`으로 이름을 바꾸고, Antigravity Claude·GPT(`third_party`) 패널과 알림을 제거했다. 5시간 사용률 알림은 처음 추가했고, 주간 사용률 알림은 구간별 알림으로 바꿨다.

## 시작한 문제

- Antigravity 5시간 사용량이 95%에 가까웠는데도 알림이 오지 않았다. 사용률 알림이 `window="weekly"`만 보고 있어서 5시간(`session`) 한도에는 조건 자체가 없었다.
- Claude 사용량은 status line의 `rate_limits`에서만 가져와, Claude Code가 메시지를 처리할 때만 갱신됐다. Grafana 값이 실제보다 1~2% 뒤처졌다.

## Claude 사용량 수집

```
Claude Code OAuth 토큰(macOS 키체인)
  → 사용량 endpoint 조회 (5분 간격, 읽기 전용)
  → ai_subscription_quota_used_percent{provider="claude",window="session|weekly"}
  → 실패 시 status line 캐시로 폴백
```

- 토큰은 **읽기만** 한다. refresh하면 Claude Code의 로그인 세션이 바뀔 수 있어서다. 토큰이 만료됐으면 오류로 처리하고 폴백한다.
- 토큰은 로그와 지표 라벨에 출력하지 않는다.
- endpoint는 공식 문서화된 API가 아니다. 응답 형식이 바뀌면 조회가 실패하고 폴백으로 넘어간다.
- 지표 이름과 라벨이 그대로라서 대시보드와 알림은 수정하지 않았다.
- 응답의 `five_hour`, `seven_day`에 사용률(%)과 초기화 시각(ISO)이 들어 있다. 사용률은 0~100 범위라 그대로 쓴다.
- 환경변수 `CLAUDE_USAGE_API`, `CLAUDE_USAGE_INTERVAL_SECONDS`, `CLAUDE_USAGE_TIMEOUT_SECONDS`, `CLAUDE_USAGE_URL`을 추가했다.
- 단위 테스트(응답 파싱, 폴백)를 추가해 11개가 통과한다.

적용 후 Mac mini와 NAS Prometheus 모두 같은 값(5시간 11%, 주간 6%)을 보여 줬고, 이전 방식과 1% 정도 차이가 있었다. 에러 로그에 폴백 메시지는 없었다.

## 알림 변경

| 규칙 | 조건 | 비고 |
| --- | --- | --- |
| AI 5-hour quota high | 5시간 사용률 80% 초과, 2분 지속 | 신규. Claude·Antigravity Gemini 대상. Codex는 5시간 한도가 없다. |
| AI weekly quota high | 주간 사용률 50/70/85/95% 구간별 1회 알림 | 기존 85% 단일 조건에서 변경. |
| 수집 실패, 사용률 | `pool!="third_party"` | Antigravity Claude·GPT pool 제외. |

- 구간별 알림은 `label_replace`로 구간마다 `tier` 라벨을 붙여 alert instance를 나눈다. 그래서 구간마다 한 번씩만 알림이 간다.
- Discord 라우트에 이 알림 전용 `repeat_interval: 168h`를 두어 4시간마다 반복하지 않게 했다.
- 구간이 누적되는 방식이라 70%를 넘으면 한 카드에 50%와 70% 줄이 함께 나올 수 있다.
- 알림 규칙은 Grafana가 시작할 때만 읽는다. NAS에서 저장소를 pull한 뒤 Grafana를 재시작해야 반영된다.

## 대시보드 변경

- `통합 대시보드` → `서비스 모니터링` 이름 변경. UID는 그대로라 알림의 Dashboard·Panel 링크는 유지된다.
- Antigravity Claude·GPT 5시간·주간 패널을 지우고 Gemini 패널을 넓혔다. 다음 초기화, 요일별 증가, 수집 상태·지연, 추이 패널에서도 `third_party`를 뺐다.
- `Codex · 다음 초기화` 패널이 No Data였다. Codex에는 `session` 구간이 없어서 `window="weekly"`를 보도록 바꾸고 이름을 `Codex · 주간 초기화`로 바꿨다.

## 겪은 문제

### instant 쿼리가 모든 구독 패널을 비움

NAS에서 커밋되지 않은 채 수정돼 있던 stat 패널 12곳의 instant 쿼리를 저장소에 옮겼더니, 구독 패널이 전부 `초기화됨 · 갱신 대기`로 표시됐다.

- 원인: 대시보드 시간 범위가 `now/d ~ now/d`라 끝 시각이 오늘 23:59다. instant 쿼리는 그 시각을 기준으로 평가돼서 `time()`이 미래가 되고, `reset_timestamp <= time()` 조건에 모든 구간이 걸렸다.
- Prometheus에는 값이 정상으로 있었다. 쿼리를 직접 조회해서 확인했다.
- 해결: `time()`을 쓰는 패널 9개의 instant 설정을 되돌렸다. 시간 범위가 `now/w ~ now`인 인프라 모니터링의 3곳은 그대로 뒀다.
- 교훈: `time()`을 쓰는 쿼리는 시간 범위의 끝이 `now`가 아니면 instant로 바꾸지 않는다.

### Git Sync가 방금 고친 내용을 되돌림

저장소에 푸시한 수정이 1분 뒤 Grafana UI에서 저장된 커밋(`feat. 서비스 모니터링 update`)에 덮였다. UI가 수정 전 화면 상태에서 저장했기 때문이다.

- 해결: UI 커밋의 다른 변경은 유지하고 내 수정만 다시 적용했다.
- 교훈: Git Sync 대시보드는 저장소와 UI 양쪽에서 쓸 수 있다. 저장소를 고친 직후에는 UI를 새로고침한 뒤에 편집한다.

### Hermes 사용량이 비어 보임

수집 문제가 아니었다. Hermes 원본 DB의 마지막 세션이 전날 오후에 시작됐고, 오늘 시작한 세션이 없었다. 대시보드가 `오늘`만 보고 `started_at` 기준으로 집계해서 비어 보였다. 시간 범위를 늘리면 해결된다.

## 배포 구조

- 대시보드: GitHub `main`에 푸시하면 Grafana Git Sync가 몇 분 안에 가져간다.
- 알림: NAS 저장소를 pull한 뒤 Grafana 컨테이너를 재시작한다.
- 수집기: Mac mini LaunchAgent가 별도 체크아웃(외장 SSD)의 파일을 실행한다. 파일을 반영하고 LaunchAgent를 재시작해야 한다.
- Birds-Nest의 `dev-mac` 브랜치에는 이번 작업과 무관한 커밋이 많아서 통째로 합치지 않고, 수집기 커밋 하나만 `main`으로 가져왔다.
