# Hermes 모니터링 전면 개편

Hermes 수집 항목, 저장 구조, 대시보드(Hermes 탭)를 새로 만들었다. 관련: [[Work/Gullinkambi/작업기록/2026-10-10-ORCA-호출별-관측-구현과-운영-반영|ORCA 호출별 관측]] (같은 파이프라인 사용).

## 결과
- 세션 상태 샘플과 도구 호출 이벤트를 수집해 TimescaleDB에 저장하고, Grafana Hermes 탭을 새 테이블 기준으로 다시 만들었다.
- 기존 `observability.hermes_runs`는 보관용으로 두고 건드리지 않았다(새 데이터는 새 테이블에서 시작).

## 배경과 발견
- Hermes `state.db`에는 **세션 누적 카운터만** 있고 호출별 토큰은 어디에도 없다(`messages.token_count`는 전부 NULL, 로그에도 없음). 그래서 "호출별 수집" 대신 **누적 값을 주기적으로 샘플링해 증감으로 계산**한다(분 단위 해상도).
- 디스코드·CLI 세션은 `ended_at`이 거의 기록되지 않는다(디스코드 278건 중 16건만 정상 종료). 그래서 "미종료"가 대부분이며, 종료 기록과 무관하게 마지막 활동 시각으로 상태를 계산한다.
- 최근 세션의 캐시 적중률이 낮게 보이는 건 계산 오류가 아니라 짧은 세션의 첫 호출·캐시 만료 때문(긴 세션 약 90%, 14일 전체 86.5%).

## 구현
- **수집기**(`hermes_sessions.py`, `collector.py`): 1분마다 세션 상태 샘플(변경 시에만)과 도구 결과 이벤트를 전송. 세션 ID는 해시, 제목·채널/사용자 ID·프롬프트·도구 인자와 결과는 보내지 않음. 도구는 이름과 결과 판정(정상/오류/비정상 종료/판정 불가)만 전송.
- **DB**(마이그레이션 009, 010): `hermes_session_samples`, `hermes_tool_events`, 뷰 `hermes_sessions_current`(상태: 활동 중 1시간 이내 / 방치 / 종료), `hermes_usage_deltas`(구간별 증감, 수집 이전 누적은 NULL로 두어 특정 시각에 귀속하지 않음). 적재 함수는 중복 재전송에 안전(append-only, 도구 결과는 판정 불가→판정됨 갱신만 허용).
- **n8n**: 검증 노드에 두 배열 추가 후 재-import·재시작. 순서는 DB → n8n → 수집기(n8n보다 수집기를 먼저 켜면 알 수 없는 배열을 무시해 데이터가 사라짐).
- **대시보드**: 한눈에 보기(활성/방치 세션, 기간 토큰, 캐시 적중률, 도구 호출/오류) → 세션(상태 도넛, 목록) → 사용량(시간대별 토큰, 프로필·모델별) → 도구(상위 호출, 결과 표, 시간대별) → 선택한 세션 상세(요약·토큰 구성·도구 사용·누적 추이). 세션 선택 변수와 표의 세션 링크로 드릴다운.
- 쓰지 않던 칸반 변수, p95 타일, 프로필별 실패율 표, 칸반 열은 삭제.

## 도구 결과 판정
- 결과 본문은 읽어도 전송하지 않고 형태만 본다. JSON 객체에서 `error`/`success:false`/실패 `status`는 오류, 0이 아닌 `exit_code`는 비정상 종료, 그 외 객체는 정상. 일반 텍스트(MCP 도구 등)·배열은 판정 불가.
- 판정 불가가 여전히 약 56%인 이유: Hermes가 컨텍스트 절약을 위해 이전 도구 결과를 `[read_file] ...` 같은 요약문으로 바꿔 원래 결과가 남지 않음, 그리고 MCP 도구의 일반 텍스트 결과. 새로 쌓이는 이벤트는 요약되기 전에 읽어서 판정 불가가 낮다(최근 1일 26%, MCP 제외 0%, 표본 31건).

## 검증
- 수집기 단위 테스트(세션 샘플, 도구 이벤트, 비공개 데이터 미포함, 규칙 변경 시 재전송), 임시 TimescaleDB에서 009 적용·중복 재전송·증감·상태 확인, NAS 반영 후 대시보드 쿼리 20개 실행 확인.
- Grafana 화면은 사용자 확인으로 피드백 반영(세션 요약 이름 표시, 막대 값 잘림 수정 등).

## 한계·남은 일
- 기간 토큰은 수집 시작(2026-10-10) 이후만 쌓임. 세션 목록의 총 토큰은 세션 누적이라 과거 세션도 보임.
- MCP 도구 실패는 판정 불가. Hermes 로그의 `Tool X returned error` 줄을 읽어 보강하는 방안은 미착수(시각 기준 근사 매칭, 오류 본문 제외 필요).
- 새 테이블용 DB 통합 테스트는 아직 없음(수동 검증만).
