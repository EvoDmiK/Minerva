# Mac mini 본체 지표 전환과 앱별 메모리

Mac mini(32GB) 시스템 패널이 OrbStack VM(16GB 제한) 값을 보여 주던 문제와, Docker 탭에서 일부 컨테이너가 빠지던 문제를 고쳤다. 같은 흐름에서 Discord 알림 제목과 범례도 손봤다.

## 결과
- Discord 알림 제목: 발생 `🚨 [RAGNAROK IS COMING...]`, 복구 `✅ [Ragnarok is over...]` (2026-10-15).
- Mac mini Docker 탭: 빠져 있던 컨테이너 6개(`alloy-macmini`, `openviking-exporter`, `n8n-test`, `n8n-runners-test`, `neo4j-test`, 당시 `macmini-node-exporter`)가 수집된다.
- Mac mini 시스템 탭: CPU·메모리·디스크·네트워크·Load·업타임이 Mac 본체 기준(메모리 32GB, Darwin)으로 나온다.
- Mac mini 시스템 탭에 "앱별 메모리" 행 추가: 현재 상위 15개 막대 + 상위 10개 추이(누적).
- Docker 탭·시스템 탭(NAS, Mac mini)의 시계열 범례가 `Last *`, `Mean`, `Max`로 바뀌었다.

## 원인과 조치
### 컨테이너 누락
- OrbStack에서는 cAdvisor가 Docker 메타데이터를 못 읽어 `name`에 64자리 컨테이너 ID를 넣는다.
- Birds-Nest `docker-compose/monitoring/prometheus.yml`이 이미지→이름을 하나씩 매핑하고, 매핑 없는 ID는 마지막 규칙에서 `drop`한다. 목록에 없던 6개가 버려지고 있었다.
- 매핑 추가로 해결. **새 컨테이너를 띄우면 같은 이유로 또 빠지므로 매핑을 추가해야 한다.**
- 이 파일은 단일 파일 bind mount라 편집 후 `/-/reload`가 아니라 `macmini-prometheus` 재시작이 필요하다.

### 시스템 지표가 VM 기준
- `macmini_node`가 OrbStack VM 안의 `macmini-node-exporter` 컨테이너를 읽고 있었다(`MemTotal` 16GB).
- brew로 설치만 돼 있던 node_exporter를 `brew services start node_exporter`로 실행하고, Prometheus 대상을 `host.docker.internal:9100`으로 바꿨다. VM 쪽 컨테이너는 compose에서 제거하고 내렸다.
- 대시보드 쿼리를 Darwin 지표에 맞춤:
  - 메모리: `macos_memory_used_bytes` / `macos_memory_total_bytes` (Activity Monitor 기준)
  - 파일시스템: `fstype="apfs",mountpoint=~"/System/Volumes/Data|/Volumes/[^/]+"`
  - 디스크: `device=~"disk[0-9]+"`, 네트워크: `device=~"en[0-9]+"`
  - 디스크 사용률: macOS에 `node_disk_io_time_seconds_total`이 없어 읽기+쓰기 시간 합으로 근사(100% 상한)
- Mac mini 디스크 alert(`infrastructure.yml`)와 독립 Mac mini 대시보드(`macmini-system.json`)도 같은 기준으로 바꿨다.

### 앱별 메모리
- `macos-memory-exporter`(9092)에 `macos_app_memory_bytes{app}` 추가. `top -l 1 -stats pid,mem`(물리 footprint)과 `ps`의 경로를 PID로 합쳐, `.app` 번들 기준으로 Helper를 묶는다(예: `Orca Helper (Renderer)` → `Orca`). 상위 20개 + `other`.
- 추가 직후 상위: OrbStack 약 11GB(Docker 전체), Python 2.8GB, claude 2.1GB, agy 1.5GB, Orca 0.9GB.
- 추이 패널이 처음에 "데이터 없음"이었던 건 기본 기간이 `now/w`라 step이 커서 몇 분치 데이터가 안 잡혔기 때문. 시간이 지나면 채워진다.

## 알아 둘 점
- NAS SSH alias는 `dove-storage`(포트 99). 문서의 `NAS` alias는 이 Mac에서 해석되지 않는다. 작업 중 한 번 SSH가 거절돼 사용자가 다시 열었다.
- Grafana `docker logs`가 비어 있어 provisioning 오류는 로그로 확인할 수 없다. 관리자 비밀번호도 env 값과 달라 API 확인이 안 된다.
- `macos-memory-exporter`는 Git 저장소 밖(`~/Library/Application Support/macos-memory-exporter/exporter.py`)에만 있다. 수정 전 원본은 `exporter.py.bak-20261022`. 재시작: `launchctl kickstart -k gui/$(id -u)/com.macos-memory-exporter`.
- Gullinkambi 커밋 이메일은 `93193661+EvoDmiK@users.noreply.github.com`(로컬 git config). GitHub이 개인 Gmail 노출 push를 막는다. 알림 제목 커밋은 이메일 수정 때문에 `main`에 force push했다.
