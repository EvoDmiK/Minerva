# Vision60 Agent 활용 이력서 초안 및 근거 검증

## 이력서 삽입용

### AI 코딩 에이전트 활용 로봇 시뮬레이션 실험·평가 하네스 구축

**핵심 기술:** Claude Code, Codex, MLflow, MCP, Python, Shell  
**적용 환경:** Isaac Sim, ROS 2, Vision60 SLAM·Navigation

Claude Code·Codex가 생성한 로봇 기능 코드를 대상으로, 실험·평가 하네스와 MLflow MCP 연동을 구축하고 반복 시험 및 파라미터 추적을 담당.

- **평가 신뢰성:** Isaac Sim ground truth 기반 도착 판정과 자세·속도·데이터 품질 검사를 활용해 성공 오판정과 기동·검증 실패를 구분.
- **실험 추적:** 다중 프로세스 trial을 MLflow parent/child run으로 연결하고, 파라미터·지표·코드 버전·시드·지도·로그를 기록해 비교 가능한 실험 이력 구성.
- **MCP 연동:** MLflow MCP 연동 구현과 기존 실험 결과를 활용한 후보 파라미터 조회·비교.
- **반복 검증 운영:** 후보 파라미터의 5회 반복 시험을 기준으로, 통과 시 지게차 속도·출발·목표 조건을 변경하고 실패 시 조정 후 재검증하여 적용 범위와 실패 조건 추적.

## 본인 기여와 근거의 경계

- 사용자 설명: Claude Code와 Codex에 로봇 구현을 맡겼으며, 본인 기여는 하네스 엔지니어링·MLflow MCP 구현·결과 테스트·파라미터 추적.
- 운영 흐름: 좋은 후보 설정 조회 → 동일 후보로 5회 반복 시험 → 통과 시 조건 변경, 실패 시 파라미터 조정.
- 문서 확인: 테스트 실행·결과 수집·판정, MLflow parent/child run, 코드 버전·시드·지도·로그 기록, 시작 실패를 포함하는 집계, 실제 pose 기반 검증.
- 미확인: MCP 서버 코드·도구 스키마, Claude Code/Codex 역할 분담, 다음 실험의 자동 의사결정 여부, 세부 변경사항별 직접 작성자.

## 수치와 표현 검수

- ‘5회 반복 테스트’는 사용자 설명과 반복 시험 문서에 근거한 운영 방식이며 모든 캠페인이 5회였다는 뜻은 아니다.
- 9/18 세 속도의 통과 사례는 각 1회·단일 시드 시험이다. 최초 1.5 m/s 실행은 타임아웃 실패 뒤 시간 예산을 바꿔 재실행했다.
- 종합 보고서의 5/5 요약을 최종 성공률로 쓰지 않았다. 9/17 수정 원본에는 재시도·시간 기준 변경이 포함되며 오후 원본은 3/5 뒤 설정을 바꾸어 2/2 재검증했다.
- 9/21 변경 시나리오의 PASS도 1회이며 지도/costmap 병목과 반복 실패가 남았다.

## 제외한 표현

- 성공률 100% 및 조건이 다른 실행을 합산한 5/5 성과.
- 모든 환경에서 최적인 범용 파라미터 도출.
- 무충돌 보장·접촉 센서 직접 계측·실물 로봇 검증 완료.
- 에이전트 내부 실행 루프나 컨텍스트 관리 엔진 직접 개발.
- 문서의 MLflow 로깅을 MCP 서버 구현의 독립 증거로 제시.

## 검증 범위

문서와 사용자 진술을 대조한 **작성 근거 검증**이다. 제품 코드·원본 로그·실제 MLflow 서버·Isaac Sim을 이번에 실행 검증하지 않았다. 수치와 통과 기록은 문서에 보고된 결과이며 독립 재현 결과가 아니다. 원본 문서는 수정하지 않았다. 독립 critic 검수의 MCP 기능 범위·참여 기간·시뮬레이션 명시·반복 시험 절차·역할 배치 지적을 원본과 대조하여 수정본(v2)에 반영했다. 전체 문서 연구 결과는 아직 미수신이며, 전체 문서의 독립 검토가 완료됐다고 주장하지 않는다.

## 제출 전 확인

실제 참여 기간, MLflow MCP 도구 목록·저장소, 문서에 나온 변경사항별 본인 기여를 확인하면 제출 문구를 더 구체화할 수 있다. 내부 주소·run ID·비밀값은 이 기록에 넣지 않았다.
