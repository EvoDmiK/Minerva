## 카테고리별 분류 및 작업 ID 체계

작업 ID는 접두사 `JR-`과 3자리 번호(`1xx`~`8xx`)로 부여합니다.  
**첫 자리는 카테고리 도메인, 뒤 두 자리는 순번**입니다.

| 카테고리 | 도메인 범위 | 예시 |
|---|---|---|
| **1xx** | 데이터셋 & 합성 데이터 | 합성 train/val 데이터 생성, 토큰 한도 압축, 라벨 검토 |
| **2xx** | 모델 구조 & 인코더 | Laya multilingual, LinearRouter, Gemma 로컬 실행 |
| **3xx** | 학습 & Hyperopt 탐색 | LR, weight decay, smoothing, warmup, seed 비교 |
| **4xx** | 에이전트 라우팅 & 인터페이스 | Hermes/Dovie 연동, 도구 호출 프로토콜 |
| **5xx** | 평가 & 오류 분석 | 고정 평가셋, 헷갈리는 도구 경계 분석, 회귀 검증 |
| **6xx** | 관측성 & MLflow | Parent/Child Run 구조, Artifacts, 파라미터 추적 |
| **7xx** | 런타임 & 가속 (CUDA/M4) | RTX 5070 Ti 서버 실행, Mac M4 환경 최적화 |
| **8xx** | 문서 & 개발환경 | 명세 문서, 재현 스크립트, 데이터셋 버전 관리 |

## 1. 신규 착수 대기 작업

### JR-102 — 실제 요청 기반 고정 평가셋 구축
- **상태**: 착수 대기
- **우선순위**: P1 (높음)
- **권장 담당**: Claude Code / AGY
- **목적**: 합성 validation 세트의 과적합을 방지하기 위해 실제 사용자 요청 약 100건 기반의 검토된 고정 테스트셋 구축.
- **완료 기준**:
  - [ ] 실제 대화 로그 및 의도 기반 100건 샘플링
  - [ ] Human review를 통한 골드 라벨 확정
  - [ ] 고정 테스트셋 JSONL 아카이빙 및 평가 파이프라인 연결

### JR-502 — 액션 및 비선택(No-Tool) 사례 보강
- **상태**: 착수 대기
- **우선순위**: P2 (보통)
- **목적**: 도구를 호출하지 않아야 하는 일반 질의나 모호한 입력에 대한 fallback 판별력 향상.
- **완료 기준**:
  - [ ] non-tool 대화형 쿼리 50건 추가
  - [ ] 잘못된 도구 오호출(False Positive) 비율 10% 이하 달성

## 작업 관리 및 검증 원칙

1. **상세 원문 1회 기록**: 학습 조건, MLflow Run ID, 파라미터 및 평가 메트릭은 반드시 `Work/Jery/작업기록/` 마크다운에 보존합니다.
2. **실제 데이터 검증**: 테스트 세트로 파라미터를 튜닝하지 않으며, 고정 시드 및 오프라인 검증 통과 수치를 기록합니다.
3. **MLflow 및 형상 관리**: 코드 커밋(`origin/dev-codex`)과 MLflow Run 산출물(Artifacts)의 정합성을 항상 유지합니다.
