# LR·가중치 공동 탐색과 데이터 형식 검증

성능 저하 상황에서 초기 LR을 그대로 고정한 점에 대한 사용자 지적을 반영했다. 사용자 추가 요청에 따라 window_none 가중치도 Hyperopt 파라미터와 MLflow 비교 파라미터에 포함했다.

## 기존 실행 보존

고정 LR Parent `bc61fce284ae468e8b7022508f36e819`는 KILLED로 중단했다. 가중치 1.0/0.5 조건은 10에폭 완료 및 FINISHED 상태로 보존했고, 0.25 조건은 진행 중 중단해 checkpoint를 보존했다. 완료한 최고 trained validation 정확도 10.89%/12.50%는 baseline 16.13%보다 낮았다.

LR 단독 Parent `c755eeb007b5481a9cc5de444ab8a085`는 준비만 한 뒤 공동 탐색 요청에 따라 학습 시작 전에 KILLED로 폐기했다. Child가 없으며 학습을 실행했다고 보고하지 않는다. 다른 회사 GPU 작업은 유지했다.

## 공동 탐색

새 [Jery Parent `afef02bf60dc496e8287ca3dc3057ad7`](https://mlflow.dove-nest.com/#/experiments/47/runs/afef02bf60dc496e8287ca3dc3057ad7)를 준비했다.

- 초기 LR: log-uniform `1e-6~1e-5`.
- window_none loss 가중치: choice `[0.25, 0.5, 1.0]`.
- Hyperopt TPE 5회, 각 10에폭. 같은 base에서 새로 시작하며 전체 데이터를 사용한다.
- weight decay 0.01, label smoothing 0, seed 3407, 유효 batch 4, warmup 64 및 linear scheduler 유지.
- 최고 trained validation 점수만 검색에 사용하고 test로 튜닝하지 않는다. serving baseline 보호와 callback 정책은 유지한다.
- 필수 Child params는 LR·가중치·epochs·seed·effective_batch_size 5개. metrics는 기존 7개. 나머지는 JSON artifact이며 모델 binary는 별도 저장한다. 기존 params 4개 plan도 지원한다.

첫 Hyperopt 후보는 LR `2.2090148907640474e-6`, 가중치 `0.5`다. 이는 시작 전 생성한 후보이며 실제 optimizer 실행 증거는 아래에 따로 기록한다. LR이 성능 저하의 유일한 원인이라고 확정하지 않는다.

## 데이터 형식 대조 결과

[Unsloth 공식 스키마](https://unsloth.ai/docs/basics/train-your-own-decision-model-with-unsloth#dataset-guide)의 `state / questions / gold` 및 choice criteria에 맞는 별도 `decision-export-v1`을 사용한다. 원본 Jery JSONL을 직접 모델에 넣지 않는다. metadata는 입력 특징이 아니다. 설치된 native builder는 dict형 label/probabilities도 처리한다.

회사 환경 Unsloth 2026.10.6 / Laya 0.4.9 / Transformers 5.17.0에서 전체 7,341개 창을 실제 native builder로 검사했다.

| split | 창 | skip | target·입력 불일치 | 잘림·충돌 | 최대 토큰 |
|---|---:|---:|---:|---:|---:|
| train | 4,172 | 0 | 0 | 0 | 950 |
| validation | 1,592 | 0 | 0 | 0 | 953 |
| test | 1,577 | 0 | 0 | 0 | 930 |

한도는 max_len 1024, head_max_len 256이다. 정답 확률의 선택지 인덱스 대응, 기록된 원래 결정·허용 도구와의 대응, gold·metadata를 읽지 않는 추론 특징과 native 학습 특징의 일치를 확인했다. 검사기는 모델 가중치를 로드하거나 GPU forward를 실행하지 않는다. 실제 학습 코드에서도 native 학습 특징과 추론 특징의 일치를 확인한다.

현재 Unsloth Laya 미세조정 형식과 호환된다는 결과이며, 원 사전학습 코퍼스의 형식·분포·품질이 같다고 확인한 것은 아니다. 도구 설명 120자 압축, criteria의 별칭 표현, window_none 분포와 다중 창 집계의 적합성은 별도 문제다. 형식 통과를 성능 개선 근거로 해석하지 않는다.

## 코드·검증

`dev-codex`의 `ba9d007`을 commit/push하고 회사 서버에 반영했다. 전체 테스트 134개, 원본 v1/v2 데이터 검증을 통과했다. 새 검사기 `scripts/audit_laya_export_format.py`, 공동 탐색 설정 `configs/training/laya-routing-v2-joint-search-20261019.json`, 재현 명령과 한계는 `docs/data/laya-routing-v2-joint-search-20261019.md`에 있다. 의존성은 기존 `requirements-decision-cuda.txt`다.

학습 데이터·가중치·대형 결과는 Git 밖에 유지한다. 합성 정답은 미검토 상태이며 실사용 정확도로 주장하지 않는다.

## 실제 시작 확인

새 Parent `afef02bf60dc496e8287ca3dc3057ad7`와 첫 Child `95ba153e90c5415bb414c6309e0c4500`가 RUNNING이다. 실제 optimizer step 175 이상과 유한한 loss·gradient를 확인했다. 실제 학습 config와 MLflow params에 LR `2.2090148907640474e-6`·가중치 `0.5`가 일치한다. Parent에 native-format-audit.json, search-preflight.json, 중단 증거 JSON을 업로드하고 재조회 SHA-256을 확인했다. 형식 검사의 최대 토큰 수는 이전 실제 CUDA 학습의 token_budget.json과도 일치한다. 성능 개선 여부는 첫 에폭 검증 전이므로 아직 평가하지 않는다.


## 사용자 실패 표시 문의 확인

MLflow API와 서버를 재조회한 시점에 현재 Parent `afef02bf60dc496e8287ca3dc3057ad7` 및 첫 Child `95ba153e90c5415bb414c6309e0c4500`는 모두 RUNNING이었다. 실제 step 2,344·약 1.10에폭까지 진행했고 첫 에폭 validation 정확도 0.1573, macro F1 0.2835, coverage 0.996 및 train loss 2.6135가 MLflow step 1에 기록됐다. supervisor·CUDA 학습 프로세스는 살아 있으며 오류 traceback·tracking_error는 확인되지 않았다. 정확도는 baseline 0.1613보다 아직 낮으므로 성능 개선 성공으로 해석하지 않는다.

최근 조회된 7개 실행에는 FAILED가 없었다. 기존 고정 LR Parent/세 번째 Child와 준비용 LR 단독 Parent의 KILLED는 설정 전환에 따른 의도적 중단이다. 기존 중단 상태를 유지하면서 MLflow phase·중단 이유·후속 Parent 링크를 명시해 현재 실행과 구분했다. 사용자가 본 실패 표시의 정확한 Run은 별도로 전달받지 않아 단정하지 않는다.
