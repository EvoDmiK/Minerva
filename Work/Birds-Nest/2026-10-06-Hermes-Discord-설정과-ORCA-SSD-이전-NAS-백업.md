# 2026-10-06 Hermes Discord 설정과 ORCA SSD 이전·NAS 백업

## 오늘 완료한 작업

### Hermes 재시작과 Discord 설정

Hermes agent를 재시작하고 Discord의 설정 채널을 허용 목록에 추가했다. 같은 채널을 Home 채널로 지정한 뒤 환경변수가 반영되도록 컨테이너를 재생성했다. Gateway 정상 실행, 컨테이너 건강 상태 및 선언형 설정과 실행 설정의 일치를 확인했다.

### ORCA 데이터의 SSD 이전

ORCA 프로젝트, worktree, 앱 데이터, 세션 기록과 캐시의 저장 위치를 외장 SSD로 전환했다. 앱과 백그라운드 데몬을 종료하고 파일을 복사한 뒤 내용 체크섬과 권한을 검증했다. 기존 경로에는 심볼릭 링크를 남겼다. 재실행 후 런타임과 그래프 준비 상태, 프로젝트 및 사용 중 Git worktree 접근을 확인했다.

현재 대화를 처리하는 Codex가 쓰는 세션 기록 두 개는 계속 갱신 중이므로 원본을 보존했다. 파일이 닫힌 뒤 SSD로 복사·검증하는 마무리 작업을 실행해 두었다. ORCA 앱 실행 프로그램 자체는 데이터 이전에 포함되지 않는다.

### ORCA 원본 백업의 NAS 보관

원본 백업 여섯 개를 압축해 NAS에 업로드했다. 압축 크기는 약 855MB이며, 로컬과 NAS의 SHA-256 일치 및 압축 파일 읽기를 검증했다. 백업 접근 권한을 소유자로 제한했다. 기록 중인 세션 로그는 백업 생성 시점의 스냅샷이다. 내장 디스크의 원본 백업도 보존했다.

## 진행 중인 작업

Birds-Nest 전체 프로젝트의 NAS 백업을 진행 중이다. Git 이력과 런타임 데이터까지 포함한다. 파일 약 28만 9천 개를 복사했고, SQLite 데이터베이스 54개는 백업 API로 스냅샷을 만든 뒤 무결성 검사를 통과했다. 기존 데이터베이스 두 개는 원본에서도 무결성 오류가 확인되어 원본 복사본을 보존하고 경고를 백업 기록에 남겼다. 전체 스냅샷을 압축 중이며, 업로드 후 검증 결과를 추가한다.

## 후속 확인

- 현재 열린 Codex 세션 기록 두 개의 SSD 이전 마무리 상태 확인.
- NAS에 보관한 백업은 업로드 시점의 스냅샷이며 이후 변경이 자동으로 반영되지 않는다.

## 기록 범위

이 문서는 작업 내용과 검증 결과를 기록한다. 내부 절대 경로, 채널 식별자, 인증 정보와 상세 백업 메타데이터는 포함하지 않는다.
