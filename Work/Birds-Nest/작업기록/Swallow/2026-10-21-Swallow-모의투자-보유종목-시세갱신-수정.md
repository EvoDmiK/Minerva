# [SW-014] Swallow 모의투자 보유 종목 시세(평가가격) 갱신 수정

## 요약

Swallow 모의투자 포트폴리오의 보유 종목 `현재가`(`paper_positions.last_price`)가 매수가에 고정되어 평가손익이 0으로 보였다. 원인은 관심종목 시세 수집기(`[Stock] Swallow - Watchlist Prices`)가 활성 관심종목만 수집하고 포지션 평가가격은 갱신하지 않았기 때문이다.

dev-claude `9fb5df3`에서 수집 대상을 **활성 관심종목 ∪ 관심목록 밖 보유 종목**으로 넓혔다. 검증된 시세를 적재하는 같은 SQL 문장에서 보유 포지션의 `last_price`·`updated_at`만 갱신한다. dev-codex `850da6a`에 통합되었다.

**현재 상태:** 구현이 완료되었다. root의 자동 테스트(격리 PG 포함)와 실제 `n8n-test:2.15.0` 이미지의 격리 n8n 노드 검증(13:56:43 KST, `positionsUpdated = 5`)을 통과했다. **운영 n8n 배포·운영 DB 변경·Grafana UI 확인은 하지 않았다.**

## 1. 작업 배경 및 문제 분석

### 발생 현상 / 요구사항
* 2026-10-21 12:44 KST에 운영 DB를 읽어 확인한 보유 6종목: 두산 `000150` 2주, 삼성전자 `005930` 1주, 삼성전기 `009150` 1주, S-Oil `010950` 1주, KT&G `033780` 1주, BGF리테일 `282330` 1주.
* 6종목 모두 `last_price`가 매수가(10/15~10/20 체결)에 고정되어 있었다.
* 삼성전자의 `stock_price_history` 최신가는 `222,750`(toss)인데 포트폴리오에는 `219,500`이 표시되었다. 나머지 5종목은 관심목록 밖이라 시세 이력이 없었다.

### 원인 분석 / 설계 검토
* `watchlist-prices`는 `stock_watchlist WHERE is_active = TRUE`만 수집하고, 포지션 평가가격은 갱신하지 않았다.
* `paper_positions.last_price`는 체결 시점에만 기록되었다. 그래서 Grafana `swallow-paper-portfolio`(패널 203 `현재가`·`평가손익`)와 MCP `swallow_get_portfolio`가 매수가 기준으로 평가했다.

## 2. 해결 방안 및 설계

* **수집 대상**: 활성 관심종목 `UNION ALL` 관심목록 밖 보유 종목(`quantity > 0`). 같은 티커는 `관심종목 정규화`에서 한 번만 조회한다. 회사명은 `paper_positions` → `companies` 순으로, 시장은 `companies`에서 채운다. **관심목록은 읽기만 하며 변경하지 않는다.**
* **원자적 갱신**: `stock_price_history` upsert와 같은 CTE 문장에서 `paper_positions.last_price`·`updated_at`을 스냅샷 가격·시각으로 갱신한다.
  * 가격 소스는 naver를 우선하고, 없으면 toss를 쓴다.
  * `quantity > 0 AND updated_at <= snapshotTs`인 행만 갱신하므로 더 새 체결이나 이후 스냅샷을 덮지 않는다.
  * 유효 시세가 없는 종목은 기존 가격·시각을 유지한다.
* **불변 범위**: 예수금, 수량, 평단, 원가, 거래 이력, 주문 키는 바꾸지 않는다. `execute_paper_trade` 등 자동매매 함수도 호출하지 않는다.
* **요약**: `positionsUpdated`를 따로 기록한다. 더 새 시각 보호로 0이 나올 수 있으며 실패로 판정하지 않는다.

### 핵심 코드 / 설정 스니펫
```sql
), priced AS (
  SELECT DISTINCT ON (ticker) ticker, ts, close_price
  FROM input
  WHERE source IN ('naver', 'toss')
  ORDER BY ticker, CASE source WHEN 'naver' THEN 0 ELSE 1 END
), positions AS (
  UPDATE public.paper_positions p
  SET last_price = priced.close_price,
      updated_at = priced.ts
  FROM priced
  WHERE p.ticker = priced.ticker
    AND p.quantity > 0
    AND p.updated_at <= priced.ts
  RETURNING p.ticker
)
```

## 4. 검증 및 테스트 결과

### 자동화 테스트 (단위 / 회귀) — root 독립 실행
* 실행 명령어: `SWALLOW_TEST_PG_CONTAINER=swallow-portfolio-review FNG_TEST_PG_CONTAINER=swallow-portfolio-review node --test --test-concurrency=1 n8n/Swallow/tests/*.test.mjs`
* 결과: **총 72건 중 71 pass / 0 fail / 1 skip**. skip 1건은 `CNN_LIVE`를 설정하지 않아 건너뛴 라이브 테스트다.
* 격리 PG에서 실제 SQL로 확인한 시나리오: 수집 중복 제거, 종료 포지션(`quantity = 0`) 제외, 소스 우선순위, 잘못된 가격일 때 기존값 보존, 같은 시각·과거 replay, 동시 체결(row lock 보유 중), 거래 테이블 불변.
* **실패 이력:** 첫 병렬 실행은 실패했다. 두 테스트 파일이 같은 격리 PG의 `public` 스키마를 동시에 초기화해 충돌했기 때문이다. 구현 결함이 아니라 테스트 실행 방식의 문제이며, `--test-concurrency=1`로 순차 재실행해 통과했다.

### 실서비스 / UI 검증 증거
* **격리 n8n 노드 검증 (root, PASS)**
  * 환경: 실제 `n8n-test:2.15.0` 이미지로 만든 별도 일회용 컨테이너다. SQLite, fixture credential(`test`), 일회용 PostgreSQL만 연결했으며 운영 데이터와 운영 자격증명은 쓰지 않았다.
  * 실행: CLI `success`, 2026-10-21T04:56:43.175Z ~ 04:56:43.763Z(13:56:43 KST).
  * 10노드 구성: Manual → 원본 스냅샷 Code → fixture 거래 불변 체크 → 원본 `관심종목 조회`(PG) → 원본 `관심종목 정규화`(Code) → 고정 시세 fixture Code(외부 시세 호출 없음) → 원본 `시세 적재`(PG) → 원본 `수집 요약`(Code) → PG 불변 확인 → assert.
  * 결과 **PASS**: 6종목 수집, 시세 이력 12행(naver/toss), `positionsUpdated = 5`(naver `223,000` 반영), `quantity = 0` 포지션 제외. 수량·평단·원가·뉴스·계좌·거래·주문 키·관심목록은 실행 전후 JSON이 같았다(`true`).
  * 실패 이력: 첫 시도는 실행되지 않았다. CLI `--file` 실행 옵션이 맞지 않았고, `none` 네트워크에서 재연결할 수 없었기 때문이다. fixture 네트워크를 다시 만들고 workflow를 import한 뒤 `--id`로 실행해 통과했다.
  * 범위 구분: 24노드 전체 실행, 외부 실시간 시세 호출, 운영 예약 실행, Grafana 확인은 이 검증에 포함되지 않는다.
  * 테스트 컨테이너와 네트워크는 root가 정리할 예정이다.
* 운영 n8n 배포·운영 DB 변경·운영 예약 실행·Grafana UI 확인: **미실시**.

## 6. 한계 및 후속 과제

* **`updated_at` 의미 변경:** `updated_at`이 체결 시각이 아니라 평가 갱신 시각이 된다. 따라서 MCP `swallow_get_portfolio`(`ORDER BY updated_at DESC`)의 보유 종목 정렬과 Grafana `최근 갱신` 열의 의미가 바뀐다.
* **기존 잔여 문제:** 체결 추격 가드(`CHASE_BUY_GUARDED`)는 `stock_price_history`를 `ORDER BY ts DESC LIMIT 1`로 조회한다. 같은 `ts`의 toss·naver 행 사이에서 어느 소스를 고를지 정해져 있지 않다. 이번 작업 범위 밖이다.
