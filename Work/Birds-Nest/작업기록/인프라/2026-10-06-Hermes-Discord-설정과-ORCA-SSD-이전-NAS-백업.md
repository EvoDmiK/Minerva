# 2026-10-06 Hermes Discord 설정과 ORCA SSD 이전·NAS 백업

## 오늘 완료한 작업

### Hermes 재시작과 Discord 설정

Hermes agent를 재시작하고 Discord의 설정 채널을 허용 목록에 추가했다. 같은 채널을 Home 채널로 지정한 뒤 환경변수가 반영되도록 컨테이너를 재생성했다. Gateway 정상 실행, 컨테이너 건강 상태 및 선언형 설정과 실행 설정의 일치를 확인했다.

### ORCA 데이터의 SSD 이전

ORCA 프로젝트, worktree, 앱 데이터, 세션 기록과 캐시의 저장 위치를 외장 SSD로 전환했다. 앱과 백그라운드 데몬을 종료하고 파일을 복사한 뒤 내용 체크섬과 권한을 검증했다. 기존 경로에는 심볼릭 링크를 남겼다. 재실행 후 런타임과 그래프 준비 상태, 프로젝트 및 사용 중 Git worktree 접근을 확인했다.

현재 대화를 처리하는 Codex가 쓰는 세션 기록 두 개는 계속 갱신 중이므로 원본을 보존했다. 파일이 닫힌 뒤 SSD로 복사·검증하는 마무리 작업을 실행해 두었다. ORCA 앱 실행 프로그램 자체는 데이터 이전에 포함되지 않는다.

### ORCA 원본 백업의 NAS 보관

원본 백업 여섯 개를 압축해 NAS에 업로드했다. 압축 크기는 약 855MB이며, 로컬과 NAS의 SHA-256 일치 및 압축 파일 읽기를 검증했다. 백업 접근 권한을 소유자로 제한했다. 기록 중인 세션 로그는 백업 생성 시점의 스냅샷이다. 내장 디스크의 원본 백업도 보존했다.

## Birds-Nest 프로젝트 전체 NAS 백업 완료

프로젝트 전체를 스냅샷으로 만든 뒤 약 5.01GB의 압축 파일로 NAS에 보관했다. Git 이력, 설정, 인증 관련 파일, 무시된 파일과 런타임 데이터까지 포함한다. 심볼릭 링크는 외부 대상을 따라가지 않고 링크 자체를 보존했으며, 임시 소켓 등 실행 중에만 필요한 파일은 제외했다.

- 파일 약 28만 9천 개를 복사했다.
- SQLite 데이터베이스 54개는 백업 API로 스냅샷을 만든 뒤 무결성 검사를 통과했다.
- 기존 OpenClaw의 Codex 로그 DB와 Hermes 상태 DB 두 개는 원본에서도 무결성 오류가 확인되어 원본 복사본을 보존하고 경고를 백업 기록에 남겼다. 이 작업에서 데이터베이스 복구는 수행하지 않았다.
- 로컬과 NAS의 SHA-256 값이 일치했다.
- NAS에서 압축 파일을 끝까지 읽는 검사를 통과했다. 파일·디렉터리·메타데이터를 합쳐 약 35만 2천 개 항목을 확인했다.
- NAS 백업 디렉터리와 파일 접근을 소유자로 제한했다.
- 압축 파일 안에 백업 범위, SQLite 검사 결과와 제외한 임시 파일을 설명하는 백업 목록을 함께 넣었다.

이 백업은 서비스를 계속 실행한 상태에서 만든 파일 단위 스냅샷이다. 정상 SQLite DB는 각각 일관된 스냅샷이지만, 전체 서비스가 동일한 시점에 멈춘 복구 이미지라는 보장은 없다. 일반 로그 등은 복사하는 동안 서로 다른 시점의 내용을 담을 수 있다. 원본 프로젝트와 원본 ORCA 백업은 변경·삭제하지 않았다.

## 후속 확인
