# 논문 원문·학습노트 템플릿

하나의 논문을 원문 보관본과 한국어 학습노트 **두 파일**로 저장하기 위한 템플릿입니다.
아래 두 Markdown 블록을 각각 사용합니다. 이 가이드 전체를 학습노트에 복사하지 않습니다.
researcher는 저장 전에 이 템플릿을 Obsidian MCP로 읽고 현재 인덱스와 경로를 확인합니다.

2026-10-21 Obsidian MCP로 확인한 `Home.md`, `Learning/index.md`,
`Learning/원문/index.md`, `Learning/학습노트/index.md`, `Templates/note.md`와
기존 FAST 논문 노트의 규칙을 따른다. 이 파일은 현재 규칙의 참고본이다.
실행 때마다 해당 인덱스·템플릿과 대상 폴더를 MCP로 다시 확인한다.
사용자가 지정한 다른 템플릿·경로는 우선한다. 오래된 경로를 재생성하지 않는다.

## 경로와 파일명

- 원문: `Learning/원문/YYYY-MM-DD-<논문-slug>-원문.md`
- 정리본: `Learning/학습노트/YYYY-MM-DD-<논문-slug>-논문-노트.md`
- 새 노트 날짜는 작성일(Asia/Seoul), 출판일은 별도 메타데이터다.
- slug는 실제 제목/식별자를 짧게 반영하고 `/ \ : * ? " < > |`를 제거한다.
- DOI/arXiv ID·원 URL로 중복 검색하고 기존 노트가 있으면 현재 경로와 파일명을
  재사용한다. 같은 논문의 다른 버전은 버전을 구분하며 과거 분석을 보존한다.
- 링크는 MCP에서 확인한 실제 경로를 사용한다. `.md` 확장자는 위키링크에서 생략한다.

## 원문 전문 보관 기준

원문 노트의 기본 저장 범위는 **요약·발췌가 아닌 논문 전문**이다. 지정한 버전의 제목·저자 정보, 초록, 모든 본문 절, 수식·표·캡션, 참고문헌과 같은 원문에 포함된 부록을 확인하고 변환된 텍스트를 빠짐없이 보존한다. 별도 보충자료는 실제 확보 여부와 범위를 구분한다.

- 초록 페이지나 검색 결과를 전문으로 저장하지 않는다. 공개 전문 HTML 또는 원본 PDF 전체를 MarkItDown으로 변환하고, 분할 추출했다면 페이지·절 순서대로 모두 합친다.
- 변환 출력의 전체 본문을 원문 노트에 넣는다. 문맥 한도나 도구 출력 제한 때문에 앞부분·일부 절·요약만 저장하지 않는다. 논문의 반복 설명·실험 설정·참고문헌을 임의로 생략하지 않는다.
- 저장 전 논문의 절/페이지 범위와 변환 결과를 대조하고 누락·빈 페이지·깨진 추출을 확인한다. 저장 후에는 MCP 전체 읽기 또는 모든 페이지·구간 조회로 변환 본문과 저장 본문의 완전한 일치를 확인한다. 가능한 경우 메타데이터를 제외한 본문 문자 수·해시도 비교한다. 시작·중간·끝 몇 군데만 확인한 것으로 전문 보관 완료를 선언하지 않는다.
- 도구 제한 때문에 전체를 한 번에 쓸 수 없다면 지원되는 분할 쓰기로 같은 노트에 순서대로 저장하고 전 구간을 재조회한다. 도구가 지원하지 않거나 검증 범위가 부족하면 그 제한과 미완료 상태를 알린다.
- 초록·일부 본문만 확보했다면 전문 보관 요청은 **미완료**다. 기본 원문 노트를 부분 본문으로 생성하거나 기존 전문을 부분 추출로 덮어쓰지 않는다. 공개 전문 링크나 원본 파일을 요청하고, 부분 보관은 사용자가 허용한 경우에만 범위를 명시해 저장한다.
- 그림·수식·표는 실제 보존 상태를 별도로 기록한다. 전문 텍스트 보관을 원본 PDF·모든 이미지 자산의 완전 보관과 동일하게 취급하지 않는다. 추출하지 못한 수식·표나 내용 누락이 있으면 이를 밝히고 전문 변환 검증 완료라고 하지 않는다.

## 원문 노트

```markdown
---
date: <저장일 YYYY-MM-DD>
created: <저장일 YYYY-MM-DD>
collected: <원문 수집일 YYYY-MM-DD>
document_role: source
tags: [learning, source, paper]
paper_title: "<실제 제목>"
paper_date: <확인된 논문 공개일>
paper_id: "<확인된 DOI/arXiv ID 및 버전>"
source_url: "<정규 원문 URL>"
primary_text: "<실제 변환한 전문 URL>"
source_role: primary
capture_scope: "<지정 버전의 전문 범위와 포함 부록·별도 보충자료 여부>"
converter: "markdown-converter / markitdown 0.1.8"
learning_notes:
  - "[[Learning/학습노트/YYYY-MM-DD-<논문-slug>-논문-노트]]"
---
# <실제 제목>

> [!info] 원문 보관 범위
> <변환한 원문 범위·표·수식·그림·각주 누락·이미지 다운로드 여부>
> 변환 검증은 논문 주장에 대한 사실 검증이나 실험 재현을 뜻하지 않는다.

<MarkItDown 변환 본문. 요약·번역으로 대체하지 않는다.>

## 관련

- [[Learning/학습노트/YYYY-MM-DD-<논문-slug>-논문-노트|한국어 정리]]
- [[Learning/원문/index|원문 인덱스]]
```

미확인 메타데이터는 생략하거나 `null`로 둔다. YAML 문자열을 올바르게 이스케이프한다.
원문의 표·코드·링크와 이미지 URL을 보존하고, 광고·메뉴 제거 등 정리가 필요하면
제거 범위를 명시한다. 실제 내려받지 않은 이미지를 로컬 보관했다고 보고하지 않는다.
이미지 보관을 요청받으면 지원 도구로 저장하고 존재를 검증한다. 별도 OCR/유료 API를
임의로 호출하지 않는다. `verification_note`는 실제 존재하는 별도 변환검증 문서를
확인한 경우에만 연결한다. 사용자의 기본 요청은 원문·학습노트 두 개다.

## 사용자 기준 예시 — Magic123 리뷰

기준 예시: [Magic123 논문 리뷰](https://evodmik.notion.site/Magic123-a1590bc9fa984670b8ac50f613e955fe)

이 링크는 핵심 이해와 접힌 상세 근거의 설명 깊이·구성 예시다. 전체 노트는 아래 3단계 구조를 따른다. 논문별 기술 주장·수식·수치의 사실 근거는 새로 분석하는 원논문에서 확인한다. 예시 문장을 복사하거나 그 논문의 2-stage 구조를 다른 논문에 강제로 적용하지 않는다.

- **원문의 논리 순서**: Abstract → Introduction → Methodology → Experiments처럼 논문의 전개를 따라 읽을 수 있게 구성한다. 필요하면 실제 논문의 절·모듈·단계에 맞춰 하위 제목을 만든다.
- **단계별 동작 해설**: 전처리·표현 방식·핵심 모듈·최적화·출력 등 실제 구성 요소마다 해결할 문제, 필요한 이유, 입력·출력, 동작 순서, 앞뒤 단계와의 연결을 설명한다. 모듈 이름 나열로 끝내지 않는다.
- **수식과 변수 표**: 핵심 목적함수·손실항·업데이트 식은 LaTeX로 제시하고, 바로 아래에 기호·의미·역할 표를 둔다. 각 항이 무엇을 유도하는지와 빠졌을 때의 현상을 근거 범위에서 설명한다. 식 번호·원문 위치를 적고 불분명한 표기는 확인 불가로 표시한다.
- **설계 선택의 이유**: 왜 이 모델·표현·정규화·지표를 사용했는지 원문의 설명과 자신의 해석을 구분한다. 모르는 배경 개념은 해당 방법을 이해할 수 있을 만큼 풀어쓴다.
- **그림과 표 해설**: 파이프라인·정성 결과·비교·절제 실험의 핵심 그림이나 표를 확인 가능한 원문 링크 또는 실제 확보한 이미지로 연결하고, 무엇을 보여주는지·축/행/열·비교 조건·해석을 설명한다. 텍스트나 캡션만 읽었으면 그 범위를 밝힌다. Notion 내부 첨부 URI를 Obsidian의 공개 이미지 주소처럼 재사용하지 않는다.
- **재현 가능한 실험 설명**: 데이터셋·지표·옵티마이저·학습률·반복 수·손실 가중치·해상도 등 실제 공개된 설정은 표로 정리하고, 결과 수치와 가중치/구성 변경에 따른 변화도 설명한다. 예시에 나온 숫자를 다른 논문에 복사하지 않는다.
- **읽기 쉬운 한국어**: 문장형 설명과 불릿·하위 제목을 적절히 섞고, 기술 용어는 원어를 병기한다. 깊이는 고정 글자 수가 아니라 주요 단계·수식·실험의 설명이 빠짐없이 이어지는지로 판단한다.
- **한계의 구분**: 장단점 한 줄 요약은 간결하게 둘 수 있으나, 상세 리뷰 본문에서는 중요한 실패 원인·가정·재현 조건을 추가 질문 없이 설명한다. 논문에 없는 사실이나 근거 없는 인과 해석으로 분량을 늘리지 않는다.

## 상세 작성 기준

논문 정리본은 **빠른 파악 → 핵심 이해 → 접어서 보는 상세 근거**의 3단계 한국어 학습 자료로 작성한다. 빠른 파악만 읽어도 연구 질문·기여·대표 결과와 비교 조건·중요한 한계·확보한 원문 범위를 알 수 있어야 한다. 핵심 이해에서는 방법의 흐름과 설계 이유, 대표 실험과 적용 범위를 연결한다. 수식·변수 정의·세부 실험 설정·전체 결과·절제 실험·관련 부록은 주제별 기본 접힘 callout(`> [!note]- 제목`)에 충분히 설명한다.

결론을 바꾸는 조건·실패 위험·미확인 사항을 접힌 영역에만 숨기지 않는다. 같은 설명을 세 단계에 반복하거나 고정 글자 수에 맞춰 자르지 않는다. 논문마다 중요한 내용에 설명을 집중하고, 각 주장에 원문 절·표·그림 위치를 붙인다. 이 구조는 정리본의 읽기 순서이며, 별도 원문 노트의 전문 보관 기준을 줄이지 않는다.

- 연구 동기·문제 정의·선행연구의 한계·기여를 연결해 설명한다.
- 핵심 용어·기호·가정을 정의하고, 방법의 입력·출력·구성 요소·처리 순서·학습과 추론 과정을 단계별로 풀어쓴다.
- 핵심 수식은 확인한 표기와 함께 변수의 의미, 직관, 성립 조건을 설명한다. 예시나 의사코드를 추가하면 원문에 있는 내용과 설명용 재구성을 구분한다.
- 데이터셋·분할·전처리·비교군·평가 지표·학습/평가 설정·컴퓨팅 조건을 확인한 만큼 기록한다.
- 주요 표·그림·절제 실험·분석 결과를 항목별로 해설하고, 수치·단위·비교 기준·원문 위치를 붙인다. 원문 수치가 없으면 채우지 않는다.
- 저자의 주장, 데이터가 뒷받침하는 범위, 분석자의 해석, 한계·실패 사례·재현 조건·실무 적용과 후속 질문을 구분한다.
- 원문의 방법·실험·논의·관련 부록에서 중요한 내용이 빠졌는지 점검한다. 확보하지 못한 부록이나 이미지·표는 미확인으로 표시한다.
- Obsidian 정리본에는 자세한 내용을 유지한다. Discord에는 핵심과 노트 링크를 안내할 수 있으며, 메시지 길이 제한 때문에 저장할 노트를 임의로 축약하지 않는다. 큰 노트는 MCP가 지원하는 방식으로 나눠 저장·재조회하고 잘림 여부를 확인한다.
- 초록/부분 본문만 확보했다면 그 안에서 자세히 설명하고 부족한 근거를 명시한다. 분량을 늘리려고 원문에 없는 내용을 추측하거나 같은 설명을 반복하지 않는다.

## 정리본 — 학습노트

기존 논문 노트의 `document_role`, `note_kind`, `language`, `source_notes`를 사용한다.
범용 `Templates/note.md`의 요약·내용·관련 구조 안에 논문 분석 항목을 배치한다.

```markdown
---
date: <분석일 YYYY-MM-DD>
created: <작성일 YYYY-MM-DD>
document_role: learning-note
note_kind: summary
language: ko
tags: [learning, paper]
paper_title: "<실제 제목>"
paper_date: <확인된 논문 공개일>
paper_id: "<확인된 DOI/arXiv ID 및 버전>"
source_url: "<정규 원문 URL>"
primary_text: "<실제 읽은 전문 URL>"
source_role: primary
capture_scope: "<실제로 읽고 분석한 범위, 전문 복제 아님>"
source_notes:
  - "[[Learning/원문/YYYY-MM-DD-<논문-slug>-원문]]"
---
# <논문 제목> — 한국어 정리

## 요약 — 빠르게 파악하기
- **한 줄 요약·연구 질문**: <무엇을 해결하는 논문인가?>
- **핵심 기여**: <기존 방법과 달라진 핵심.>
- **대표 결과와 조건**: <지표·수치·데이터셋·비교군·중요한 평가 조건과 원문 위치.>
- **중요한 한계와 주의점**: <결론·활용 판단에 영향을 주는 가정·실패 사례·미확인 사항. 저자 명시와 분석자 해석을 구분.>
- **읽은 범위**: <실제 확인한 본문·부록·그림 범위와 근거 공백.>

## 내용 — 핵심 이해하기
### 배경과 핵심 아이디어
<문제·선행연구의 한계·기여를 연결하고 필요한 개념을 설명.>

## 관련

- [[Learning/학습노트/index|학습노트 인덱스]]
```

초록만 읽었다면 해당 범위에 맞게 줄이고 미확인 결과를 채우지 않는다. 두 노트의
논문 ID·버전·URL과 연결 링크를 일치시킨다. 원문 노트의 요약 대체를 금지한다.

## 인덱스 반영과 검증

- 신규 문서를 실제 저장·재조회한 뒤 `Learning/원문/index.md`,
  `Learning/학습노트/index.md`, `Learning/index.md`를 읽고 기존 형식으로 등록한다.
- 같은 문서 링크는 중복 등록하지 않는다. 기존 항목과 사용자 설명을 보존한다.
- 현재 관리 기준이 달라졌으면 현재 인덱스 지침을 우선한다.
- 본문 두 노트와 변경한 인덱스를 각각 재조회한다. 일부 실패는 부분 완료로 보고한다.
- 별도 변환검증 문서를 자동 생성하지 않는다. 변환 한계·읽기 검증 상태는 원문
  범위와 최종 응답에 남기며, 별도 기록 요청이 있으면 `Learning/변환검증/`의
  현재 규칙을 읽고 작성한다. 링크 대상이 없는 `verification_note`를 만들지 않는다.
