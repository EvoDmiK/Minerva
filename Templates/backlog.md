## 카테고리별 분류 및 작업 ID 체계

작업 ID는 접두사 `{{PROJECT_PREFIX}}-`와 3자리 번호(`1xx`~`8xx`)로 부여합니다.  
**첫 자리는 카테고리 도메인, 뒤 두 자리는 순번**입니다.

| 카테고리 | 도메인 범위 | 예시 |
|---|---|---|
| **1xx** | 인프라·저장소·DB | DB 스키마, 저장소 분담, NAS/Docker 환경 설정 |
| **2xx** | 코어 로직·검색·API | 핵심 파이프라인, 비즈니스 로직, 외부 API 연동 |
| **3xx** | AI·모델·프롬프트 | LLM 연동, 에이전트 라우팅, 프롬프트 엔지니어링 |
| **4xx** | UI·프론트엔드·화면 | 컴포넌트, 상호작용, CSS/레이아웃 |
| **5xx** | 데이터·품질·정제 | 데이터 수집, 정규화, 검증 세트 |
| **6xx** | 관측·평가·로깅 | 메트릭, 대시보드, 로깅, 성능 평가 |
| **7xx** | 배포·자동화·CI/CD | 배포 스크립트, n8n 웹훅, 자동 빌드 |
| **8xx** | 문서·개발환경 | 백로그 정비, 가이드 문서, 개발 도구 |

## 작업 관리 및 검증 원칙

1. **상세 원문 1회 기록**: 작업 완료 후 상세한 실행 로그, 변경 diff, 테스트 수치는 반드시 `Work/{{project}}/작업기록/` 하위 마크다운에 남기고 백로그에서는 링크로 참조합니다.
2. **실제 환경 검증**: 코드 작성 후 단위 테스트 패스율 및 실서비스/NAS 배포 결과를 기록하고, 추정이나 가정이 아닌 실제 증거를 문서화합니다.
3. **지식 증류 연계**: 공통 재사용 가치가 높은 기술 패턴은 `scripts/distill_knowledge.py`를 통해 `Dev/` 상록수 지식으로 승격 검토합니다.
