# 반복 오류 검토와 10개 도구 데이터 v2

> 자동 증류 초안 · 원천 [[Work/Jery/작업기록/2026-10-20-Jery-반복오류-검토와-데이터보강]] · 분류 근거 {"인프라":1,"자동화":0,"관측성":0,"데이터":0}

## 1. 개요 및 목적

사용자가 반복 오류와 정답 검토, 헷갈리는 도구 경계 사례 보강을 요청했다. 배치·시드 10회 Parent a29741cab715401ea4ae3fa25cbe3ea4는 완료됐으며 추가 파라미터 탐색 대신 데이터와 입력 명세를 점검했다.

선정 head의 validation 예측만 결합했다. 10개 run에서 20개 source_id가 각각 한 번씩 있어 총 200개 예측이고 그중 오류 80개다. 독립 사례는 200개가 아니라 검증 20개다. 10개 사례에서 한 번 이상 오류가 있었고 4개는 모든 실행에서 틀렸다. Test 예측은 오류 분석에 사용하지 않았다.

## 4. 검증 근거 및 트러블슈팅

사용자가 반복 오류와 정답 검토, 헷갈리는 도구 경계 사례 보강을 요청했다. 배치·시드 10회 Parent a29741cab715401ea4ae3fa25cbe3ea4는 완료됐으며 추가 파라미터 탐색 대신 데이터와 입력 명세를 점검했다.

선정 head의 validation 예측만 결합했다. 10개 run에서 20개 source_id가 각각 한 번씩 있어 총 200개 예측이고 그중 오류 80개다. 독립 사례는 200개가 아니라 검증 20개다. 10개 사례에서 한 번 이상 오류가 있었고 4개는 모든 실행에서 틀렸다. Test 예측은 오류 분석에 사용하지 않았다.

- Bases 뷰 조회: 10/10 실행에서 Dataview로 오선택.
- 과거 일별 종가 조회: 10/10 실행에서 현재가로 오선택.
- 한 종목 보유 여부: 10/10 실행에서 다른 도구로 오선택.
- 계좌 전체 평가손익 사례: 10/10 실행에서 주문/가격 이력으로 오선택.
- Frontmatter 수정 2건: 각각 9/10, 7/10 오류.
- 파일 이름 변경: 4/10 오류.

고정 카탈로그에는 vault.rename, edit.patch(frontmatter), bases.view가 있지만 기존 짧은 선택지 설명은 일부 기능을 생략했다. 이는 확인된 표현 품질 문제다. 실제 오류의 단일 원인이라고 단정하지 않는다. 카탈로그와 직접 충돌하는 기존 라벨은 확인하지 못했으며 label-inspection.json은 AI 대조 결과다. Human review 또는 execution 상태를 승격하지 않았다. 카탈로그가 정답의 유일성이나 실행 성공을 보장하는 것도 아니다.

description_control은 기존 train 60개에 새 설명만 적용하고 augmented는 같은 설명으로 train 240개를 사용한다. 두 profile의 validation/test 각 20개는 바이트 동일하다. 이전 v1의 state·gold·aliases·scenario·순서는 보존하되 설명·catalog provenance는 바뀌므로 이전 입력과 바이트 동일하지 않다. 기존 원본 데이터와 export는 덮어쓰지 않았다.
