## 4. 검증 근거 및 트러블슈팅

사용자는 비교표에서 같은 체중 570g·524g이 두 번 표시되고 각 값마다 출처 토글이 붙은 화면을 제시했다. 같은 표시값은 한 번만 보이고 출처는 한 곳에서 확인하기를 요청했다. 또한 비교 하단의 긴 점수 설명, 추천 순위 문장, 큰 분류 기준 문구를 읽기 좋게 정리해 달라고 했다. 바로 앞 요청의 카드 버튼 가로 배치를 유지하면서 비교값과 요약을 정리했다.

운영 반영은 변경별 명시적 승인이 필요하다는 사용자 지시를 따른다. 이번에는 로컬 검증과 NAS TEST만 반영했다. 운영 배포·DB 변경·운영 재시작·롤백은 하지 않았다.

`src/robingraph/api/static/chat.js`에서 각 비교 셀의 완성된 표시 문자열을 중복 확인한다. 같은 표시값은 한 번만 append하고, 다른 값·단위·추정 표기·표본 평균·문헌 범위 평균은 구별한다. 원자료 자체를 변경하거나 범위가 다른 데이터를 종 전체 평균으로 합치지 않는다. 각 그룹의 출처와 메타데이터, 종명·항목명·표시값 문맥은 기존 통합 답변 출처 패널에 추가한다. 비교표 셀에는 값만 남고 출처 링크와 토글은 없다.

`tests/frontend/chat_ui.test.js`에서는 긴 한 문장 점수 기대를 구조화된 score·basis 검사로 변경했다. 새 회귀는 570 숫자와 "570" 문자열의 동일 표시를 한 번만 출력하고, 571과 표본 평균을 구분하며, 네 원자료 링크가 하단에서 각각 한 번 유지되는지 확인한다. 셀에 출처 details/link가 남지 않는 것도 검사한다.

최종 `node --test tests/frontend/*.test.js`: 302개 통과, 실패·취소·건너뛰기 0. fake DOM 회귀이며 실제 DB 실행으로 세지 않는다. 최초 구조 변경에서는 세 기존 테스트가 이전의 한 문장 점수 문구를 기대해 실패했다. 변경 후 score·basis를 각각 검증하도록 고쳤고, 출처 제목을 통합 패널에 남겨 마지막 기존 기대도 충족했다. 최종 코드에서 전체 회귀를 다시 통과했다.
