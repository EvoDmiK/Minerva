## 4. 검증 근거 및 트러블슈팅

사용자가 RG-406의 남은 작업 중 이미 국외 분포를 검토한 6종의 영어 이름·학명을 검색 자료에 포함하고 오타 후보 검색을 TEST에서 진행하도록 승인했다.

대상은 기존 `species_distribution.json`의 active v2025b/KR outside 6종이다. 영어 이름은 같은 활성 `TaxonConceptSet`·`Taxon`·`VernacularName`의 `policy_status=allowed`, source-preferred 영어 이름·동일 `dataset`/`source_release`를 실제 TEST Neo4j에서 확인했다. 학명은 pinned 종 ID와 완전 일치해야 하며, 새 국명·영문명·옛 학명 alias를 임의 생성하지 않는다.

1. **카탈로그 확장**:
   - 기존: 검토 한국어 이름 850종의 텍스트만 임베딩되어 있어, 국외 종 오타 후보 집합에는 Kea 한 종만 존재했다. 준비된 영어/학명 오타 12건은 모두 후보를 찾지 못했다.
   - 변경: 기존 한국어 이름 집합과 위 6종을 ID 기준으로 병합했다. 신규 5종은 검증 영어 이름+학명, 기존 Kea는 기존 한국어 이름+영어 이름+학명을 텍스트에 보존하여 850 → 855종으로 확장했다 (최대 1,000 상한 유지).
2. **한정 Latin 1-Edit 철자 보완**:
   - 자료 추가만 진행한 1차 검증에서는 오타 12건 중 6건만 통과하고, 나머지는 실제 cosine이 0.25 미만으로 탈락했다.
   - 전역 일반 cosine 하한(0.25)을 낮추지 않고, 위 검토 국외 6종 집합의 영어 원자료 이름/학명과 Latin 입력이 한 글자만 다른 경우를 별도 확인 후보로 보완했다.
   - **적용 조건**: 삽입·삭제·치환·인접 전치(1-edit distance), 입력 최소 4글자 / 원자료 최소 3글자, ASCII Latin 알파벳·공백·하이픈으로 한정.
   - **적용 순서**: 일반 cosine 및 기존 한글 자모 철자 보완 후보가 없을 때만 최종 fallback으로 적용.
   - **점수 및 검증 정책**:
     - 원자료 종을 활성 그래프에서 반드시 재검증해야 하며, 임베딩 서비스나 벡터 저장소가 불능일 때 철자만으로 우회하여 후보를 생성하지 않는다.
     - 실제 cosine 점수는 그대로 유지하여 반환한다 (예: `Keaa` → `Kea`는 약 0.1449). 인위적으로 점수를 올리거나 확률·정답 신뢰도로 왜곡하지 않는다.
     - 후보는 자동 연결(matched)이 아니라 사용자의 선택을 요구하는 확인 후보(candidates)로 제시된다. 질문/alias/조류 노드를 DB에 새로 쓰지 않는다.
3. **범위별 동작**:
   - `scope=outside`: 위 6종 집합 안에서 후보를 확인한다.
   - `scope=all`: 일반 후보가 없을 때 같은 검토 집합을 추가 확인하되, 동일한 query vector를 재사용하여 추가 `embed_query` API 호출을 유발하지 않는다. 전체 범위에서는 기존 검토 한국어 표시를 유지한다 (Kea는 전체에서 높은산앵무, 국외에서 Kea).
   - `scope=korea`, `scope=unknown`: 이 국외 보완 분기를 섞지 않는다.

- **환경 격리 및 백업**:
  - `ROBINGRAPH_DEPLOY_TARGET=test`, Neo4j URI `bolt://192.168.219.98:7687`를 확인한 뒤 수행했다.
  - 갱신 전 현재 이름 벡터 엔트리·catalog·인덱스 정의를 M4 관리 폴더에 private 백업했다 (`/Users/kimdove/robingraph-test/backups/2026-10-19-outside-before.json`, 파일 권한 0600, 부모 디렉토리 0700). 벡터 데이터와 인증정보는 저장소 및 Obsidian 문서에 복사하지 않았다. 새 6개 벡터의 준비 파일도 동일한 private 폴더에 보관했다.
- **Dry-run 및 Apply 단계**:
  - 실제 dry-run: `inventory 855`, `reused 849`, `to_embed 6`, 기존 schema/constraint 호환 확인.
  - 실제 apply: 6개 텍스트를 실제 Jina embedding service로 임베딩한 뒤, 한 트랜잭션에서 855개 catalog metadata를 원자적으로 교체했다 (`inventory 855`, `reused 849`, `embedded 6`, `stale 0`, `catalog_current true`).
  - 후속 dry-run: `reused 855`, `to_embed 0`, `embedded 0`, `catalog_current true` 확인.
  - 이름 벡터 인덱스 정의·차원·제약 조건은 변경되지 않았으며, 삭제 후 재생성하지 않았다 (문헌 청크 인덱스는 무관하며 변경 없음).
- **보존 대조 (Preservation Check)**:
  - 기존 849개 `text_hash`가 온전히 유지되었다.
  - 기존 849개 중 **845개 벡터는 바이트 값까지 동일**하고, 나머지 **4개는 단위 벡터 정규화 경로 재사용에 따른 최대 `2.7755575615628914e-17`의 roundoff 차이**였다. 이를 **"849개 완전 바이트 동일"이라고 표현하지 않는다**.
  - 의미 있는 텍스트 변경은 Kea 1종이며, 새 종 ID는 5개다 (`preservation.json`).
  - **실패 보정 기록**: 첫 보존 검사 스크립트 작성 시 정확한 부동소수점 값 변경이 Kea 1개뿐일 것으로 가정하여 assertion 실패가 발생했다. 이에 실측 부동소수점 roundoff(4개)와 실제 텍스트/의미 변경(1개)을 엄격히 구분하도록 검사와 기록을 정정했다.
