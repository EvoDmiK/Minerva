# [RG-207] 원문 조건 추출·스팬 커버리지·안전 검증 구현 및 검증 — 2026-10-22

## 1. 개요 및 목적

> **문서 상태: 검증 범위 완료 (조건 추출·스팬 커버리지 완료; 런타임 엔드투엔드는 RG-208로 연계, 운영은 향후 별도 승인)**  
> 상위 에픽 **RG-204 (의미 기반 그래프 질의 해석 및 안전한 실행 전환)**의 핵심 3단계 과제인 **RG-207 (원문 조건 추출·스팬 커버리지·안전 검증)**의 구현과 독립 검증을 완료했다. 결정론적 스팬 소비(span-consumption) 규칙을 통해 원문의 모든 문자 스팬이 완전히 소비되거나 잔여(`residual`)로 분류되도록 강제하는 `graph_condition_extractor.py`를 구현하였으며, 단위 테스트 17건 전수 통과 및 40건 고정 홀드아웃 실측에서 **표본 내 오실행 0건, 조건 누락 실행 0건**으로 관측되었다.  
> **검증 범위 및 방법론적 한계 명시**: 실제 TEST 환경의 자체 호스팅 Jina 임베딩 결합 실측에서 답변 커버리지 85%(17/20건), 유형 정확도 96.8%(30/31건), 슬롯 정확도 83.9%(26/31건)로 사전 정의된 게이트(`gates.json` v1: 커버리지 70% 이상, 오실행 0건)를 모두 통과했다. 그러나 **규칙 단독(90%) 대비 임베딩 결합 시 보수적 보류(`kind_tie`)가 1건 추가되어 커버리지가 85%로 5%p 감소**했으며, 기존 정규식(55%) 대비 향상된 성능은 **새로운 단일 의미 구조 및 스팬 커버리지 설계 전반의 효과이지 임베딩 단독의 개선 효과가 아님**을 명확히 기록한다. 또한 40건 표본은 `agent_reviewed` 상태이며 사람 검토(human gold review)는 미수행 상태이다. 현재 신규 배포는 0건이며, 이제 **RG-208 (통합·관측·TEST 비교·단계적 전환)** 착수로 진입한다.

1. **규칙 단독(90%) vs 임베딩 결합(85%) 커버리지 차이**:
   - 추출기 규칙만 단독으로 실행했을 때는 커버리지가 90%(18/20)였으나, Jina 임베딩 라우터 후보와 결합했을 때는 커버리지가 85%(17/20)로 5%p 감소함.
   - 이는 임베딩 라우터가 대조 질의(예: `GGQ-H-045`)에서 상충 후보를 제시하여 안전하게 `kind_tie`(`clarify`)로 보수적 보류 처리되었기 때문임.
2. **성능 개선의 원천에 대한 냉정한 평가**:
   - 기존 정규식 기준선(55%) 대비 달성된 85%의 커버리지는 **"새로운 단일 의미 구조 및 스팬 커버리지 설계 전반의 효과"**이지, 임베딩 모델 단독의 기여가 아님.
   - 임베딩은 유형 후보를 보조적으로 좁혀주는 역할을 할 뿐이며, 안전성과 정확도의 근본은 추출기의 결정론적 스팬 소비 규칙에 기반함.
3. **인간 미검토(No Human Gold Review)**:
   - 40건 홀드아웃셋은 Codex 작성 및 Writer 독립 시맨틱 검토를 거친 `agent_reviewed` 상태이며, 실제 사람/사용자 검토는 향후 과제로 분리 관리됨.
4. **전체 런타임 미완료 및 TEST 서버 상태**:
   - RG-207 조건 추출기 검증은 완료되었으나, 상위 에픽 RG-204 및 런타임 전체 통합은 완료되지 않음.
   - TEST 서버는 RG-207 검증 당시 시점 기준 기존 RG-203 배포본(`robingraph-api:test-question-endings-203d19900989`)을 유지한 상태였으며 (현재는 후속 [[Work/RobinGraph/작업기록/2xx 검색·RAG·그래프 질의/2026-10-22-RG208-통합-관측-TEST-비교-단계적-전환|RG-208]]을 통해 `robingraph-api:test-semantic-graph-b77e26c7e897` 배포로 전환 완료), 새 배포 0건, DB 쓰기 0건, 운영 변경 0건, Git commit/push 0건이었음.
   - 이후 단계인 **RG-208 통합 및 TEST 비교 검증**에서 실제 API 호출 및 브라우저 검증이 완료됨.
