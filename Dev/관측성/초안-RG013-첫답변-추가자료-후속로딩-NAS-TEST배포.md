## 1. 개요 및 목적

사용자가 플로우 지연 점검 결과를 보고 ‘답변·아종 목록을 먼저 표시하고 사진·설명·추천은 뒤이어 불러오는 방식’을 승인했다. 이전 점검에서 아종 질문도 부모 종의 전체 카드 조회를 기다리며, 외부 설명 수집·Gemini 요약이 약 5초인 느린 요청이 있었다. 일반 profile 채팅은 기본 카드 뒤에 비슷한 새 추천을 동기로 계산해 약 2초 이상 추가 지연이 있었다. Jev 의도 분류 약 2초만 줄여서는 부가 자료 대기가 해소되지 않는 구조였다.

목표는 기존 종·활성 개념집합·분류판·출처 검증을 유지하면서 필수 답변과 부가 자료의 표시 시점을 분리하는 것이다. 검색·분류 데이터나 Jev 모델·프롬프트는 바꾸지 않는다.

## 4. 검증 근거 및 트러블슈팅

목표는 기존 종·활성 개념집합·분류판·출처 검증을 유지하면서 필수 답변과 부가 자료의 표시 시점을 분리하는 것이다. 검색·분류 데이터나 Jev 모델·프롬프트는 바꾸지 않는다.

Codex root가 백엔드·실제 DB/API 검증·패키징·배포를 담당했다. `progressive_chat_ui` 협업 에이전트는 채팅 DOM·상태 관리와 프런트엔드 회귀 테스트를 구현했고, `progressive_review` 에이전트는 백엔드·화면 변경을 읽기 전용으로 검토했다. 독립 검토 중 발견한 초기 빈 설명의 부재 문구 잔존, 후속 제공처 경고 누락, 완료 후 빈 결과 안내 누락, 비교 카드가 이전 기본 프로필을 재사용하는 문제를 수정했다. 실제 호출·배포 검증은 root가 별도로 실행했다.

변경 전에는 채팅이 전체 종 카드의 사진·설명을 기다리고, 일반 소개는 추천까지 완성한 뒤 응답했다. 변경 후 채팅 화면은 `defer_enrichment: true`로 요청한다. 첫 응답에는 동일한 검증 경로의 종 식별·특성·보전 상태·요약과 필요한 아종 목록이 포함되고, 사진·설명·선택적 추천은 포함된 `enrichment_pending` 표시를 기준으로 후속 조회한다. 첫 답변이 표시되면 입력 폼을 즉시 다시 사용할 수 있다.

후속 프로필과 추천의 종 ID·개념집합·분류판이 최초 응답과 모두 같을 때만 화면에 반영한다. 카드 DOM 전체를 교체하지 않고 사진 영역을 갱신하여 팝업·뒤집기·아종 탐색 상태를 보존한다. 기존 섹션과 중복되지 않는 추가 설명과 출처, 새 제공처 경고를 안전한 텍스트로 표시한다. 검증된 후속 프로필은 같은 객체 참조에도 반영하여 이후 비교 카드가 완성된 정보를 사용하게 한다. 새 질문·대화 삭제·비교 시작은 이전 후속 응답의 반영을 취소하고, 취소된 카드가 영구 로딩 상태로 남지 않게 한다.
