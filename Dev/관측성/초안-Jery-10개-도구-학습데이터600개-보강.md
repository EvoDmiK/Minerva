## 1. 개요 및 목적

학습 데이터를 기존 240개에서 600개(도구당 60개)로 늘렸다. 검증·평가는 각 20개를 그대로 유지했다. 이번 작업은 학습 데이터 제작이며 새 학습이나 성능 평가는 실행하지 않았다.

Claude·Antigravity가 각각 새 합성 사례 180개씩 작성했다. 신규 360개는 도구당 36개, 시나리오 260개, 문맥 요청 54개다. 최종 학습 600개는 시나리오 355개다. 실제 Hermes 요청 후보는 학습에 넣지 않았다.

## 4. 검증 근거 및 트러블슈팅

학습 데이터를 기존 240개에서 600개(도구당 60개)로 늘렸다. 검증·평가는 각 20개를 그대로 유지했다. 이번 작업은 학습 데이터 제작이며 새 학습이나 성능 평가는 실행하지 않았다.

Claude는 Antigravity 초안의 28개에 대해 이전 편집 버퍼 의존, 답을 반복하는 문맥, 종목·숫자만 바꾼 템플릿, action 표기와 경로 공백 수정을 요청했다. 수정본 180개를 다시 검토해 모두 AI accept로 판정했다. Antigravity는 자기 작성분 수정 후 사용량 한도에 걸려 Claude 작성분 상대 검토와 최종 commit/push를 완료하지 못했다. 실패 상태를 기록하고 미커밋 수정본을 보존했다. Codex가 Claude 작성분 180개를 이어서 검토하고, 호가·장중 고가/저가로 읽힐 수 있는 요청 2개와 속성 키가 모호한 요청 1개를 명확히 했다. 최종 검토자는 Claude·Codex이며 Antigravity가 완료하지 못한 상대 검토를 완료로 기록하지 않았다.

모든 원문은 needs_human_review / execution_verified=false다. AI 검토는 사람 정답이나 실제 실행 검증이 아니다. 고정 10개 후보의 단일 도구 선택용이며 action·no_tool·clarify·unsupported 예측 데이터까지 보강한 것은 아니다.

전체 테스트 169개와 기존 데이터 검증 PASS. 서로 다른 경로에서 두 번 재생성한 최종 export가 같았다. 기존 train240 prefix와 validation/test 파일을 바이트 단위로 보존했다. 새 원문의 정규화 중복·분할 시나리오 겹침이 없고 heldout과 Jaccard0.55 이상 유사 후보도 0개였다.

최종 수정 후 다시 native builder/tokenizer 검사를 수행했다. train600/validation20/test20에서 skipped·truncated·feature mismatch·target mismatch 모두 0개, 최대 sequence는 358/269/272 tokens였다. max_len1024·head_max_len256, Unsloth2026.10.6/Laya0.4.9/Transformers5.17.0 환경이다. 모델 가중치·forward·학습 없이 형식과 정답 매핑만 확인했다. 카탈로그 hermes-ten-tools-2289142ab57a, 표현 v2.1-native-budget, seed3407을 유지했다.
