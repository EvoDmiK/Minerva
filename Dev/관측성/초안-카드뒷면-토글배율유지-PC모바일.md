# 카드 뒷면 상세 토글 확대 방지 — PC·모바일

> 자동 증류 초안 · 원천 [[Work/RobinGraph/작업기록/4xx 채팅 UI·카드/2026-10-10-카드뒷면-토글배율유지-PC모바일]] · 분류 근거 {"인프라":1,"자동화":0,"관측성":4,"데이터":3}

## 1. 개요 및 목적

사용자는 원앙 카드 뒷면에서 `측정값 더 보기`를 열면 카드가 확대되고 위쪽 제목이 화면 밖으로 밀리는 스크린샷을 제시했다. PC와 모바일 모두 토글 전후 카드 크기를 유지하도록 요청했다.

목표는 토글을 열어도 기본 화면에 맞춘 배율·카드 너비·프레임 크기를 유지하고, 추가 내용은 기존 상세 스크롤로 끝까지 읽을 수 있게 하는 것이다. `측정값 더 보기`, `분류 계통 보기`, 두 도넛의 `항목·비율`에 같은 동작을 적용한다. 종별 특례나 데이터 보정으로 해결하지 않는다.

## 4. 검증 근거 및 트러블슈팅

`graphify query`로 `buildSpeciesPopup`·`fitCard`·`scrollToggleOpen`을 찾고 실제 코드와 기존 테스트를 확인했다.

- 기본 상태: `fitCard`는 자연 너비와 자연 높이를 모두 사용해 카드 전체를 화면 안에 맞췄다.
- 상세 토글이 열리면 `scrollToggleOpen()`이 true가 되면서 높이 조건을 제거하고 **너비만 기준으로 배율을 다시 계산**했다.
- 기본 상태에서 높이 때문에 줄어든 카드가 상세를 열자 너비 배율까지 커졌다. 팝업 프레임 너비도 카드 배율을 따라 커졌고, 내용 확장·스크롤 위치까지 겹쳐 제목이 잘려 보일 수 있었다.
- 기존 테스트에도 열린 상세는 너비만 맞추고 배율을 키우는 동작을 명시적으로 기대하고 있었다. CSS만 고쳐서는 이 계산을 해결할 수 없다.

- `src/robingraph/api/static/styles.css`: 상세 상태에서도 화면 맞춤 배율을 유지한다는 주석으로 수정했다. 스크롤·터치·색상 CSS 자체는 바꾸지 않았다.
- `tests/frontend/chat_ui.test.js`: 열린 토글의 너비 기준 확대를 기대하던 단정을 배율 유지 단정으로 수정했다. 모바일 확대된 콘텐츠의 스크롤 범위와 observer·복수 토글·resize 검증을 추가했다.
- `docs/verification/assets/2026-10-10-card-toggle-scale.cjs`: 실제 API 프로필과 실제 Chrome에서 기본/열림/닫힘 배율·팝업 너비·상세 끝까지의 스크롤·복수 토글·resize를 검사하는 도구.

- `node --test tests/frontend/chat_ui.test.js`: **294 통과, 실패 0, 건너뜀 0**.
- `node --test tests/frontend/birds_ui.test.js`: **3 통과, 실패 0, 건너뜀 0**.
- 합계 **297 통과**. 모의 DOM·순수 함수·CSS 단정 검사이며 실제 브라우저 결과와 구분한다.
- 브라우저 도구 `node --check`, `git diff --check` 통과.
- Python 백엔드/DB 테스트는 실행하지 않았다. 백엔드와 DB 데이터 변경이 없는 프런트엔드 배율 수정이다. CI는 조회하지 않았다.

- 원앙 실제 프로필, PC 1280×900·모바일 390×640 두 사례에서 각 4개 토글의 배율 증가를 확인했다. 이는 기대했던 문제 재현 성공이며 수정본의 테스트 실패가 아니다.
- 최초 도구 실행에는 실제 카드 제목이 h2라는 잘못된 검사 선택자로 오류가 발생했다. 실제 `.species-card-heading` 선택자로 고쳐 재실행했다.
- 최초 재현 화면의 모바일 390×844는 확대가 필요 없는 너비 맞춤 상태여서 증가 단정에 맞지 않았다. 390×640으로 바꿔 높이 제한이 있는 경우를 재현했다. 앱 문제를 해결했다고 판단한 근거는 아래 수정본 실측이다.
